## 0. 30초 요약

1인 사업가가 여러 벤처의 콘텐츠를 만들다가, 그 제작 공정 자체를 제품화하기로 했다. openclaw-auto가 이미 발행 플랫폼(v3.0, 채널 30종)이므로 그 위에 **제작 엔진(studio)** 을 모듈로 얹는다. 차별점은 생성이 아니라 **사용자가 A/B/C를 골라 취향을 학습시키는 루프**다.

**지금 막힌 것 하나**: 나레이션 목소리 최종 선택. 회장 청취 대기. 이것만 풀리면 파일럿 1편이 완성되고 그것이 마케팅 증거물이 된다.

## 1. 회장 제품 모델 (채택)

- openclaw 엔진 = SNS 채널 정보를 갖고 **발행과 성과 조회**를 담당. 구글·네이버 트렌드 등 핫 콘텐츠 수집도 담당
- studio 엔진 = 사용자 정보, 마케팅 하네스 정보, 외부 성과와 트렌드를 갖고 **제작**을 담당
- common 모듈에서 정의한 훅·스킬 위에서 고객의 모든 작업이 관리·제한된다
- tenant 모듈에서 유저의 사업 특성·취향·성과·트렌드를 종합해 결정된 프롬프트와 파라미터가 정의된다
- common + tenant가 합쳐져 실행 컨텍스트가 만들어진다
- A/B/C 샷건으로 사용자가 평가(eval)한다
- 초기에는 마케팅 지식 기반 질문 제안으로 방향성이 만들어진다
- 실시간 트렌드와 채널 정보가 방향성에 누적된다
- 성과는 openclaw를 통해 수집되어 방향성에 누적된다

**eval 루프 4대 입력**: A. 기초 마케팅 지식(내장) + B. A/B/C 샷건 사용자 취향 + C. 콘텐츠 성과 + D. 구글 트렌드 등 핫 트렌드

**비유(회장)**: 미소녀 연애 시뮬레이션. 선택이 누적되어 상태가 되고, 그 상태가 다음 출력을 바꾼다. UI 설계에 그대로 쓴다.

## 2. 회장 모델에서 정정된 것 1건 (중요)

### 기각: "실행 컨텍스트를 앤트로픽·딥시크에 이미지·영상과 함께 전달해 편집된 영상이 나온다"

**앤트로픽과 딥시크는 이미지·영상을 편집하지 못한다.** 텍스트 전용 모델이다.

**실제 구조**

```
실행 컨텍스트 → LLM(앤트로픽·딥시크·제미나이 무관) → 편집 지시서(JSON)
                                                        ↓
                              렌더러(ffmpeg + PIL, 결정론적 우리 코드) → 완성 영상
```

LLM은 "컷2는 4.5초부터, 자막은 이 문장, 말풍선은 우측 상단에서 슬라이드 인" 같은 **명세서**를 쓴다. 픽셀은 우리 코드가 그린다.

**이 구분이 중요한 이유 3가지**

| 이유 | 설명 |
|---|---|
| 재현성 | 같은 명세서면 항상 같은 영상. LLM이 직접 그리면 매번 다름 |
| 비용 | 편집이 코드라 재조립이 무료. 실측: v1.1을 v1.2로 고칠 때 소재 재생성 0장 |
| 품질 게이트 | 명세서는 검사 가능. "고지 문구 누락", "자막 안전영역 침범"을 렌더 전에 잡음. 픽셀 검사는 어려움 |

**따라서 제품의 진짜 자산은 "편집 지시서 스키마"다.** 우리가 정의하는 언어이고, 경쟁사가 복제하기 어려운 지점이다. 설계 1순위.

### 3층 API 키 구조

| 층 | 무엇 | 필요한 키 |
|---|---|---|
| 편집층 | 레이아웃, 컷 전환, 자막, 용어칩, 오버레이, 사회적 증거 말풍선, 인코딩 | **없음.** ffmpeg + PIL 로컬 코드. 인터넷도 불필요 |
| 연출층 | 대본 컷 분해, 프롬프트 작성, 자막 타이밍, 반응 배치 | LLM 아무거나(앤트로픽·딥시크·제미나이) |
| 소재층 | 이미지·영상·목소리 원본 | **미디어 생성 모델 필요.** 앤트로픽·딥시크 불가 |

**소재 공급자는 어댑터로 추상화한다.** 2026-08-14 힉스필드가 `free plan, 0 credits`로 중단된 실사례가 있다. 한 공급자에 결합하면 그날 제품이 멈춘다. 힉스필드·제미나이(Imagen·Veo·Nano Banana)·OpenAI를 마이그레이션(migration) 가능해야 한다.

**미검증 항목**: 제미나이 키로 Veo·Nano Banana를 직접 호출하면 힉스필드 경유보다 싼지. 힉스필드가 쓰는 모델이 원래 구글 것이므로 중간 마진이 없을 가능성. 검증 1순위.

## 3. 아키텍처 3층

```
[1층] 스튜디오 공용 하네스     ← 우리 소유, 전 테넌트 공통, 테넌트 수정 불가
      품질헌법(image/video/voice/layout), 파이프라인 코드, 게이트 규칙
                    ↓ 컴파일 입력
[2층] 테넌트 프로파일 (DB)     ← 유저마다 다름
      브랜드킷 · 금지선 · 채널규격 · 취향벡터 · 승인자산(목소리ID·SoulID)
                    ↓ 런타임 조립
[3층] 실행 컨텍스트            ← 매 생성마다 새로 생성
      시스템 프롬프트 + 파이프라인 파라미터 + 활성 스킬 목록
```

### 설계 결정과 기각안

| 항목 | 채택 | 기각 |
|---|---|---|
| 테넌트별 하네스 | 프로파일 DB에서 **런타임 컴파일** | 테넌트마다 CLAUDE.md 파일 생성(관리 불가) |
| 스킬 | 공용 레지스트리 + 테넌트별 on/off | 테넌트별 스킬 작성 |
| 훅(품질 게이트) | 전부 우리 것, 유저가 못 끔 | 유저 설정 가능(끄는 순간 그냥 클릭 툴이 됨) |
| 1층 수정 | 불가. "이미지에 한글 넣지 마라"는 취향이 아니라 물리 법칙 | 유저 커스터마이징 허용 |

### 취향 수집 방식

**강제 A/B 선택이다. 별점이나 좋아요가 아니다.**

| 단계 | 무엇 | 2026-08-14 실사례 |
|---|---|---|
| 후보 생성 | 같은 입력으로 N개 변형 | 음성 6종 생성 |
| **강제 선택** | 유저가 번호로 고름 | 회장 판정 "1=2=5=4 >>> 6,3" |
| 이유 추출 | LLM이 선택 이유를 축으로 환원 | "낭독형 대 생성형", "속도 과함" |
| 프로파일 갱신 | 축별 가중치 저장 | qwen 기각, elevenlabs 채택 |
| 다음 생성 편향 | 파라미터·프롬프트 반영 | 다음 전편은 elevenlabs |

별점은 데이터가 안 된다. 회장도 "좋다"가 아니라 순위를 매겼을 때 정보가 나왔다.

### AI 제안 엔진

```
제안 카드: "이 컷은 오픈루프라 물음표 댓글이 붙으면 이탈이 줄 수 있습니다"
           [넣고 비교해보기] [안 넣기] [항상 넣기]
```

"넣고 비교"를 누르면 두 판을 만들어 나란히 보여주고, 선택이 다시 프로파일에 쌓인다. **제안 → 실험 → 선택 → 학습**이 한 루프.

**주의**: "댓글 반응이 리텐션을 올린다"는 현재 **미검증 가설**이다. 우리 데이터로 확인한 적 없다. 제안 엔진이 신뢰받으려면 제안 근거가 **우리 실험 로그에서 나온 것**이어야 한다. 그게 경쟁사가 못 베끼는 부분이다.

### DB 스키마 초안

| 테이블 | 담는 것 |
|---|---|
| tenant | 계정, 플랜, 키 방식 |
| brand_kit | 팔레트, 폰트, 로고, 톤, 금지선 |
| approved_asset | 승인된 목소리ID, SoulID, 페르소나 |
| preference_event | 후보군, 선택, 이유축, 시각 |
| taste_profile | 축별 가중치(현재 취향 상태) |
| suggestion | AI 제안, 채택 여부, 결과 |
| job / variant | 생성 작업과 변형본 |
| quality_gate_log | 게이트 통과·반려 이력 |

> **주의**: 이 스키마는 초안이다. 하네스 §6.3.5에 따라 API 계약과 DB 스키마는 회장 합의 전 확정하지 않는다. tech-architect 위임 전에 회장과 티키타카를 거칠 것.

## 4. 경계선 (openclaw와 studio)

기준은 **"창작 결정이냐 채널 적응이냐"** 다. 회장의 "발행과 성과만" 방향을 채택하되, 채널 규격 적응은 openclaw에 남긴다. 그건 창작이 아니라 배포 규격이다.

| 작업 | studio | openclaw |
|---|---|---|
| 무엇을 말할까 | O | X |
| 어떤 톤·화풍 | O | X |
| 어느 컷에 무슨 반응을 심을까 | O | X |
| 브랜드 가이드·금지선 | O | X |
| 채널 비율 크롭 | X | O |
| 캡션 길이 자르기, 해시태그 | X | O |
| 언제 올릴까, 어느 계정으로 | X | O |
| 조회·저장·댓글 수집 | X | O |
| 트렌드 수집 | X | O |

**openclaw-auto에서 제거할 것**: 브랜드 가이드라인과 톤 소유권.

**익스텐션 재배치 방향**
- `generate-drafts` → studio 호출로 전환
- `card-generator`, `video-generate` → studio 이관
- `longform-to-shorts` → studio(자르는 기준이 창작 판단)

## 5. UI 통합

유저는 엔진 경계를 알 이유가 없다. 화면은 하나다.

```
[대시보드]  이번 주 성과, 뜨는 주제
[제작]      주제 넣기 → A/B/C 샷건 → 선택 → 완성물        ← studio
[취향]      내 취향 상태, 선택 이력, 제안 카드              ← studio
[발행]      예약, 채널별 미리보기, 계정 관리                ← openclaw
[성과]      채널별 지표, 어떤 선택이 성과로 이어졌나         ← 양쪽 결합
```

**승부처는 성과 탭**이다. "내가 3번을 골랐더니 저장률이 올랐다"를 보여주는 화면. 취향과 성과가 만나는 지점이고, 유저가 이탈하지 못하는 이유가 된다.

### 관리 방식 3선택지 (회장 미결정)

| | A. openclaw-auto 안 모듈 | B. 별도 서비스 2개 + UI는 openclaw | C. 새 모노레포 |
|---|---|---|---|
| 장점 | 가장 빠름. 배포 하나. design 단계 안 깸 | 엔진 독립. 나중에 따로 판매 가능 | 구조가 제일 깨끗 |
| 단점 | 나중에 분리하려면 수술 | 인프라 2벌 운영(1인 부담) | 이사 비용. design 단계 파손 |
| 리스크 | 낮음 | 중간 | 높음 |

**세션 추천 = A.** 근거 3가지.
1. openclaw-auto에 Next.js 껍데기, 익스텐션 30개, R2 스토리지 UI가 이미 있다
2. 스튜디오가 아직 파이썬 스크립트와 문서 뭉치라 서비스로 뗄 만큼 여물지 않았다. 지금 떼면 계약을 추측으로 짠다
3. 1인 사업가가 인프라 2벌을 굴리면 그게 병목이다

**단 A로 가되 의존 방향을 지킬 것.** `studio/`가 채널 코드를 import하지 않고, 발행 쪽이 브랜드킷을 import하지 않으면 나중에 분리가 쉽다. 경계는 폴더가 아니라 의존 방향이 지킨다.

**2026-08-15 이관 실행됨**: A안 전제로 `studio/`(문서·코드, 2.6MB) + `studio-assets/`(미디어 614MB, gitignore) 배치 완료.

## 6. 3덩어리 배치

| 무엇 | 어디 | 이유 |
|---|---|---|
| 제품(UI + 발행엔진 + 스튜디오엔진) | `openclaw-auto` repo | git 추적, 배포 대상 |
| 에셋(영상·이미지·음성뱅크·Soul 레퍼런스) | `openclaw-auto/studio-assets/` (gitignore) → 나중에 R2 | 614MB. repo에 넣으면 파손 |
| 전략 정본 | BRAIN wiki | 사업 판단의 출처 |
| **도메인 지식·대본·용어 정의** | **각 벤처 repo** (haejo-danta, zero-one) | 그 사업이 소유. 콘텐츠 정본이 흩어지면 안 됨 |

### 도메인 지식 원칙

**스튜디오가 벤처 repo를 읽으러 가지 않는다. 벤처가 인테이크로 밀어 넣는다.**

우리 벤처만 특별대우하면 외부 테넌트가 붙을 때 동작이 달라져 외주 제품이 성립하지 않는다. 인테이크 양식(`ventures/_intake-template.md`)이 곧 SaaS의 업로드 화면이 된다.

### 지식 연동 로드맵 (회장 제기)

| 단계 | 스튜디오가 받는 것 | 스튜디오가 만드는 것 |
|---|---|---|
| 지금 | 완성 대본 | 영상·카드뉴스 |
| 다음 | 주제 + 용어 정의 + 금지선 | 대본 + 영상 |
| 그다음 | **지식 저장소 연결**(위키·노션·강의자료·FAQ) | 주제 발굴 + 대본 + 영상 |

**"지식 저장소 연결"이 해자 후보다.** 시그마인이 홈페이지를 크롤링할 때 우리는 고객 내부 지식을 받는다. 고객은 자기 지식이 들어간 만큼 이탈 비용이 생긴다. BRAIN의 `brain-mcp`(읽기 전용 MCP 연결)를 원형으로 쓸 수 있다.

> "현재 우리는 마지막 성과 회수와 범용 자동화가 없으므로 아직 해자가 아니다."

### 국내: 시그마인 (가장 유사, 최우선 대응 대상)

[sigmine.ai](https://sigmine.ai/) · [나무위키](https://namu.wiki/w/시그마인) · 2025년 청년창업사관학교 15기 선정

- **포지셔닝**: "대한민국 1위 AI 마케터". 슬로건 "마케터 채용 대신, 고민하는 시간에 콘텐츠를 만드세요"
- **동작**: 홈페이지 URL로 브랜드 학습 → 블로그 3건/일, 스레드 3건/일, 숏폼 90~100건/월 생성 → 자동 발행 → 성과 추적 후 다음 달 전략에 자동 반영
- **채널**: 인스타그램, 블로그, 스레드, 링크드인, 유튜브, 틱톡
- **가격**: 블로그 15만원/월, 스레드 15만원/월, 숏폼 45만원/월, 번들 75만원/월(약 300건)
- **비교 프레임**: 대행사 월 200~500만원, 직원 연 4000만원 대비 "대행사의 4분의 1"

**우리와 겹치는 것**: 생성 + 발행 + 성과 추적 + 다채널. "할수록 좋아집니다" 문구까지 동일.

**결정적 차이 3가지 (우리 킥)**

| 축 | 시그마인 | 우리 |
|---|---|---|
| 최적화 주체 | AI가 성과 보고 알아서 조정 | **사용자가 A/B/C 골라 취향 축적** |
| 무게중심 | 볼륨(월 300건) | 편당 밀도(컷 분해·용어 하이라이트·리텐션 장치·고지) |
| 브랜드 입력 | 홈페이지 URL 크롤링 | **벤처 내부 지식 인테이크** |

**왜 취향이 성과보다 먼저여야 하나**: 성과 데이터만으로 최적화하면 조회수 잘 나오는 자극적 톤으로 수렴해 브랜드가 망가진다. 회장이 음성 6종에서 "3번은 외국인 같고 쓰레기 수준"이라고 한 판정은 조회수로는 절대 나오지 않는다.

**반론(반드시 기억할 것)**: 시그마인은 이미 매출과 정부 지원이 있고 우리는 영상 1편이다. **속도에서 압도적으로 뒤진다.** 저쪽이 300건 낼 때 우리가 3건 내면 시장은 "느리고 비싼 툴"로 본다. 따라서 **처음부터 좁은 시장**(교육·금융처럼 정확성이 돈이 되는 도메인)으로 가야 한다. 일반 자영업 SNS 시장에서 정면으로 붙으면 진다.

### 벤치마킹 실수 기록

첫 위임에서 국내 서비스를 놓쳤다. 원인은 **위임 프롬프트에 예시 서비스를 영어권 위주로 나열해서** Codex가 그 목록을 범위로 삼은 것이다. 교훈: 벤치마킹 위임에는 **시장 구분(국내/해외)과 언어를 명시**한다.

## 8. 가격 (회장 안 + 세션 수정)

회장 안은 저가(원본만) / 고가(채널 연결 eval) / 초고가(컨설팅) 3단이다. 앵커링 구조는 채택한다.

**세션이 수정 제안한 것: 저가 티어에서 취향 학습을 빼지 말 것.**

| 티어 | 파는 것 | 이유 |
|---|---|---|
| 저가 | **제작 + 취향 학습**(채널 연결 없음) | eval 루프를 저가에서도 맛보게 해야 차별점이 보인다. 취향 데이터가 쌓이면 이탈 비용도 생긴다 |
| 중가(주력) | 저가 + 채널 연결, 성과 회수, 성과 기반 최적화 | 취향만으로는 반쪽. 성과가 붙어야 루프가 닫힌다 |
| 초고가 | 중가 + 전략 컨설팅, 전용 페르소나·목소리 학습, 브랜드 전용 하네스 | 앵커. 몇 개만 팔려도 됨 |

**근거**: 저가에서 취향 학습을 빼면 "싼 생성 툴"이 되고, 그 시장엔 이미 InVideo가 월 17달러에 있다.

### 키 방식 (회장 미결정, 세션 의견)

**우리 키 + 충전식 추천.**
1. 유저 키 등록은 온보딩에서 이탈한다. 힉스필드·제미나이·엘라븐랩스 세 군데를 가입시켜야 한다
2. 우리가 소재 공급자를 마이그레이션(migration)할 수 있어야 한다. 힉스필드 중단 사례가 있다
3. 원가 마진이 우리 손에 있어야 티어 설계가 가능하다

구독만 받으면 헤비 유저가 원가를 넘기므로 **충전식**이 맞다.

### 포지셔닝 (회장 지시로 이관 후 재검토)

- **"원클릭"이라는 말을 쓰지 않는다.** 우리 차별점은 클릭 한 번이 아니라 고르게 해서 취향을 배우는 것이다. 원클릭을 내세우면 이미 잘하는 경쟁사와 같은 링에서 싸운다
- **"ZEROONE-컨텐츠-studio" 명명 재고 요청.** ZERO-ONE은 이미 IT 스터디·교육 벤처로 서 있다(BRAIN `synthesis-ZERO-ONE-IT스터디-운영`). 같은 브랜드를 쓰면 두 사업이 서로를 희석한다. BRAIN에 `decision-조곤-제로원-콘텐츠-경계` 선례가 있다
- **비교 대상 제안**: 시그마인이 "마케터 채용 대신"으로 잡았으므로, 우리는 "대행사 대신"이 아니라 **"내가 직접 만드는 것 대신"** 이 낫다. 같은 링을 피하려면 비교 대상 자체를 달리 잡아야 한다

## 9. 실측으로 확정된 제작 규칙

| 규칙 | 근거 |
|---|---|
| 이미지·영상 프롬프트에 텍스트를 요구하지 않는다 | 힉스필드 전 모델이 한글을 못 쓴다. 요구하지 않아도 배경 소품(간판·메뉴판·TV)에 깨진 글자가 생긴다. 2차 실험 4회 전부 발생 |
| 자막·용어칩·오버레이는 로컬 렌더 후 합성한다 | 크레딧 0, 완전 제어. 이 맥의 ffmpeg는 libass·drawtext가 없어 PIL로 PNG 렌더 후 overlay 필터 사용 |

| 속도는 후처리 배속이 아니라 생성 파라미터로 | 배속은 운율을 뭉갠다. qwen speech_rate 2.0에서 "글자 그대로 읽는 느낌" 실패 |
| 넓은 실내 군중샷은 세로 구도 사고가 잦다 | Kling 3회 중 2회 화면이 90도 누움. Veo는 0회. 프롬프트로 통제 불가(세로 명시한 쪽이 오히려 누움) |
| 화풍은 크레딧에 영향이 없다 | 같은 모델·해상도면 실사든 일러스트든 동일 단가. 돈은 정지 이미지를 영상으로 바꿀 때 든다(컷당 8~12크레딧) |
| 모션은 엔진마다 잘하는 게 다르다 | 달력 되감기·서류 합치기는 Kling 3.0, 버튼 앞 정지는 Wan 2.7. 한 엔진에 몰면 손해 |
| Soul ID는 영구 자산 | 한 번 학습하면 전 편에 같은 얼굴. 크레딧 리셋과 무관 |
| 파일명에 날짜·모델을 박는다 | `<주제>-<용도>-<버전>-<날짜>-<모델·툴>-<규격>.<ext>` |
