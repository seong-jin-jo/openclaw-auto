## 4. 한국어 품질 판정

지원 언어 목록에 한국어가 있다는 것과 한국인처럼 말하고 한국식 자막이 안전하다는 것은 다르다.

### 신뢰 가능한 현재 판정

1. Vrew는 한국어 자막과 텍스트 기반 편집의 직접 적합성이 가장 높다.
2. Higgsfield 안의 ElevenLabs와 MiniMax는 회장 엔진 수준 청취에서 상위였다. 같은 플랫폼의 Qwen과 seed_speech는 기각됐다.
3. Fliki는 한국어 음성 선택 폭과 제어값이 가장 구체적으로 공개돼 있다. 하지만 업체 공개 샘플을 우리가 블라인드 청취한 것은 아니다.
4. HeyGen과 Synthesia는 한국어 지원이 공식 확인된다. 소비자 숏폼에 필요한 구어체, 속도, 감정은 아바타와 voice별로 재시험해야 한다.
5. 나머지 서비스는 다국어 주장을 한국어 품질 승인으로 올리지 않는다.

### 우리에게 필요한 통제 벤치

모든 후보에 같은 세 문장을 넣는다.

- 훅: 숫자와 반전이 있는 3문장.
- 설명: 경제용어와 연결어가 있는 3문장.
- 긴 문장: 쉼과 감정 전환이 있는 1문장.

평가축은 사람다움, 한국어 억양, 용어 발음, 화자 일관성, 속도다. 4점 이상이고 `F`, `P`, `A` 결함이 없을 때만 채택한다.

| 글로벌 현지화 | HeyGen과 Synthesia의 아바타 번역과 립싱크 | 6사업체 한국어 중심, 번역 파이프라인 없음 |
| 신뢰성과 처리량 | 상용 SaaS의 큐, 저장, 팀 요금제, API | 로컬 단일 작업과 수동 실행 중심 |
| 성과 데이터 | 일부 서비스는 광고와 발행까지 연결 | 콘텐츠별 노출, 유지, 저장, 클릭이 제작 변수로 회수되지 않음 |

이 격차를 숨기면 전략이 틀어진다. 우리는 경쟁 서비스보다 더 많은 것을 자동화한 제품이 아니다. 더 엄격하게 통제하는 내부 생산 체계의 초안이다.

## 6. 이들이 못하고 우리가 할 수 있는 것

| OSMU Studio의 잠재 우위 | 내부 증거 | 조건 |
|---|---|---|
| 벤처별 브랜드와 금지선이 제작 전에 들어감 | README의 벤처와 스튜디오 책임 분리, 인테이크 | brand kit와 금지선이 실제 manifest에 연결돼야 함 |
| 컷 유형별 엔진 라우팅 | M1과 M2는 Kling, M3는 Wan이라는 17편 실측 | 더 많은 반복과 장면 유형 데이터 필요 |
| 실패가 다음 생성 규칙으로 남음 | 눕힘, 문자, 화자 드리프트, 속도 회귀 기록 | 검색 가능하고 자동 게이트로 실행돼야 함 |
| 한국어를 생성 모델 밖에서 결정적으로 합성 | PIL 자막과 1080x1920 로컬 overlay 성공 | manifest 기반 범용 렌더러로 바꿔야 함 |
| 법적 고지와 사업 금지선을 픽셀 규격으로 고정 | 조곤경제 고지, 리딩방 문법 금지 | 6사업체별 법적 검토와 버전 관리 필요 |
| 콘텐츠 전략부터 검수까지 연결 | 브랜드, 훅, 시리즈, OpenClaw 가이드, 초안, QA 역할 | 현재 저장소에는 생성 이후 성과 회수 자동화가 없음 |
| 모델 공급사 교체 가능성 | 이미지와 모션을 컷별로 여러 엔진 비교 | 공급사 API 변화에 견디는 어댑터 필요 |

핵심은 특정 모델이 아니다. 같은 장면을 통제해 실패와 비용을 기록하고, 승인된 원재료만 로컬 템플릿에 넣는 절차다.

## 7. 가장 강한 반론: “우리 하네스가 해자다”

### 반론

하네스는 아직 Markdown 문서와 하드코딩된 Python 스크립트다. 경쟁사는 이미 Brand Kit, custom template, avatar, voice clone, agent, API, workspace, 광고 성과 도구를 갖고 있다. 우리 규칙은 읽고 복사할 수 있고, 더 큰 업체가 비슷한 QA 옵션을 제품에 넣으면 차이가 사라진다. 더구나 현재 `build.py`는 입력 manifest도 없고 최종 concat도 수동이다. 이 상태를 해자라고 부르면 내부 문서의 양을 제품 경쟁력으로 착각하는 것이다.

### 답

이 반론이 맞다. 지금 하네스는 해자가 아니라 운영 우위 후보다. 해자가 되려면 다음 네 자산이 쌓여야 한다.

1. 벤처별 승인·기각 원재료와 회장 평가 원문이 구조화된 데이터셋.
2. 컷 유형, 모델, 프롬프트, 비용, 실패, 최종 성과를 잇는 실험 원장.
3. 브랜드와 법적 규칙을 자동 검사하는 manifest 기반 컴파일러.
4. 발행 후 유지율, 저장률, 클릭률을 다음 훅과 컷 선택으로 돌리는 폐쇄루프.

문서는 1번과 2번의 시작점이다. 3번과 4번이 없으면 누구나 흉내 낼 수 있는 제작 매뉴얼에 머문다.

## 8. 차용할 구조와 버릴 구조

| 경쟁 구조 | 왜 강한가 | OSMU식 차용 | 그대로 쓰면 생기는 위험 |
|---|---|---|---|
| Creatify의 URL-to-ad | 입력 마찰이 낮고 변형 속도가 빠름 | 벤처 URL과 brand kit를 인테이크에 자동 첨부 | 사이트 문구가 틀리면 오류도 대량 복제 |
| Arcads Mark의 제품·경쟁·승리소재 입력 | 생성 전에 시장 문맥을 받음 | OpenClaw brief에 승리·기각 사례를 함께 주입 | 경쟁 문구와 배우 스타일 도용 위험 |
| OpusClip의 brand vocabulary | 자막 오탈자와 전문용어를 줄임 | 경제용어, 교육용어, 금지어 사전 구축 | 용어 정확성이 콘텐츠 진실성을 보증하지 않음 |

| Pictory와 Fliki의 Brand Kit | 팔레트와 로고 반복 작업을 줄임 | 로컬 theme.json으로 결정적 렌더 | 팔레트 일치만으로 브랜드 목소리까지 맞았다고 착각 |
| InVideo의 대화형 장면 수정 | 전체 재생성 대신 국소 수정이 쉬움 | 컷 단위 재생성과 승인 상태 도입 | 대화 기록만 남고 실행 manifest가 없으면 재현 불가 |

## 9. 전략 판정

### 하지 말아야 할 것

- 범용 “텍스트 한 줄에서 영상” 서비스를 새로 만드는 것.
- 모델 접근권을 제품 가치로 파는 것.
- 모든 컷을 한 엔진에 몰아주는 것.
- 브랜드 전략과 대본이 비어 있는데 생성부터 시작하는 것.
- 외부 SaaS가 이미 잘하는 아바타 번역과 롱폼 클리핑을 처음부터 다시 만드는 것.

### 추천 포지션

OSMU Studio는 생성기보다 `콘텐츠 컴파일러와 품질 관제층`으로 가야 한다.

```text
벤처 인테이크
  -> 브랜드·법적 규칙
  -> 대본과 컷 manifest
  -> 컷별 최적 외부 모델 라우팅
  -> 한국어 로컬 합성
  -> 증거 기반 QA
  -> 발행
  -> 성과 회수
  -> 다음 생성 규칙
```

### 외부 도구 활용 원칙

- 아바타 설명과 번역: HeyGen과 Synthesia를 파일럿 비교 후 구매.
- UGC 광고 대량 테스트: Arcads와 Creatify를 외부 실험장으로 사용.
- 롱폼 재활용: OpusClip 또는 Vizard를 재구현하지 않고 연결.
- 한국어 자막 수정: Vrew를 편집 보조로 검토.
- 벤처 고유 교육 숏폼과 법적 고지: OSMU 로컬 렌더가 정본.

## 10. 다음 검증 우선순위

1. `_intake-template.md`를 JSON 또는 YAML manifest로 변환한다.
2. `build.py`에서 `CUTS`와 theme을 외부화한다.
3. 같은 30초 한국어 대본으로 HeyGen, Synthesia, Fliki, Vrew를 무크레딧 또는 무료 범위에서 비교한다. 외부 유료 생성은 별도 승인 후 진행한다.
4. 같은 제품 URL로 Arcads와 Creatify의 훅, 증거, 장면 편차를 비교한다.
5. 한 편 발행 후 3초 유지율, 완주율, 저장률, 클릭률을 컷 manifest에 연결한다.
