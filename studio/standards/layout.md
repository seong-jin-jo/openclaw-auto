# 세로 숏폼 레이아웃 품질헌법

## 1. 캔버스와 3영역 규격

기준 캔버스는 1080x1920, 9:16이다.

| 영역 | y 좌표 | 높이 | 비중 | 역할 |
|---|---:|---:|---:|---|
| 상단 띠 | 0부터 287px | 288px | 15% | 브랜드명, 시리즈명, 용어 태그 |
| 중앙 영상 | 288부터 1535px | 1248px | 65% | 이미지, 영상, 개념 오버레이, 댓글과 반응 장치 |
| 하단 띠 | 1536부터 1919px | 384px | 20% | 발화 자막, 구분선, 투자 비추천 고지 |

중앙 원본은 비율을 유지한 채 확대하고 중심 크롭해 1080x1248로 만든다. 가로와 세로를 따로 늘리지 않는다.

## 2. 내부 안전영역

이번 파이프라인에서 실제 사용한 텍스트 안전영역은 다음과 같다.

| 요소 | 안전 좌표 | 근거 |
|---|---|---|
| 상단 태그 | x 52px 이상, y 64px 이상 | 기존 `mk_tag` 시작 좌표 |
| 일반 자막 박스 | x 90부터 990px | PIL 예시의 900px 폭 자막 박스 |
| 중앙 중요 시각물 | y 288부터 1535px | 3영역 시험판 중앙 고정 |
| 하단 고지 중심 | y 1824px | `H-96` 고지 기준선 |

내부 하드 규칙:

- 중요 텍스트는 x 90부터 990px 안에 둔다.
- 하단 고지는 바닥 96px 위에 둔다.
- 중앙 이미지에 생성된 문자를 자막으로 취급하지 않는다.
- 플랫폼 버튼, 계정명, 설명 영역은 앱과 업데이트에 따라 달라진다. 이번 실험은 플랫폼별 업로드 화면을 직접 캡처해 검증하지 않았으므로, 위 수치를 TikTok이나 YouTube의 영구 안전영역이라고 부르지 않는다.
- 실제 발행 전 각 플랫폼 미리보기에서 우측 액션 버튼과 하단 설명 가림을 다시 확인한다.

## 3. 자막 규격

| 항목 | 기본값 | 허용 범위 또는 규칙 |
|---|---|---|
| 글꼴 | Pretendard Bold | 없으면 Apple SD Gothic Neo로 폴백 |
| 기본 자막 크기 | 56px | 1080x1920 기준, 최대 2줄 |
| 기본 자막 색 | 흰색 | RGBA 255,255,255,255 |
| 외곽선 | 7px | 짙은 남색 또는 검정 RGBA 14,16,20,240 |
| 줄 간격 | 80px 기준선 간격 | `build.py` 실측 |
| 정렬 | 가로 중앙 | anchor `mm` |
| 한 줄 분리 | 소스 문자열의 `|` | PIL 렌더 전에 배열로 분리 |
| 하단 배경 | 불투명 띠 | 중앙 이미지와 자막 대비를 분리 |

자막은 현재 발화만 보여준다. 자막 한 덩어리는 최대 2줄이며, 한 줄이 x 90부터 990px을 넘으면 문장을 다시 나눈다. 자동 축소로 40px 이하까지 줄이지 않는다.

## 4. 텍스트 계층

기존 `build.py`에서 검증된 크기다.

| 계층 | 크기 | 용도 |
|---|---:|---|
| 초대형 숫자 | 190px | `32`처럼 첫 훅의 단일 숫자 |
| 중형 강조 | 110px | 경고, 판정, 도장형 한 단어 |
| 용어칩 | 60px | 경기종합지수 같은 핵심 용어 |
| 기본 자막 | 56px | 발화 자막 |
| 미니 설명 | 52px | 방향과 힘처럼 보조 설명 |
| 상단 시리즈 태그 | 38px | 오늘의 800선 용어 |
| 법적 고지 | 32px | 투자 추천 아님, 용어와 구조 해설 |

숫자와 핵심 용어는 자막보다 크게 쓸 수 있지만 같은 프레임에 초대형 강조를 두 개 이상 놓지 않는다.

- 글자: 짙은 남색 RGBA 20,22,28,255.

- 용어 전체가 한 줄에 안 들어오면 폰트를 억지로 줄이지 않고 칩 폭, 위치, 문구 축약 순으로 조정한다.

## 7. 댓글과 반응 장치

실사 시험판에서 사용한 장치:

- 댓글은 컷마다 최대 1개.
- 화면 밖에서 0.38초 동안 슬라이드 인.
- 하트는 댓글 진입 0.45초 뒤부터 56px, 92px, 72px 순서로 팝업.

이 장치는 시험판에서 존재와 가독성만 확인됐다. 완주율과 저장률 개선은 미검증이다. 교육 콘텐츠의 신뢰를 깎을 수 있으므로 기본 템플릿으로 확정하지 않고, 동일 소재의 무장치 버전과 발행 A/B 후 채택한다.

## 8. 한글 렌더 방식

한글은 생성 이미지나 영상 모델에 맡기지 않는다. 로컬 PIL에서 투명 PNG를 만든 뒤 FFmpeg `overlay`로 합성한다.

```python
from PIL import Image, ImageDraw, ImageFont

canvas = Image.new("RGBA", (1080, 1920), (0, 0, 0, 0))
draw = ImageDraw.Draw(canvas)
font = ImageFont.truetype("/Users/sj/Library/Fonts/Pretendard-Bold.ttf", 56)
draw.multiline_text(
    (540, 1620),
    "토요일 2시, 카페 웨이팅이 32번이었음",
    font=font,
    fill=(255, 255, 255, 255),
    anchor="mm",
    align="center",
    spacing=16,
    stroke_width=7,
    stroke_fill=(14, 16, 20, 240),
)
canvas.save("subtitle-cut01.png")
```

로컬 ffmpeg 8.1.1에 libass와 drawtext가 없었던 환경에서도 PIL PNG overlay는 성공했다. 폰트와 자막 PNG를 먼저 눈으로 확인한 뒤 합성한다.
