# 나레이션 품질헌법

## 1. 합격선

한 편의 고정 화자는 다음 조건을 모두 만족해야 한다.

1. 훅에서 숫자, 반전어, 결론어의 강세가 의미에 따라 달라진다.
2. 설명에서 문장부호만 따라 쉬지 않고 의미 단위로 호흡한다.
3. 한국어 받침, 고유명사, 경제용어 오독이 없다.
4. 같은 voice_id로 세 번 생성했을 때 같은 사람으로 들린다.
5. 한 편 전체에서 voice_id, 엔진 변종, 언어, 속도 설정이 고정된다.
6. 회장 청취 4점 이상이고 `F`, `P`, `A` 결함이 없다.

파일 생성과 디코딩 성공은 기술 검증이다. 사람다움 승인은 청취 판정 후에만 부여한다.

## 2. 낭독형 TTS와 생성형 음성

이 구분은 청각 결과를 설명하는 운영 분류다. 상용 엔진의 내부 구조를 역설계해 단정하는 말이 아니다.

| 구분 | 낭독형 결과 | 생성형 결과 |
|---|---|---|
| 최적화 중심 | 글자와 발음의 안정적 재현 | 문맥, 화자, 감정, 다음 말까지 포함한 전달 |
| 쉼 | 쉼표와 마침표 위치에 기계적으로 붙음 | 의미 전환과 긴장에 따라 움직임 |
| 강세 | 절마다 비슷한 높낮이와 종결 | 숫자, 반전어, 결론어에 다른 무게 |
| 장점 | 정확하고 일관됨 | 실제 말하는 느낌과 감정 이동 |
| 위험 | 글자를 순서대로 읽는 느낌 | 화자 드리프트, 과장, 생성 간 편차 |

EC0147에서 `seed_audio`는 문장을 연기해 자연스러웠지만 11회 호출마다 화자가 달라졌다. `qwen_audio_tts`는 Arthur를 고정했지만 `speech_rate 2.0`과 결합했을 때 낭독조가 치명적으로 강해졌다. 자연스러움과 일관성 중 하나를 포기하는 것이 아니라, 고정 voice_id가 있는 엔진에서 둘을 함께 통과시켜야 한다.

## 4. 목소리 고정 규칙

1. 전편 제작 전에 훅, 설명, 긴 문장 3종을 같은 voice_id로 생성한다.
2. 각 문장을 같은 설정으로 3회 반복한다.
3. 세 번 모두 같은 사람으로 들리고, 훅과 설명이 모두 4점 이상일 때만 고정 화자 후보가 된다.
4. 한 편 안에서 엔진 변종과 voice_id를 섞지 않는다.
5. 새 후보가 통과하기 전 기준 음원을 삭제하지 않는다.
6. voice_id, 엔진, 언어, 속도, seed, 문장 버전을 manifest에 기록한다.
7. 이름만으로 성별과 한국어 적합성을 추정하지 않는다. Onyx는 이름상 남성 후보였지만 API 메타데이터는 여성이었다.

## 5. 속도 조절 규칙

1. 기본 속도 1.0을 먼저 듣는다.
2. 네이티브 속도 파라미터가 있으면 0.1에서 0.2 단위로만 조정한다.
3. `speech_rate 2.0`은 금지한다. 음절 간 여백, 문장 끝 감속, 강조 직전 쉼을 무너뜨렸다.
4. 로컬 `atempo`는 최종 수단이다. v1.1의 1.40에서 1.48은 자연스러운 음성의 운율을 압축했고 회장에게 “살짝 빠르다”는 판정을 받았다.
5. 전체 길이를 사람다움의 대리 지표로 쓰지 않는다. 120초와 134초 차이는 운율 통과를 증명하지 않는다.
6. 길이 목표를 맞추기 위해 먼저 대본 호흡과 문장 길이를 조정한다. 엔진과 속도를 같은 회차에 동시에 바꾸지 않는다.

## 6. 사람다움 5점 척도

| 점수 | 기준 | 운영 결과 |
|---:|---|---|
| 5 | 실제 사람이 장면을 떠올리며 말한다. 숫자, 반전, 결론의 강세와 쉼이 모두 자연스럽다. | 승인 후보 |

| 3 | 안정적이지만 스탠다드 낭독이다. 종결 리듬이 반복된다. | 보류 |
| 2 | 글자를 순서대로 읽는다. 핵심 단어 강세가 없다. | 탈락 `R` |
| 1 | 외국인 억양, 오독, 금속성, 비정상 속도 중 하나가 두드러진다. | 즉시 탈락 |

결함 라벨:

- `R`: 읽는 느낌.
- `F`: 외국인 억양.
- `P`: 발음 오류.
- `B`: 호흡과 쉼 오류.
- `A`: 합성 아티팩트.
