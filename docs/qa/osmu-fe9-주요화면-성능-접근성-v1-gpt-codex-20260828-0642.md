# 주요 다섯 화면 성능·키보드·대비 검증

## 결론

수정 전 가장 느렸던 편집실 첫 그림은 1,312.2ms에서 653.7ms로 50% 줄었다.
생성실과 편집실의 초기 API 요청은 16건에서 7건으로 줄었다. 수정 후 다섯 화면의 FCP는
468ms부터 784ms였고, 첫 그림은 546.5ms부터 1,293.6ms였다. 키보드 주요 흐름 14단계,
실제 후보 생성 HTTP 201, 실제 초안 저장 HTTP 200, 라이트·다크 텍스트 1,102개 대비 검사는
모두 통과했다.

## 원인과 수정

1. 생성실·편집실 주소로 들어가도 저장소 기본값인 발행실을 먼저 그린 뒤 effect에서 방을
   바꾸고 있었다. 주소 쿼리를 첫 렌더부터 진실원으로 사용하고, 같은 페이지 안 쿼리 이동도
   반응형으로 갱신하도록 고쳤다.
2. 생성실과 편집실에서도 발행용 첫 댓글 기능과 네 플랫폼 계정 요청을 시작했다.
   발행실에서만 요청하도록 제한해 초기 API를 16건에서 7건으로 줄였다.
3. 키보드 검증 중 편집실에서 발행실로 이동한 뒤 화면이 갱신되지 않는 회귀를 실제로 발견했다.
   `useSearchParams` 기반 방 선택으로 고치고 생성부터 성과 확인까지 다시 통과했다.
4. 라이트 보조 글자 토큰은 흰 배경에서 2.56:1, 다크 보조 글자 토큰은 다크 surface에서
   3.74:1이었다. 각각 5.69:1과 7.05:1로 보정하고 공통 3px `focus-visible` 링을 추가했다.
5. 카드뉴스 이전·다음 단추에 한국어 접근성 이름과 44px 조작 영역을 추가하고, 의미 토큰만
   사용하도록 바꿨다.
