# OSMU 인수 기준과 QA 시나리오 v1.0

## 이 문서가 있는 이유

지금까지 인수 기준을 승인된 기획서에서 뽑지 않고 회장이 그 자리에서 지적한 것으로 삼았다.
그래서 카드뉴스·영상·취소·리셋·학습 정보 완료·작업물 목록 축이 통째로 비었고, 회장 스모크
한 번에 일곱 건이 쏟아졌다. 이 문서는 그 재발을 막기 위해 **기획 정본에서 인수 기준을
끌어와** 고정한다. 새 판은 이 표를 통과해야 완료다.

## 근거가 되는 기획 조항

| 조항 | 무엇을 정했나 |
|---|---|
| 사업계획 v0.4 §10 | 첫 매체는 카드뉴스. 만들기 전 비용 승인 관문을 둔다 |
| 사업계획 v0.4 §7 | 원가는 생성 호출에서 난다. 실측 건당 5에서 95 크레딧 |
| PRD v8.2.1 §도입부 | 고객이 저해상도 후보 3개를 받아 1개만 고해상도로 완성한다 |
| studio 계약 v3 | 만들기 전 estimate, 승인 상한과 함께 production 생성 |
| ADR-006 | 심사 전 한시 절차는 화면이 링크까지 준다. 연결 단추를 막지 않는다 |
| ADR-007 | 조용한 실패 금지. 못 하면 이유를 말하고 빠져나갈 길을 준다 |

## 생성기 프로비저닝 상태 (2026-09-06 실측)

카드뉴스 이미지 생성을 고객 계정에서 실제로 눌러 본 결과 `502` 로 끝났다. 원인을 좁히니
**운영 배포 어디에도 이미지·영상 생성기가 프로비저닝돼 있지 않다.** 배포 워크플로의 환경
변수 렌더, 컨테이너 구성, 이미지 빌드 어디에도 해당 설정이 없다. 코드의 실행기 경로
기본값은 `higgsfield` 인데 컨테이너에 그 실행 파일이 없다.

그래서 지금은 비용 승인까지는 정상으로 뜨고 그 다음에 실패한다. 실패가 502 로만 보여
무엇이 문제인지 알 수 없던 것은 고쳤다. 이제 생성기가 없으면 그 사실을 말한다.
**그 뒤 조치.** 이미지에 생성기를 설치하고 자격증명은 기존 claude 방식과 같이 호스트에서
읽기 전용 마운트하도록 배포 구성을 고쳤다. 지금 남은 것은 배포 호스트에서 생성기 로그인을
한 번 하는 것뿐이다. 브라우저 인증이라 회장이 직접 해야 한다.

**토큰만으로 되는 길이 있는지 실제로 확인했다(2026-09-06).** 생성기 실행 파일이 읽는 설정
이름을 전수로 뽑아 보니 로그인 방식은 브라우저 인증 하나뿐이고, 토큰을 설정값으로 받는
길은 없다. 다만 **자격증명 파일의 위치를 설정으로 바꿀 수 있다**(`HIGGSFIELD_CREDENTIALS_PATH`).
그래서 회장이 하실 일은 하나로 줄어든다. 배포 호스트에서 `higgsfield auth login` 을 한 번
돌리는 것이다. 배포 호스트는 이 맥이 아니라 별도 마케팅 서버이고, 그 서버의
`~/.config/higgsfield` 가 지금 비어 있다. 자격증명은 비밀값이라 세션이 옮기지 않는다. 그 전까지 화면은
"생성기에 로그인되어 있지 않습니다"로 정직하게 닫힌다.

## 플랫폼 연결 전수 상태 (2026-09-06 실측)

연결 진입 지점을 고객 토큰으로 전부 호출해 응답 코드를 쟀다.

| 플랫폼 | 응답 | 판정 |
|---|---|---|
| Threads | 200 | 진입 가능 |
| Instagram | 200 | 진입 가능. 회장 보고로는 콜백에서 장기 토큰 오류 |
| Facebook | 200 | 진입 가능 |
| YouTube | 200 | 진입은 되나 구글이 거절. 원인 확정 (아래) |
| X | 503 | 앱 자격증명 미설정 |
| TikTok | 503 | 앱 자격증명 미설정 |
| LinkedIn | 503 | 앱 자격증명 미설정 |

**구현을 안 한 것이 아니다.** 열 개 제공자 설정이 코드에 있고 네 개는 진입까지 열린다.
셋은 외부 앱 자격증명이 등록되지 않아 서버가 스스로 503 으로 막는다. 이것은 회장 콘솔
등록이 있어야 풀린다. ### 유튜브: 원인 확정

`/api/connect/youtube` 가 내주는 실제 authorize 주소를 그대로 호출해 구글 응답의
`authError` 값을 디코드했다. 문구는 **`redirect_uri_mismatch`** 이고, 구글이 거절한
주소는 다음이다.

```
https://openclaw.sj-onpremise-cloudflare-tunnel.cloud/api/connect/youtube/callback
```

우리 서버가 보내는 이 주소가 구글 클라우드 콘솔의 해당 자격증명에 등록돼 있지 않다.
코드 수정으로 풀리는 문제가 아니라 **콘솔에 이 주소 한 줄을 추가**하면 끝난다.

### 인스타그램: 진입은 정상, 콜백 이후가 미확정

인스타그램은 아직 실제 오류 문구를 못 잡았다. 코드는 제공자 응답의
사유를 화면 문구에 실어 보내므로(장기 토큰 교환 실패 시 상태 코드와 사유 포함), 회장이
다시 시도하시면 **화면에 뜨는 그 문구 자체가 원인 단서**다. 그 문구를 주시면 원인을 확정한다.
직전 시도의 컨테이너 로그는 이후 재배포로 사라졌다.
