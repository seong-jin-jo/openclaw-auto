# 회장 요청 원문 (2026-08-17) — 4실 구조와 챗봇 진행 구상

kind: chairman-request
status: 정본. 유저플로우·프로토타입·기술설계는 이 구상을 기반으로 논의·확장한다. 대체하거나 무시하지 않는다.

## 원문

우리가 userflow 와 prototype 에 대해서 좀 더 논의를 거치고 만들어야겠다는 생각을 했다. 너가 바로 프로토타입을 만드려고 하니까 어려워 하는 것 같아. 일단 비회원이 한 번 컨텐츠를 생성하고 편집하는 랜딩페이지와 회원이 작업하는 흐름은 분리되어야할 것 같아. 지금은 유입 전환을 위한 스킬보다는 회원가입했다는 가정하에 편리한 AI SaaS 흐름을 만드는 것에 집중.

첫번째 생각은 사이드바 좌측에서 Studio 생성/Studio 편집/Openclaw 발행/Openclaw 성과관리 로 관심사를 구분해서 논의하면 어떨까 하는 생각이야. studio-service 가 하는 역할은 생성과 편집, openclaw-service 가 하는 역할은 발행과 SNS 관리, 성과수집으로 명확히 나눠 있잖아. 공간을 분리하는거지. 그렇게 하는게 기획 디자인이나 기술설계에서 적합하지 않을까 싶어.

- Studio 생성에서는 추천을 받든 직접 입력하든 일련의 과정을 거쳐서 System Prompt 를 만들고 생성을 진행. 이 때 여러 안을 제안받거나 개선을 요청할 수도 있고 확정이 되면 편집실로 넘어가는거지.

- Studio 편집에서는 새로운 컨텐츠 창조를 하지않고 자막을 수정하거나, 속도를 조절하거나, 이미지나 음성을 교체하거나 순서를 바꾸는 식의 작업을 하는거야. 여기서 확정이 되면 Openclaw 발행으로 넘어가는거지

- Openclaw 발행실에서는 발행하려는 SNS 플랫폼별로 미리보고 캡션을 수정하든 댓글을 수정하든 발행준비를 하는거야. 완료하면 바로 발행을 할 수도 있고 인박스나 캘린더에 올릴 수도 있는거지. 즉, depth가 발행실 아래에 미리보기, 인박스, 캘린더 등이 있는 모양이 자연스럽지않을까 싶어.

- Openclaw 성과실(?)에서는 발행된 컨텐츠에 대한 성과, 종합적인 성과 등을 확인하고 자동 댓글 자동 좋아요 기존 컨텐츠 삭제 등 SNS에 올린 게시물에 대한 상호작용을 담당하는거야.

- Studio 생성 -> Studio  편집 -> SNS 발행 -> SNS 성과 순으로 진행하는데 만약 다시 되돌리고 싶다면 해당 객체를 다시 원하는 지점으로 되돌리는거지. 성과에서는 이미 발행이 되어버렸으니까 되돌아갈 수는 없고 이것과 유사한 컨텐츠를 만들고 싶으면 그 컨텍스트 정보를 가지고 다시 생성으로 돌아가는거지. 성과실에서 인기 키워드나 트렌드 핫한 컨텐츠를 둘러보면서 이것과 유사한 컨텐츠 만들기식으로 하면 어떨까 싶네.

- 그리고 별도로 학습정보를 두는거지. 각 단계에서 선택한 내용을 기반으로 자연스럽게 계속 학습이 되는거지. LLM WIKI처럼. 한편 완전히 새로운 컨텐츠 (타겟을 바꾼다거나, 컨셉을 바꾼다거나)를 하고 싶을 수도 있으니 학습정보도 워크스페이스 분리하듯이 여러가지 분리해서 쓰게끔해야겠지? 생성, 편집 Studio Service에서 쓸 System Prompt가 사용자에 맞게 관리되고, Openclaw Service 에서 발행 운영하는데 사용되는 System Prompt를 별도로 관리하는게 맞겠지?

- 한편 UX 상으로는 화면에서 다음다음 선택하는 것도 좋지만 챗봇을 하나 만들어서 사용자와 대화하면서 클릭 클릭 진행하는게 어떨까 싶어. 칩 선택도 챗봇안에서 하는거고 설명도 거기서 하는거고. 또 직접 프롬프트 입력받으면서 학습정보를 생성 수정할 수도 있으니까 퀄리티도 높아지지 않을까 싶다.

- 기본적으로 OSMU 파이프라인을 이용하여 생성과 편집 발행을 하되 플랫폼별로 별도로 측정관리하고 싶을때도 있잖아. 그럴때는 각 플랫폼 연구실들어가서 확인하는거지. (지금 플랫폼 별로 기능이 제각각 이라는게 고질적인 요청사항이기도 했음. 이부분도 같이 논의해보자)

- 이미 만든 이미지나 영상을 재활용해서 토큰을 아끼고 싶을때도 있으니까 그건 Assets에서 관리하게 되는 개념.

- 유저가 단순히 AI SaaS가 아니라 자기만의 에이전시 하나를 가져서 실제 가상공간에서 직원들과 인터렉션하며 작업한다는 경험을 주고 싶어.

논의하면서 진행하자. 너가 그냥 '만들어' 하니까어려워하는것 같다.

## 이 요청에서 확정되는 것

### 작업 방식
- 프로토타입 즉시 제작 중단. 유저플로우를 논의로 먼저 수렴한 뒤 만든다.
- 이번 집중 범위는 **회원 가입 이후의 편리한 흐름**이다. 비회원 랜딩과 유입 전환은 분리하고 나중에 다룬다.

### 공간 구조 (4실)
서비스 경계를 화면 공간으로 그대로 나눈다.

| 방 | 소유 서비스 | 하는 일 |
|---|---|---|
| Studio 생성 | studio-service | 추천 또는 직접 입력으로 시스템 프롬프트를 만들고 생성. 여러 안 제안, 개선 요청, 확정 |
| Studio 편집 | studio-service | 창작 없음. 자막 수정, 속도 조절, 이미지·음성 교체, 순서 변경 |
| 발행실 | openclaw-service | 플랫폼별 미리보기, 캡션·댓글 수정, 즉시 발행 또는 인박스·캘린더로. 하위 depth = 미리보기·인박스·캘린더 |
| 성과실 | openclaw-service | 개별·종합 성과, 자동 댓글, 자동 좋아요, 기존 콘텐츠 삭제 등 발행물 상호작용 |

### 진행과 되돌리기
- 순서: 생성 → 편집 → 발행 → 성과
- 되돌리기: 해당 객체를 원하는 지점으로 되돌린다
- 성과에서는 이미 발행됐으므로 되돌아갈 수 없다. 대신 그 컨텍스트를 들고 생성으로 새로 간다
- 성과실에서 인기 키워드·트렌드를 둘러보다가 "이것과 유사한 콘텐츠 만들기"로 생성 진입

### 학습 정보
- 각 단계의 선택에서 자연스럽게 계속 학습된다. LLM 위키처럼 쌓인다
- 타깃이나 컨셉이 완전히 다르면 따로 써야 하므로 워크스페이스처럼 여러 벌로 분리한다
- 생성·편집용 시스템 프롬프트와 발행·운영용 시스템 프롬프트를 별도 관리

### 그 밖
- 챗봇으로 대화하며 클릭으로 진행. 칩 선택과 설명도 챗봇 안에서. 직접 프롬프트로 학습 정보 생성·수정 가능
- 기본은 하나로 만들어 여러 곳에 내는 파이프라인. 플랫폼별로 따로 보고 싶을 때는 각 플랫폼 연구실로
- 플랫폼별 기능이 제각각인 문제는 고질적 요청사항. 함께 논의 대상
- 이미 만든 이미지·영상 재활용은 Assets에서 관리
- 경험 목표: 단순한 도구가 아니라 자기만의 에이전시를 갖고 가상 공간에서 직원들과 상호작용하며 일하는 느낌

## 회장 회신 (2026-08-17, 5건 확정)

### 원문
하나. 프로토타입을 봐야 알 것 같아. 왼쪽 사이드에는 방을 두고 작업물 목록은 GNB나 다른 영역으로 넣으며 히스토리 보게끔 하는것을 제안해본다. 방이라고 착각할 수도 있으니까.

둘. 백지공포같은경우에는 챗봇에서 먼저 친절하게 알려주고 안내하면 강력하게 백지공포가 해소되지 않을까?

셋. openclaw 쪽도 시스템프롬프트 있을수있지않아? 가령 사용자 취향에 맞게 이 사람은 반응있는 유저들한테 친절하게 댓글을 달아주는걸 좋아한다 좀 고자세를 취하는걸 좋아한다 뭐 이런 발행 시스템프롬프트도 있지않을까? 아니면 사용자가 스튜디오에서 컨텐츠만 만들어놓고 발행도 '너가 적절한 시간 선택해서 발행해' 라고 했을때 그때 사용자학습정보가 있어야 판단할거야아니야.

넷. 공통정보를 관리하고 그 안에서 워크스페이스를 관리하는것은? 이건 고민된다.

다섯. 덮어쓰면 안되지. 앞의 공간에서 작업할 목록에 추가가 되는거지

### 확정 사항
1. **왼쪽 사이드바에는 방만 둔다.** 작업물 목록은 상단 영역에 두고 히스토리를 본다. 사이드바에 넣으면 방으로 착각한다.
2. **챗봇이 먼저 친절하게 알려주고 안내한다.** 이것으로 백지공포를 해소한다.
3. **발행 쪽에도 학습된 취향이 있다.** 댓글 말투(친절 / 고자세), 발행 시간 위임("네가 적절한 시간 골라서 발행해") 모두 사용자 학습정보가 있어야 판단 가능하다. 세션의 "openclaw는 규칙일 뿐" 구분은 폐기한다.
4. **공통정보가 상위, 워크스페이스가 그 안.** (회장 제안, 고민 표시됨)
5. **되돌리기는 덮어쓰지 않는다.** 되돌리면 앞 방의 작업 목록에 항목이 추가된다.
