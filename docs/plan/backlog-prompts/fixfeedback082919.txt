회장이 배포된 화면을 직접 써 보고 남긴 피드백에서 "고장" 항목만 고친다. 취향이나 구조 재설계는 이 판의 몫이 아니다. 그것은 디자인 단계가 따로 맡는다.

회장 원문(반드시 먼저 Read): docs/requests/2026-08-29-회장-4실-실사용-피드백.md

## 최우선

1. **로그인이 안 된다. 전부 연결 실패로 떨어진다.** 회장 원문 마지막 줄이다. 배포된 환경에서 로그인 경로를 실제로 밟아 어디서 끊기는지 찾아라. 설정 누락인지 코드 결함인지 구분해서 적어라. 설정 누락이면 어느 값이 필요한지 이름만 적어라(값 금지).

2. **편집실 목차가 가려져 읽을 수 없다.** 실제 화면을 열어 재현하고 고쳐라.

3. **발행실 미리보기가 깨졌다.** X 만 본문이 다르고, 닉네임이 화면 밖으로 나간다. 표시이름·캡션·해시태그가 모든 플랫폼 동일하게 하드코딩돼 있다. 플랫폼별 실제 업로드 화면과 같아지게 고쳐라.

4. **성과실 헤더가 사라진다.** 다른 방에는 있는 헤더가 성과실에서만 없다. 되살려라.

5. **성과 제안 단추 정렬이 어긋나 있다.** DESIGN.md 토큰으로 맞춰라. 임의 px 금지.

## 그 다음

6. **한 작업을 끝내고 새로 시작하는 흐름이 없다.** 생성실에서 편집실로 넘긴 뒤 다시 생성실에 가면 이전 것이 남아 있어 새로 만들 방법이 없다. "새로 시작"과 "이어서 하기"를 명시적으로 나눠라.

7. **편집실에 임시저장이 없다.** 하다가 나중에 돌아와 이어 편집할 수 있어야 한다.

8. **문구가 뜻이 안 통한다.** 아래를 회장이 읽어서 뜻이 서는 말로 바꿔라. 기능을 지우지는 마라.
   - "OpenClaw 큐로 넘기기": 무슨 뜻인지 화면에서 알 수 없다.
   - "소재 권리를 확인했습니다": 무엇을 확인했다는 것인지 알 수 없다.
   - "날짜 잡기": 실제 동작이 예약 발행이면 그렇게 써라.
   - "2곳에 올리기": 선택한 수가 아니라 전체를 못 올리는 것처럼 읽힌다.
   - "초안으로 저장", "검토 요청": 각각 무엇이 일어나는지 화면에 드러나야 한다.

9. **예약 발행한 것을 확인할 자리가 없다.** 예약을 건 뒤 어디서 보는지 화면으로 이어져야 한다.

10. **연결 안 된 계정에 연결 경로가 없다.** 발행실에서 미연결 계정을 누르면 연결 화면으로 가야 한다.

## 이 판에서 하지 말 것

아래는 회장이 던진 구조 질문이라 디자인 단계가 답한다. 코드로 먼저 정하지 마라.
- 학습 정보를 언제 어디서 받을지의 위계
- 만들 종류 중복 선택
- 발행실·성과실에 대화창을 둘지
- 성과실과 플랫폼별 분석의 경계
- 영상 모델 고르기를 어떻게 쉽게 할지

## 공통 규율

- 완료 = 증거. 도는 앱에 실제 요청을 보내거나 화면을 열어 관찰하고 붙여라. mock 통과는 증거가 아니다.
- npm run test 와 npx tsc --noEmit 통과 필수.
- 고친 것마다 재현 시나리오를 실제로 돌려 이제 안 깨지는 것을 보여라.
- 다 못 고치면 어디까지 했는지 정확히 적어라. 거짓 완료 금지.
- 작업이 길어지면 중간중간 커밋해라.
- 사족 문구 금지. 긴 대시 금지. 이모지 금지.
- 끝나면 docs/qa/qa-tracker.md 에 증거를 적고 커밋해라.
