최우선. 네 방 기본 흐름이 끝까지 도는 것만 본다. 다른 것은 손대지 마라.

회장 지시(2026-08-28): "일단 기본 flow (생성 편집 발행 성과) 잘 돌아가는 것에 우선순위를 높여서 집중해라."

## 컨트롤러가 직접 관찰한 결함

앱을 실제로 열어 네 방을 순회하며 DOM 을 재서 얻은 것이다. 추측이 아니다.

| 방 | 방이 그려짐 | 목차 항목 | 미리보기 | 화면을 덮은 모달 |
|---|---|---|---|---|
| 생성실 | 예 | 0 | 0 | 0 |
| 편집실 | 예 | 3 | 1 | 0 |
| 발행실 | 예 | 0 | 0 | 0 |
| 성과실 | **아니오** | 0 | 0 | **1** |

### 결함 하나. 성과실에 도달할 수 없다 (최우선)

사이드바의 네 번째 방 성과실은 `/` 로 간다(`Sidebar.tsx` 의 `ROOM_FLOW`). 그런데 `/` 는 채널이 하나도 연결되지 않았으면 온보딩 마법사를 `fixed inset-0 z-50` 전체 화면 모달로 띄운다(`app/page.tsx` 의 `showOnboarding`, `OnboardingWizard.tsx:108`).

첫 사용자는 채널이 0개다. 그러므로 **첫 사용자는 성과실을 볼 수 없다.** 네 방 흐름의 마지막 방에 도달하는 경로가 없다.

고칠 방향을 스스로 정하되 다음을 지켜라.
- 성과실은 네 방 흐름의 한 칸이다. 사이드바에서 눌렀을 때 성과실이 보여야 한다.
- 온보딩은 첫 사용자를 돕는 것이지 막는 것이 아니다. 전체 화면으로 덮어 다른 방을 못 가게 하지 마라.
- 회장 확정: 성과가 0건이어도 방향 제안 3건이 뜬다. 그것이 성과실의 빈 상태다.

### 결함 둘. 후보 없이 발행실에 가면 빈 화면이다

발행실에 미리보기가 0장이고 무엇을 해야 하는지 안내가 없다. 생성실을 거치지 않고 발행실을 누르면 사용자는 빈 화면을 본다.

빈 상태에 "무엇을 하면 되는지" 한 줄과 그리로 가는 단추를 둔다. 사족 설명은 붙이지 마라.

### 결함 셋. 생성실 빈 상태도 같다

후보를 만들기 전 생성실에 단추가 넷뿐이다. 처음 온 사람이 무엇부터 눌러야 하는지 분명해야 한다.

## 반드시 통과시킬 것

`dashboard/scripts/verify-basic-flow-e2e.mjs` 는 이미 11단계 전부 통과한다(백엔드 흐름). 이것을 계속 통과시켜라.

여기에 더해 **화면 쪽 기본 흐름 검증을 새로 만든다.** 네 방을 실제로 순회하며 이것을 재라.
- 네 방이 각각 자기 내용을 그리는가
- 어느 방에서도 전체 화면 모달이 다른 방으로 가는 길을 막지 않는가
- 사이드바의 네 칸이 각각 그 방으로 실제로 데려가는가
- 빈 상태에서 다음에 할 일이 화면에 있는가
- 390, 768, 1024, 1440 네 폭에서 위 전부

`dashboard/scripts/capture-studio-fe3-playwright.mjs` 를 확장하거나 새 스크립트를 만들어라. 캡처는 `docs/prototype/qa-flow/` 에.
