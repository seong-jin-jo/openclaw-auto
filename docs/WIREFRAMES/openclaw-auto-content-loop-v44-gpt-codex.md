# 와이어프레임: 한 편의 콘텐츠가 네 방을 도는 흐름 v44

한 줄 결론: 생성실에서 시작한 한 편이 편집실·발행실·성과실을 지나고, 성과와 제작 정보가 사람의 승낙을 거쳐 다음 생성의 읽는 정보가 되는 고리를 한 디스플레이에 닫는다.

## 1. 기반과 보존 범위

v43 기능 인벤토리는 `docs/prototype/qa-v44/openclaw-auto-v43-function-inventory-v1-gpt-codex.md`가 정본이다. 화면 정의 119개, 공통 셸, 15종 채널, 상태 5종, 라이트·다크, 390·768·1024·1440을 삭제 없이 보존한다.

v44가 새로 정하는 것은 `한 편의 흐름` 장면 12개뿐이다. 기존 방 내부 화면과 조작은 재배선하지 않는다.

## 2. 정보 구조

```text
헤더 한 줄
┌ 작업 공간 ─ 작업물 ─ 학습 정보 ─ 크레딧 ─ 알림 ─ 계정 ┐

디스플레이
┌ 현재 작업물: 산후 회복, 다시 걷는 첫 주 ─ 현재 방 ┐
├ 생성실 ───── 편집실 ───── 발행실 ───── 성과실 ↺ ┤
├ 지금 보는 결과 ┬ 지금 읽음 / 이번에 쌓임 ┬ 다음 인계 ┤
└ 성과와 제작 정보 ─ 규칙 후보 ─ 승낙 뒤 다음 생성 ┘

오른쪽 아래
● 담당 호출
```

주축 방향:

- 셸: `column`, 헤더 → 본문
- 디스플레이: `column`, 현재 작업물 → 흐름 레일 → 현재 방 상세 → 학습 고리
- 네 방 레일: `row`, 4열 고정
- 현재 방 상세 1024·1440: `row`, 결과 1.1fr / 정보 1.35fr / 인계 .9fr
- 현재 방 상세 390: `column` 1열. 결과와 인계 상세은 접고 정보 묶음을 우선
- 정보 묶음: `row`, 지금 읽음 / 이번에 쌓임 2열
- 학습 고리: 1024·1440은 연결선 포함 5열, 390은 뜻말 3열

## 3. 방별 입력·누적·인계

| 현재 방 | 지금 읽음 | 이번에 쌓임 | 다음으로 넘김 |
|---|---|---|---|
| 생성실 | 안전과 권리, 작업 공간 사실, 제작법, 승낙한 규칙, 이번 요청 | 후보 3개, 선택 원본 1개, 선택 관찰, 제작 정보 | 선택 원본 + 제작 정보 |
| 편집실 | 선택 원본, 편집 요청, 글·영상 갈래, 채널별 규격 | 완성 원본, 채널별 문구, 수정 관찰, 편집 기록 | 완성 원본 + 채널별 문구 |
| 발행실 | 완성 원본, 채널별 문구, 발행 취향, 계정 연결 상태 | 발행 시각, 외부 결과 주소, 발행 기록, 실패·재시도 기록 | 외부 결과 + 발행 기록 |
| 성과실 | 외부 결과, 성과 수치, 제작 정보, 선택·수정 관찰, 비슷한 공개 흐름 | 비교 근거, 배운 규칙 후보, 근거 부족 표시 | 규칙 후보 + 근거 |
| 다음 생성 | 승낙한 규칙, 새 요청, 작업 공간 사실, 안전과 권리 | 새 후보와 새 제작 정보 | 다시 네 방 순환 |

층과 네 방의 맞물림은 화면에 층 이름으로 늘어놓지 않는다. 각 방의 `지금 읽음`과 `이번에 쌓임`에 뜻말로만 드러낸다. 스킬은 제작법을 돕는 층이며 별도 화면이나 브랜드 칸이 아니다.

┌──────────────────────────────────────────────────────────────────────────┐

│ 한 편  산후 회복, 다시 걷는 첫 주                         [편집실][원본 보존] │
├──────────────┬──────────────┬──────────────┬──────────────┤
│ 생성실 완료  │ 편집실 현재  │ 발행실       │ 성과실 ↺     │
│ 후보와 원본  │ 채널별 완성  │ 연결과 발행  │ 성과와 학습  │
├────────────────┬─────────────────────────┬────────────────┤

├──────────────────────────────────────────────────────────────────────────┤
│ 성과와 제작 정보 ───────── 규칙 후보 ───────── 승낙 뒤 다음 생성          │

1440에서도 정보량을 늘리지 않는다. 프레임은 최대 폭 안에서 정렬하고 남는 폭은 여백으로 둔다.

## 5. 390 와이어프레임

```text
┌──────────────────────────────┐
│ 모노스튜디오  학습 정보  1,240 │
├──────────────────────────────┤
│ 한 편  산후 회복, 다시 걷는 첫 주 │
├──────┬──────┬──────┬──────┤
│ 생성 │ 편집 │ 발행 │ 성과 │
├──────────────────────────────┤
│ 읽고 쌓는 정보                │
│ ┌ 지금 읽음 ┬ 이번에 쌓임 ┐  │
│ │ 선택 원본  │ 채널별 문구  │  │
│ │ 편집 요청  │ 수정 관찰    │  │
│ │ 글·영상    │ 편집 기록    │  │
│ └───────────┴─────────────┘  │
├─────────┬─────────┬─────────┤
│ 성과와   │ 규칙     │ 승낙 뒤 │
│ 제작 정보│ 후보     │ 다음 생성│
└─────────┴─────────┴─────────┘
                         ● 담당
```

모바일에서 숨기는 것은 큰 결과 그림과 다음 인계 설명이다. 현재 방, 읽는 정보, 쌓이는 정보, 학습 고리의 세 단계는 숨기지 않는다.

## 6. 상태와 인터랙션

| 상태 | 화면에 남는 것 | 닫는 행동 |
|---|---|---|
| 정상 | 현재 방, 결과, 읽음, 쌓임, 다음 인계, 학습 고리 | 네 방 레일 또는 다음 방 이름 클릭 |
| 불러오는 중 | 어떤 작업물의 어느 방인지, 지금 읽는 정보 | 같은 자리에서 결과 도착 대기. 레이아웃 이동 없음 |
| 내용 없음 | 네 방 레일과 첫 갈래 선택 | `글` 또는 `영상` 선택. 채널 연결 요구 없음 |
| 오류 | 원본 보존, 실패한 정보, 재시도 | `다시 불러오기`. 발행 재실행은 하지 않음 |
| 내용 많음 | 상위 기록과 전체 건수 | 나머지 건수 접어 둠. 디스플레이 세로 스크롤 없음 |

상호작용:

1. 네 방 레일의 방을 누르면 현재 방 상세만 교체된다.
2. `다음으로 넘김`의 방 이름을 누르면 다음 방이 활성화된다.
3. 성과실에서 규칙 후보가 생겨도 다음 생성에 자동 적용하지 않는다.
4. 규칙 승낙은 기존 학습 정보의 승낙 화면이 맡는다. 승낙 뒤 `다음 생성` 장면이 열린다.
5. 담당은 기본 접힘이다. 오른쪽 아래 원형 단추로 열고 같은 자리에서 접는다.

## 7. 심리 근거와 Google Stitch 적용

| 근거 | 적용 | 과용 방지 |
|---|---|---|
| Zeigarnik 효과 | 현재 방을 파란 좌측선과 상태 글자로 표시해 끝나지 않은 단계를 기억하게 함 | 진행률 숫자와 게임화는 쓰지 않음 |
| Hick의 법칙 | 현재 방 상세만 열고 다른 세 방은 64px 레일로 축약 | 네 방 자체는 숨기지 않음 |
| Nielsen 상태 가시성 | 읽는 정보와 새로 쌓인 정보를 분리해 변화의 원인을 보임 | 내부 변수와 기술 용어는 숨김 |
| 손실회피 완화 | 모든 인계에 원본 보존을 표시하고 오류에도 보존된 것을 먼저 알림 | 공포 문구와 과장 경고는 쓰지 않음 |
| 점진 노출 | 390에서 결과 그림과 긴 인계만 접음 | 학습 고리의 가운데 `규칙 후보`는 유지 |

Google Stitch 공식 화면에서 확인한 것은 여러 화면을 공간에 연결하고 재생 가능한 프로토타입으로 보며, 에이전트가 프로젝트의 이전 결정을 문맥으로 유지하는 접근이다. v44는 이를 네 방 레일, 클릭 전환, 누적 정보 묶음으로 번역했다. 무한 캔버스는 발표 화면의 한 장 원칙과 충돌하므로 쓰지 않는다.

## 8. 계획 빈틈과 회수

새로운 plan gap은 발견하지 않았다. 사업계획 v1.2 §1.5의 한 편 순환과 §3.4의 층·조립·상호작용이 같은 방향이며, R01~R99의 확정 규칙과 충돌하지 않는다.

기존 문서에 남은 브랜드 층과 과거 채널 선연결 전제는 v43부터 이미 하류 문서 정합화 대상으로 표시돼 있다. v44에서 새로 확정하지 않는다.

## 9. 레드팀과 셀프심문

경쟁자는 네 방과 데이터 묶음을 한 화면에 넣으면 내부 운영 도식처럼 보여 사용자가 콘텐츠보다 시스템을 먼저 배워야 한다고 공격할 수 있다. 그래서 서비스명·층 코드·저장 구조를 제거하고 `지금 읽음 / 이번에 쌓임 / 다음으로 넘김` 세 질문으로만 번역했다.

이 결론이 틀렸다면 가장 그럴듯한 이유는 흐름을 한 장에 담느라 모바일에서 정보가 사라지는 것이다. 390에서는 큰 그림과 긴 인계만 접고 네 방·읽음·쌓임·규칙 후보의 세 고리를 실렌더로 재확인한다.
