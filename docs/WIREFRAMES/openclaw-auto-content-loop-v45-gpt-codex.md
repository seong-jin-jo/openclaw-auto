# 와이어프레임: 한 편의 콘텐츠가 네 방을 도는 흐름 v45

한 줄 결론: v44의 네 방 진행 띠와 디스플레이 구조를 보존하면서, 방 사이마다 실제 전달물을 끼워 넣고 카드 여백 A/B 및 화면 선택·저장·미리보기·복사를 한 프로토타입 안에서 비교한다.

## 1. 기반과 보존 범위

v45는 `docs/prototype/openclaw-auto-4room-v44.html`의 화면 정의 131개, 공통 셸, 네 방 전환, 15종 채널, 상태 5종, 라이트·다크, 390·768·1024·1440을 보존한다. 기존 방 내부 화면과 데이터축은 삭제하거나 재배선하지 않는다.

새로 정하는 범위는 세 가지다.

1. 네 방 사이의 전달물 3개를 진행 띠 안에 상시 표시한다.
2. 카드의 남는 세로 여백을 `높이 맞춤`과 `내용 높이`로 즉시 비교한다.
3. 회장이 현재 화면을 선택하고 저장하면 실제 화면 미리보기와 명령창용 문장을 같은 패널에서 받는다.

## 2. 정보 구조

```text
한 줄 헤더
┌ 작업 공간 ─ 작업물 ─ 학습 정보 ─ 크레딧 ─ 알림 ─ 계정 ┐

디스플레이
┌ 현재 작업물 ─ 현재 방 ─ 카드 여백 A/B ┐
├ 생성실 ─ [선택 원본+제작 정보] ─ 편집실 ─ [완성 원본+채널별 문구] ─ 발행실 ─ [발행 증거+제작 정보] ─ 성과실 ┤
├ 390 현재 전달물: <앞 방에서 지금 방으로 넘어온 묶음> ┤
├ 지금 보는 결과 ┬ 지금 읽음 / 이번에 쌓임 ┬ 다음 인계 ┤
└ 성과와 제작 정보 ─ 규칙 후보 ─ 승낙 뒤 다음 생성 ┘

오른쪽 아래
● 담당 호출

오른쪽 위 고정 도구
[화면 고르기]
  ├ 현재 화면 담기
  ├ 선택 화면 칩 + 자유 메모
  ├ 저장하고 미리보기
  ├ 실제 화면 미리보기
  └ 명령창에 붙일 문장 + 복사
```

주축 방향:

- 셸: `column`, 헤더 다음 디스플레이
- 헤더: `row`, 한 줄. 학습 정보는 크레딧의 바로 왼쪽
- 흐름 띠 1024·1440: `row`, 방 4개와 전달물 3개를 교차 배치
- 흐름 띠 390: `row`, 방 4개만 유지하고 전달물은 현재 방 아래 1행으로 집약
- 현재 방 상세 1024·1440: `row`, 결과 1.1fr / 정보 1.35fr / 인계 .9fr
- 현재 방 상세 390: `column`, 전달물과 읽음·쌓임을 우선하고 긴 결과 설명은 접음
- 화면 선택 패널: `column`, 선택 → 저장 → 미리보기 → 복사 순서
- 저장된 미리보기: 1024·1440은 `row` 2열, 390은 `column` 1열

## 3. 방 사이 전달물

| 출발 방 | 도착 방 | 흐름 띠에 보이는 전달물 | 도착 뒤 쓰이는 자리 |
|---|---|---|---|
| 생성실 | 편집실 | 선택 원본 + 제작 정보 | 편집 기준, 원본 보존, 갈래 판단 |
| 편집실 | 발행실 | 완성 원본 + 채널별 문구 | 채널 미리보기, 발행 시각, 연결 상태 |
| 발행실 | 성과실 | 발행 증거 + 제작 정보 | 결과 주소, 성과 비교, 제작 조건 회고 |

성과실에서 다음 생성으로 돌아가는 것은 진행 띠 끝의 학습 고리에서 `규칙 후보 + 근거`로 보인다. 자동 적용은 하지 않고 승낙 뒤 다음 생성이 읽는다.

390에서는 방 사이 전달물 3개를 레일 사이에 모두 끼우지 않는다. 현재 방으로 들어온 전달물만 한 줄에 보여 가로 넘침을 막고, 네 방의 순서는 유지한다.

## 6. 카드 여백 비교

| 안 | 규칙 | 장점 | 리스크 | 프로토타입 표현 |
|---|---|---|---|---|
| A 높이 맞춤 | 같은 행의 카드 바닥선을 맞춤 | 빠른 비교, 안정된 격자 | 내용이 짧은 카드에 빈 공간 | `align-stretch`, 동일 행 높이 |
| B 내용 높이 | 카드가 내용만큼만 높아짐 | 빈 공간 감소, 정보량을 솔직하게 반영 | 바닥선이 어긋나 스캔 리듬 저하 | `align-start`, 내용 높이 |

두 안은 같은 화면에서 즉시 토글한다. 선택은 브라우저 저장소에 남아 새로고침 뒤에도 유지된다. 이 판에서는 어느 안도 정본으로 확정하지 않는다.

## 7. 화면 선택·저장·미리보기·복사

```text
현재 화면을 보고 있음
  → 화면 고르기
  → 현재 화면 담기
  → 다른 방·상태·뷰포트로 이동
  → 현재 화면 담기
  → 자유 메모 입력
  → 저장하고 미리보기
  → 선택한 실제 화면 iframe 미리보기 생성
  → 명령창용 문장 생성
  → 클립보드 복사
```

저장 데이터:

- 화면 이름
- 방·상태·뷰포트·테마를 포함한 현재 해시
- 자유 메모
- 저장 시각

상태:

| 상태 | 화면 반응 | 빠져나가는 길 |
|---|---|---|
| 선택 0개 | 저장 시 현재 화면을 자동으로 1개 담음 | 저장 계속 |
| 같은 화면 중복 | 기존 선택을 유지하고 중복 추가하지 않음 | 다른 화면 이동 또는 저장 |
| 저장 성공 | 실제 미리보기와 명령 문장을 같은 패널에 표시 | 복사 또는 선택 수정 |
| 클립보드 허용 | 문장을 즉시 복사 | 명령창에 붙여넣기 |
| 클립보드 차단 | 문장 입력칸을 선택하고 수동 복사 상태 표시 | 입력칸에서 복사 |
| 새로고침 | 마지막 선택과 메모 복원 | 수정 또는 초기화 |
| 초기화 | 선택·메모·미리보기·저장값 제거 | 새 선택 시작 |

## 8. 상태·overflow·접근성

| 검사 | 0 | 정상 | 과다 |
|---|---|---|---|
| 흐름 데이터 | 네 방과 첫 행동 유지 | 세 전달물과 현재 상세 | 카드 내부 상위 항목 + 전체 건수, 바깥 스크롤 없음 |
| 화면 선택 | 현재 화면 자동 담기 | 2개 미리보기 | 선택 칩 가로 감김, 미리보기 패널 내부 감김 |
| 긴 화면명 | 해당 없음 | 한 줄 | 칩과 제목에서 말줄임, 원본은 `title`로 보존 |
| 긴 메모 | 빈 입력 | 2~3문장 | 입력칸 내부 스크롤, 패널 폭 고정 |

토글 버튼은 눌림 상태를 `aria-pressed`로 노출하고, 라벨 자체는 바꾸지 않는다. 저장·복사 결과는 같은 패널의 상태 문구로 알린다. 키보드 초점선은 제거하지 않는다.

## 10. 계획 빈틈과 회수

새 plan gap은 발견하지 않았다. 사업계획 내부 v1.3 §1.5의 한 편 순환, §3.4.2의 작업물별 제작 정보, §3.4.3의 층 상호작용은 v45의 전달물과 충돌하지 않는다.

카드 여백의 정본 선택은 회장 미결이므로 프로토타입에 두 안을 병렬 보존했다. 선택 전 DESIGN.md의 기본값은 v44 회귀 방지를 위해 A 높이 맞춤이며, 확정 뒤 한 안을 정본 토큰으로 승격해야 한다.

## 11. 레드팀과 셀프심문

경쟁자는 전달물까지 진행 띠에 넣으면 시스템 도식처럼 보이고 한 화면 한 결정 원칙을 흐린다고 공격할 수 있다. 전달물은 명사 2개만 남기고, 내부 저장 구조와 층 코드는 숨겼다. 390에서는 현재 전달물 하나로 줄였다.

이 판단이 틀렸다면 왜 틀렸나:

1. 전달물 3개가 방보다 강해져 흐름이 아니라 데이터 사전처럼 보일 수 있다. 답: 전달물을 작은 점선 캡슐로 낮추고 방 카드에 상태 강조를 유지했다.
2. 카드 여백 A/B가 제품 기능처럼 오해될 수 있다. 답: 바깥 QA 도구에 두고 디스플레이 안의 사용자 행동과 분리했다.
3. 저장 뒤 정적 썸네일이면 회장이 실제 상태를 검증하지 못할 수 있다. 답: 선택한 해시를 그대로 여는 실제 iframe 미리보기로 수정했다.
