# 와이어프레임: 상시 담당과 접히는 사이드바 v46

한 줄 결론: v45의 화면 131개와 선택·저장·미리보기·복사를 보존하고, 왼쪽은 전체 접기, 오른쪽은 상시 담당, 디스플레이 본문은 단계명 중복 없는 한 장면으로 정리한다.

## 1. 기존 구현 확인과 보존

| 확인 대상 | 실제 상태 | v46 판단 |
|---|---|---|
| `dashboard/src/components/layout/Sidebar.tsx` | 그룹 단위 접기는 있으나 전체 사이드바 접기는 없음 | 기존 항목과 그룹은 그대로 두고 전체 접기 아이콘 하나만 추가 |
| `openclaw-auto-4room-v45.html` | 담당은 원형 단추로 접히며, 디스플레이 본문에 네 단계 이름이 다시 보임 | 원형 단추를 없애고 상시 담당으로 교체. 본문 단계명 제거 |
| `DESIGN.md` v23 | 담당을 기본 접힘 보조층으로 규정 | v24에서 상시 담당과 접히는 사이드바 계약으로 최신화 |
| v45 검수 셸 | 화면 선택, 저장, 실제 미리보기, 복사, 카드 여백 A/B가 있음 | 전부 유지. A/B 라벨에 실물 출처를 붙임 |

유지한 기존 기능: 헤더 한 줄, 학습 정보와 크레딧 순서, 헤더 2층 네 단계 진행 띠, 발표형 디스플레이, 상태 5종, 화면 선택, 자동 저장, 실제 미리보기, 복사, 라이트·다크, 390·768·1024·1440, 카드 전체 선택과 확대.

## 2. 데스크톱 구조 1024·1440

주축은 `row`다. 순서는 사이드바 → 디스플레이 → 상시 담당이다.

```text
┌──────────────────────────── 헤더 한 줄 ────────────────────────────┐
├────────────────────── 헤더 2층 진행 띠 ───────────────────────────┤
├──────────────┬──────────────────────────────────┬──────────────────┤
│ 사이드바     │ 디스플레이                       │ 담당             │
│ 224 또는 56  │ 한 화면, 내부 세로 스크롤 없음   │ 304, 항상 보임   │
│              │                                  │                  │
│ [‹] 전체접기 │ 받아온 묶음  ›  다음 묶음        │ 대화              │
│ 메뉴 전량    │                                  │ 고르는 칩         │
│              │ 결과 / 읽고 쌓는 정보 / 인계     │ 직접 입력·보내기  │
└──────────────┴──────────────────────────────────┴──────────────────┘
```

- 1440: 사이드바 기본 224px, 상시 담당 304px, 열 간격 16px. 디스플레이가 넓은 비교 화면을 가진다.
- 1024: 사용자가 사이드바 접기 아이콘을 누르면 224px이 56px이 되어 디스플레이 폭 168px을 회복한다. 접힌 상태에서도 아이콘, 현재 항목 강조, 툴팁을 보존한다.
- 상시 담당은 닫기와 접기 행동이 없다. 현재 단계가 바뀌면 같은 열에서 담당 이름과 대화 문맥만 바뀐다.
- 화면 선택·저장·미리보기·복사는 기기 프레임 밖 검수 셸에 남아 제품 정보 예산을 쓰지 않는다.

## 3. 모바일 구조 390

주축은 `column`이다. 순서는 헤더 → 디스플레이 → 상시 담당이다.

```text
┌──────────── 헤더 ────────────┐
├──────── 헤더 2층 진행 띠 ────┤
├──────────────────────────────┤
│ 디스플레이 336px             │
│ 받아온 묶음 › 다음 묶음      │
│ 선택한 카드 한 장            │
├──────────────────────────────┤
│ 담당 상시 패널, 최대 216px   │
│ 대화 내용은 내부 스크롤       │
│ 입력과 보내기 44px 이상       │
└──────────────────────────────┘
```

모바일은 기존 햄버거 서랍을 유지한다. 데스크톱용 전체 접기 아이콘은 중복 노출하지 않는다. 담당을 오른쪽 304px로 고정하면 디스플레이와 입력이 각각 44px 행동 폭을 잃으므로, 390에서만 본문 아래에 상시 이어 놓는다.

## 4. 디스플레이 본문

헤더 2층 진행 띠가 현재 단계를 말하므로 본문에서 `생성실`, `편집실`, `발행실`, `성과실`을 다시 쓰지 않는다.

```text
┌ 한 편 · 산후 회복, 다시 걷는 첫 주                 원본 보존 ┐
├ 받아온 묶음: 선택 원본 + 제작 정보
│                                      › 다음 묶음: 완성 원본 + 채널별 문구 ┤
├ 지금 보는 결과 ┬ 읽고 쌓는 정보 ┬ 다음으로 넘김 ┤
│ 선택한 한 편    │ 지금 읽음       │ 한 묶음       │
│ 원본 보존       │ 이번에 쌓임     │ 다음 단계로   │
└ 성과와 제작 정보 → 규칙 후보 → 승낙 뒤 다음 생성 ┘
```

단계 전환 버튼의 이름도 방 이름이 아니라 `다음 단계로`다. 현재 위치는 헤더의 강조 상태가 답한다. 내부 층 코드와 서비스명은 없다.

## 5. 카드 여백 A/B의 실물 근거

| 안 | 실물 출처 | 차용한 것 | 쓰는 조건 | 기각한 것 |
|---|---|---|---|---|
| A · Stitch 높이 맞춤 | Google Stitch 공식 Play 이미지 | 같은 규격 모바일 프레임 6개가 공통 위·아래선과 일정한 간격으로 정렬되어 흐름과 변형을 빠르게 비교 | 카드가 같은 종류이고 차이를 비교하는 장면 | 무한 캔버스와 자유 스크롤. 발표형 디스플레이와 충돌 |
| B · Linear 내용 높이 | Linear Board 공식 문서 | 카드에는 필수 속성만 남기고 설명과 전체 속성은 Space Peek로 열어 열 밀도를 유지 | 카드별 정보량이 다르고 빈 공간이 읽기 순서를 흐리는 장면 | 모든 상세를 카드 안에 상시 노출하는 안 |

Google Stitch 본체 `https://stitch.withgoogle.com/`는 WebFetch에서 본문 0줄의 JavaScript 앱 셸만 반환했다. 로그인 뒤 조작 UI는 조사 불가다. 대신 Google 공식 발표의 1928×1085 AI-native canvas와 1920×1080 Play 이미지를 직접 열어 프레임 배치와 간격을 확인했다.

추가 벤치마크:

- Notion Sidebar: `<<`·`>>` 아이콘 하나와 `Ctrl/Cmd+\`로 전체 사이드바를 여닫는다. v46의 단일 아이콘과 접근 가능한 이름에 차용했다.
- Microsoft 365 Copilot: 작업물 옆 side pane에서 대화를 이어 간다. 담당을 별도 팝업이 아니라 상시 오른쪽 문맥 열로 두는 데 차용했다.
- Figma UI3: 패널을 접고 크기를 바꿔 캔버스 폭을 회복한다. 전체 UI 숨김은 담당 상시 노출 지시와 충돌해 기각했다.

## 6. 상태와 인터랙션

| 상태 | 디스플레이 | 상시 담당 | 막다른 길 방지 |
|---|---|---|---|
| 정상 | 현재 결과, 읽는 정보, 쌓이는 정보, 다음 묶음 | 현재 단계 문맥과 다음 선택 | `다음 단계로` 또는 담당 입력 |
| 내용 없음 | 첫 후보를 만들 갈래 두 개 | 무엇부터 고를지 질문 | 글로 만들기, 영상으로 만들기 |
| 불러오는 중 | 자리를 고정하고 읽는 정보 설명 | 같은 열에서 대기 이유 표시 | 자동 복구 뒤 현재 장면 유지 |
| 오류 | 보존된 원본과 늦은 성과를 구분 | 복구 선택 안내 | 성과 다시 받기, 원본 보기 |
| 내용 많음 | 상위 묶음과 `나머지 12건은 접어 둠` | 추가 정보는 대화 안 내부 스크롤 | 현재 판단을 막지 않음 |

사이드바 접기는 화면·단계·대화 상태를 바꾸지 않는다. 새로고침 뒤에도 마지막 접기 상태가 복원된다. 선택 저장과 복사는 v45의 Clipboard 폴백과 보이는 문장 출력을 그대로 유지한다.

## 7. 레드팀과 셀프심문

레드팀: 까다로운 고객은 오른쪽 담당이 1024에서 디스플레이를 너무 좁혀, 상시 노출 지시를 지키면서도 본 업무를 망친다고 공격한다. 수정: 전체 사이드바 접기로 168px을 즉시 회복하고, 담당 폭은 304px로 고정해 대화 줄길이가 흔들리지 않게 했다. 390에서는 오른쪽 고정을 고집하지 않고 아래에 상시 이어 44px 입력과 카드 폭을 지켰다.

셀프심문: 이 결론이 틀렸다면 가장 그럴듯한 이유는 단계명을 본문에서 모두 빼 사용자가 현재 위치를 잃는 것이다. 답: 헤더 2층 진행 띠가 항상 보이고 현재 단계는 색과 강조선으로 표시된다. 본문에는 단계명 대신 `받아온 묶음 / 다음 묶음`을 남겨 지금 해야 할 판단만 보강했다.

회수 필요: 390에서도 담당을 물리적으로 오른쪽 열에 고정해야 한다는 의미라면 카드와 입력을 읽을 수 있는 최소 폭을 동시에 만족할 수 없다. v46은 `항상 보임`을 보존하고 배치만 아래로 바꾸는 반응형 해석을 택했다.
