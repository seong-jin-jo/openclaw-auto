# 디스플레이 v42 와이어프레임

## 1. 불변 셸

위에서 아래, 왼쪽에서 오른쪽 순서다.

1. GNB `row`: 작업 공간 라벨 + 이름, 작업물 전체, 크레딧, 알림, 계정.
2. 전역 헤더 `row`: 생성, 편집, 발행, 성과, 학습 정보.
3. 본문 `row`: 사이드바 224px, 디스플레이 `minmax(0,1fr)`, 담당 레일 320px 또는 접힌 48px.
4. 390 본문 `column`: 상단 메뉴, 디스플레이, 접힌 담당 대화.

삭제 예외는 두 개뿐이다. 헤더의 `내 에이전시`와 챗봇의 되짚기·가리킴 목록은 확정 지시로 제거한다. 나머지 v41 기능은 기기 밖 대응표에서 1대1로 추적한다.

## 2. 1024·1440 디스플레이

```text
┌ 작업 공간 모노스튜디오        작업물·크레딧·알림·계정 ┐
├ 생성       편집       발행       성과       학습 정보 ┤
├ 디스플레이                         [접힌/펼친 담당] ┤
│ [브랜드 1] [브랜드 2] [브랜드 새로 만들기]          │
│ [추천] [예시] [편집 중] [자세한 설명]               │
│ ┌ 후보 1 ┐ ┌ 후보 2 선택됨 ┐ ┌ 후보 3 ┐             │
│ │실물·제목│ │실물·제목·근거 │ │실물·제목│             │
│ │행동 2개 │ │행동 2개       │ │행동 2개 │             │
│ └────────┘ └───────────────┘ └────────┘             │
└──────────────────────────────────────────────────────┘
```

- 한 화면 결정: 지금 볼 장면 하나와 후보 세 개.
- 디스플레이 내부 세로 스크롤 0.
- 긴 제목 2줄, 근거 3줄. 초과는 의미 단위 줄임표.
- 후보 11개면 상위 3개와 `나머지 8개는 다음 장`만 보인다.

## 3. 390 디스플레이

```text
┌ 작업 공간 모노스튜디오  작업물  알림  계정 ┐
├ 생성     편집     발행     성과     학습 정보 ┤
├ 디스플레이                                   ┤
│ [브랜드 1] [브랜드 2] [새 브랜드]            │
│ [추천] [예시] [편집 중] [자세한 설명]         │
│ [후보 1] [후보 2] [후보 3]                   │
│ ┌ 선택한 후보 한 장                         ┐ │
│ │ 실물                                      │ │
│ │ 형식 · 선택됨                             │ │
│ │ 제목 · 근거                               │ │
│ │ [크게 보기] [담당에게 이걸로 말하기]       │ │
│ └───────────────────────────────────────────┘ │
│ [대화 열기]                                  │
└──────────────────────────────────────────────┘
```

- 세 후보는 탭으로 모두 접근한다. 한 번에는 선택한 한 장만 보여 글자와 행동 크기를 지킨다.
- 탭을 누르면 같은 상태가 디스플레이 카드의 테두리와 `선택됨` 글자에 반영된다.
- 작업 공간은 모든 폭에서 가로 배열한다.
- 학습 정보는 모든 폭의 헤더에 뜻말로 남는다.

## 4. 상태와 상호작용

| 상태 | 요소 | 행동 | 막다른 길 |
|---|---|---|---|
| 정상 | 세 후보 또는 모바일 한 후보 | 후보 탭, 크게 보기, 담당에게 선택 전달 | 없음 |
| 내용 없음 | 사실을 지어내지 않는 빈 장면 | 흐름만으로 만들기, 주제 말하기 | 없음 |
| 불러오는 중 | 세 자리 골격 | 대화는 계속 가능 | 없음 |
| 오류 | 원인, 보존, 다음 행동 | 다시 불러오기, 주제 직접 말하기 | 없음 |
| 내용 많음 | 전체 수, 상위 3개, 나머지 수 | 다음 장 또는 담당 선택 | 없음 |

## 5. 일곱 칸 계약

제품에는 `시스템 고정 · 우리 지식 · 개인 · 브랜드 · 작업 공간 · 배운 규칙 · 이번 요청`만 쓴다. 내부 코드는 기기 밖 검수 패널에서만 쓴다.

제작법은 칸이 아니라 별도 면이다. 구조·장면 순서·길이의 빈 곳만 채우며 사용자가 명시한 값을 덮지 않는다.

## 6. 셀프심문과 레드팀

이 결론이 틀렸다면 가장 그럴듯한 이유는 모바일에서 한 장만 보여 비교성이 약해지는 것이다. 세 후보 탭을 같은 접힘선 안에 두고 선택 상태를 즉시 반영해 비교 경로를 보존했다.

까다로운 고객은 “근거를 왜 숨겼나”라고 공격할 수 있다. 선택한 카드에는 근거 이름과 핵심 수치를 남기고, 전체 문단만 자세한 설명 장면과 담당 대화로 옮겼다.
