## 0. v21 구성 원칙 (v20 원칙 + 3개)

v20의 원칙 4개를 유지한다. 새 primitive를 만들지 않고, 3분류 칩 체계를 유지하고,
44×44 최소 목표와 3px accent 포커스를 유지한다. v21이 더한 원칙:

5. **상태 색은 사유의 주인을 따른다.** 내가 풀 수 있으면 행동색, 우리가 풀 것이면 중립색.
   유저가 할 일이 없는 상태를 경고색으로 칠하면 유저는 자기 탓으로 읽는다.
6. **누를 수 없으면 버튼을 만들지 않는다.** 비활성 버튼은 하고 싶은 일을 이름으로 걸어놓고 막는 것이다.
7. **강조는 목록에서도 하나.** v20 시작 체크리스트의 다음 단계 테두리를 채널 목록에 재사용한다.

## 1. 상태 3분류 (v21 핵심 컴포넌트)

```
StatusThree = [배지] + [사유의 주인 칩]

발행 가능                     (초록 배지, 주인 칩 없음)
미연결      [내가 할 일]      (주황 배지, 회색 주인 칩)
오픈 준비중  [우리가 할 일]    (회색 배지, 파란 주인 칩)
```

| 요소 | 규칙 |
|---|---|
| 배지 | 기존 `StatusBadge` 재사용. 새 모양 만들지 않음 |
| 주인 칩 | 12px, radius 999, `우리가 할 일`만 accent 계열로 물러난 강조 |
| 발행 가능 | 주인 칩 없음. 할 일이 없는데 주인을 적으면 소음 |
| 어휘 고정 | 채널 목록·채널 상세·Settings·시작 체크리스트가 같은 세 단어만 사용 |

### 1.1 사유 블록 (채널 상세)

```
┌ 지금 이 채널 상태  [이번에 더함] ─────────────────────────┐
│ [오픈 준비중] [우리가 할 일]                              │
│ 우리 쪽 준비가 아직입니다. 앱 등록을 안 했거나, 등록했지만 │
│ 플랫폼 심사를 기다리는 중입니다.                          │
│ Google 민감 권한 검증과 YouTube 컴플라이언스 감사를       │
│ 아직 통과하지 못했습니다.                                 │
│ ┌ notice ───────────────────────────────────────────────┐│
│ │ 기다리시면 됩니다. 이 채널은 고객이 할 수 있는 일이    ││
│ │ 없고, 우리가 준비를 끝내면 자동으로 열립니다.          ││
│ └────────────────────────────────────────────────────────┘│
│  보낼 수 있는 양   전 회원 합쳐 하루 100건   [앱 전체 공유]│
│  필요한 계정 종류  일반 채널 가능                          │
│ ┌ warning ──────────────────────────────────────────────┐│
│ │ 이 채널의 한도는 회원마다 따로 있지 않고 우리 서비스   ││
│ │ 전체가 나눠 씁니다. 다른 회원이 많이 쓰면 오늘 내 몫이 ││
│ │ 줄어들 수 있습니다.                                    ││
│ └────────────────────────────────────────────────────────┘│
└────────────────────────────────────────────────────────────┘
```

| 규칙 | 내용 |
|---|---|
| 위치 | **발행 가능이 아닌 채널은 탭 위에.** 어느 탭에 있든 먼저 보인다 |
| 발행 가능인 채널 | Settings 탭 안에만. 잘 되는 것을 매 화면 반복하지 않는다 |
| 미연결 | 사유 아래에 `이렇게 하면 됩니다` 안내 박스 |
| 오픈 준비중 | 사유 아래에 `기다리시면 됩니다` 안내 박스. 행동 버튼 없음 |
| TikTok 추가 | warning으로 `지금 시험 삼아 올리면 비공개로만 게시됩니다` |
| 앱 전체 공유 | quota scope 칩 + warning 문장 |

│  [미연결][내가 할 일] Telegram                     [연결]     │
│  [미연결][내가 할 일] Discord                      [연결]     │
│  [미연결][내가 할 일] Slack                        [연결]     │

│ ┌ surface-2 배경 ──────────────────────────────────────────┐ │

| 규칙 | 내용 |
|---|---|
| 정렬 | 미연결 → 발행 가능 → 오픈 준비중. 풀 수 있는 순서 |
| 강조 | 첫 미연결 하나만. 나머지 미연결은 평범한 행 |
| 오픈 준비중 | 중립 배경, 버튼 없음, `기다리시면 됩니다` 평문 |
| 요약 칩 줄 | 세 상태의 개수를 목록 위에 |
| 읽기 카드 | 발행 가능 채널의 것을 편다. v20은 끊긴 채널이었으나 v21에서는 끊긴 채널 개념이 3분류로 흡수됨 |
| 비활성 버튼 | **0개.** 정적 QA가 강제 |

## 3. YouTube Create (쇼츠가 주 용도)

```
┌ 쇼츠로 인식되는 조건  [이번에 더함] [공식 문서 기준] ────────┐
│ [비율]   세로 또는 정사각                                     │
│          권장 크기는 1080 곱하기 1920입니다                   │
│ [길이]   3분 미만                                             │
│          이 두 조건을 만족하면 자동으로 쇼츠가 됩니다         │
│ [해시태그] #Shorts는 필수가 아닙니다                          │
│          비율과 길이로 자동 판정하기 때문입니다               │
│ ┌ notice ──────────────────────────────────────────────────┐ │
│ │ 쇼츠 전용 업로드 경로는 없습니다. 일반 영상 업로드와 같은 │ │
│ │ 길로 올라갑니다. 그래서 쇼츠도 같은 하루 한도를 나눠 씁니다│ │
│ └───────────────────────────────────────────────────────────┘ │
│ ┌ warning ─────────────────────────────────────────────────┐ │
│ │ 오늘 우리 서비스 전체가 올릴 수 있는 양은 100건입니다.     │ │
│ │ 이 100건은 회원 1인당이 아니라 전 회원을 합친 숫자입니다.  │ │
│ │ 지금 12건 사용했습니다.                                    │ │
│ └───────────────────────────────────────────────────────────┘ │
│ ▓▓░░░░░░░░░░░░░░░░░░  12 / 100                                │
└───────────────────────────────────────────────────────────────┘
```

금지: `1600 유닛`, `하루 6건`을 어느 화면에도 쓰지 않는다. 정적 QA가 부재를 검사한다.

## 4. X Create (게시당 과금)

```
┌ 이 게시에 드는 비용  [이번에 더함] [건당 과금 채널] ─────────┐
│ [✓] 본문에 링크를 넣습니다                                    │
│ ┌───────────────────────────────────────────────────────────┐ │
│ │ 이 게시 1건                                    약 $0.20   │ │
│ └───────────────────────────────────────────────────────────┘ │
│ ┌ warning ─────────────────────────────────────────────────┐ │
│ │ 링크를 넣으면 약 13배가 됩니다. 링크 없이 올리면 약        │ │
│ │ $0.015입니다. 링크를 프로필에 두고 본문에서 빼는 방법을    │ │
│ │ 고려해 보세요.                                             │ │
│ └───────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────┘
```

체크박스 기본값은 **켜짐**이다. 마케팅 글은 링크를 붙이므로 비싼 쪽이 기본이어야 유저가 나중에 놀라지 않는다.
싼 쪽을 기본으로 두고 켤 때만 경고하면 청구서를 보고 알게 된다. 그건 다크패턴이다.

## 5. TikTok Create (심사 전 비공개)

```
┌ 지금 올리면 어떻게 되나 ──────────────────────────────────────┐
│ ┌ warning ─────────────────────────────────────────────────┐ │
│ │ 비공개로만 게시됩니다. 내 계정에는 올라가지만 다른        │ │
│ │ 사람에게는 보이지 않습니다. 심사를 통과하면 그때부터      │ │
│ │ 공개로 올릴 수 있습니다. 지금 올린 것은 나중에 자동으로   │ │
│ │ 공개가 되지 않습니다.                                     │ │
│ └───────────────────────────────────────────────────────────┘ │
│ [비공개로 시험 게시]  [심사 통과까지 기다리기]                │
└───────────────────────────────────────────────────────────────┘
```

주 버튼은 `심사 통과까지 기다리기`다. 시험 게시를 막지는 않되 기본 권유는 기다림이다.
결과 문구에 `게시됨`을 쓰지 않는다.

## 6. Studio 안 채널별 다시 쓰기 (게시 앞 필수 단계)

```
┌ rewrite-step, 아직 그대로면 warning 테두리 ──────────────────┐
│ [아직 그대로] [게시 전 반드시 거치는 단계] [이번에 더함]      │
│ 채널별로 다시 쓰기                                            │
│ 같은 문장을 여러 채널에 그대로 올리면 플랫폼이 중복으로       │
│ 판단합니다. 한 번 쓴 초안을 채널마다 고쳐 쓰는 것이 이 제품의 │
│ 기본 동작입니다.                                              │
│  [YouTube]   최소한만 바꾼 비슷한 영상 대량 게시 금지         │
│              수익 자격 상실과 채널 정지까지 갈 수 있습니다    │
│  [TikTok]    2025년 9월 원본성 정책으로 중복 노출 감소        │
│              올라가긴 하지만 사람들에게 덜 보입니다           │
│  [Pinterest] 같은 이미지 반복은 스팸으로 표시                 │
│              계정 전체 노출이 떨어집니다                      │
│ ┌ warning ─────────────────────────────────────────────────┐ │
│ │ 지금은 8개 채널이 같은 문장을 씁니다. 이대로 올리면       │ │
│ │ 유튜브와 틱톡에서 노출이 줄거나 제재를 받을 수 있습니다.  │ │
│ │ 첫 문장과 마무리만 바꿔도 중복 판정을 피합니다.           │ │
│ └───────────────────────────────────────────────────────────┘ │
│ [채널별로 다시 쓰기]  [그대로 두고 진행]                      │
│ ── 그대로 두고 진행을 누르면 아래가 열린다 ──                 │
│ ┌ danger ──────────────────────────────────────────────────┐ │
│ │ 그대로 진행하면 이 위험을 고객이 집니다. 유튜브는 최소한  │ │
│ │ 만 바꾼 유사 콘텐츠 대량 게시를 금지하고, 틱톡은 노출을   │ │
│ │ 줄입니다. 그래도 진행하시겠습니까?                        │ │
│ └───────────────────────────────────────────────────────────┘ │
│ [위험을 알고 그대로 진행](danger)  [다시 쓰기로 돌아가기](주) │
└───────────────────────────────────────────────────────────────┘
```

| 규칙 | 내용 |
|---|---|
| 기본 상태 | `아직 그대로`. 다시 쓰기를 하지 않은 상태가 기본이므로 경고가 기본으로 보인다 |
| 막지 않음 | 건너뛰기를 차단하지 않는다. 대신 위험을 한 번 더 읽고 누르게 한다 |
| 되돌리기 | 다시 쓴 뒤에도 원래 문구로 되돌릴 수 있다 |
| 위치 | OSMU 플랫폼 실행 표 바로 아래. 게시로 가는 길목 |
| 주 버튼 | 항상 안전한 쪽. 위험한 쪽은 danger 색이고 부차 위치 |

## 7. Blog 안 네이버 블로그 (반자동)

## 11. 레드팀과 셀프심문

**경쟁자의 공격**: "채널 10개 중 9개에 변명을 달아놨다. 우리는 그냥 되는 채널만 보여준다."

받아들이지 않은 이유: 되는 것만 보여주면 유저는 나머지가 없는 줄 알고 다른 도구를 병행한다.
그리고 오픈 준비중 3개는 우리가 뚫으면 열리는 것이라 로드맵을 유저와 공유하는 효과가 있다.
다만 이 공격의 절반은 맞다. 그래서 첫 화면 강조는 하나로 줄이고, 오픈 준비중을 목록 맨 아래로 밀었다.

**SOCRATIC_MARKER, 이 화면 정의가 틀렸다면 가장 그럴듯한 이유**:
`사유의 주인`을 화면에 노출하는 것이 유저에게 필요 이상의 내부 사정을 보여주는 것일 수 있다.
유저는 "왜 안 되는지"만 알면 되고 "누구 탓인지"는 우리 내부 관심사일 수 있다.
반박: 회장 지시의 핵심이 정확히 그 구분이었고, 실제로 유저 행동이 갈린다.
내 탓이면 지금 뭘 하고 우리 탓이면 기다린다. 이건 내부 사정이 아니라 행동 지시다.
다만 `내가 할 일`·`우리가 할 일`이라는 표현이 책임 공방처럼 읽힐 여지는 남는다.

⛔ 회수 필요: `내가 할 일`·`우리가 할 일` 표현을 유지할지, `지금 연결하기`·`기다리는 중` 같은 행동어로 바꿀지.
