## 1. 문서 역할

이 문서는 `docs/prototype/openclaw-auto-osmu-v25-gpt-codex.html`에 구현된 7개 핵심 화면의 요소, 상태, 인터랙션, 반응형 축을 개발 전달용으로 고정한다.

상류 흐름의 정본은 `docs/design-docs/user-flow-openclaw-service-v9.5-gpt-codex.md`다. 이 문서는 흐름을 재정의하지 않고 화면 단위 구현 계약만 구체화한다.

## 2. 공통 shell

### 2.1 1024px

- 주축: `row`
- 열: sidebar `224px` + content `minmax(0, 1fr)`
- content 내부 주축: `column`
- page 좌우 여백: `space-6`, 24px
- sidebar 순서: 제작 1~3, 검수 4~5, 자산 6, 운영 7
- 상단 순서: 제품 위치, 잔액, 테마 전환
- 검수 전용 control bar는 상단 점유 영역이다. 본문 위에 떠서 가리지 않는다.

### 2.2 390px

- 주축: `column`
- 열: `1`
- sidebar는 숨기고 56px 상단 bar로 대체한다.
- page 좌우 여백: `space-4`, 16px
- 2열·3열 card group은 화면 순서를 유지해 1열로 reflow한다.
- 운영 탭만 내부 가로 scroll을 허용한다. page 전체 가로 scroll은 금지한다.

### 2.3 공통 상태

| 상태 | 필수 표시 | 복구 행동 |
|---|---|---|
| normal | 실제 고객·비용·시간·언어 데이터 | 화면별 주 행동 |
| loading | 대상 이름, skeleton, 보존 안내 | 자동 완료 또는 이전 화면 |
| empty | 비어 있는 대상과 필요한 입력 | 기본값 채우기, 이전 화면 |
| error | 실패 대상, 보존된 값, 실패 이유 | 다시 확인, 저장 후 종료 |
| overflow | 긴 시장·언어·근거·자막·이력 | 줄바꿈·reflow, 내용 삭제 금지 |

## 3. 화면 1. 제작 요청

### 목적

콘텐츠가 노출될 타깃 시장과 결과물의 출력 언어를 서로 다른 값으로 확정한다.

### 요소 순서

1. 진행 표시 `질문 1/3`
2. 제목과 3개 상한 설명
3. 타깃 시장 선택기
4. 출력 언어 선택기
5. 언어별 품질 보증 범위 안내
6. 추천안 카드
7. 건너뛰기·추천값 사용·다음 질문 행동

### 레이아웃

- 1024 주축: `row`, 입력 `7` + 추천 `5`
- 각 선택기: `grid`, 2열
- 390 주축: `column`, 선택기 1열, 추천 카드는 입력 다음

### 인터랙션

- 시장·언어 option 선택 시 선택 border와 check를 함께 갱신한다.
- 추천값 사용 시 `한국 시장 · 한국어`가 선택되고 이후 화면 context bar에 유지된다.
- 품질 보증 안내는 생성 가능 여부와 품질 보증 여부를 구분한다.
- 다음 질문은 질문 화면으로 이동한다.

## 4. 화면 2. 질문 3개

### 목적

요청 확정에 꼭 필요한 질문만 최대 3개까지 제시하고 추천안으로 결정 부담을 줄인다.

### 요소 순서

1. `질문 2/3`와 `질문은 3개가 끝입니다`
2. 시장·언어·취향·브랜드 context bar
3. 3칸 progress
4. 선택지 3개
5. 추천안, 근거, 예상 비용 범위, 예상 소요 시간, 한계
6. 이전·건너뛰기·다음 질문

### 레이아웃

- 1024 주축: `row`, 선택지 `7` + 추천 `5`
- 선택지: `column`, 3행
- 390 주축: `column`, 추천 카드는 선택지 다음

### 인터랙션

- 추천안 1개를 먼저 강조하되 직접 입력과 다른 선택을 유지한다.
- 건너뛰기는 현재 저장값을 보존하고 다음 질문으로 이동한다.
- 세 번째 답 이후 네 번째 질문을 만들지 않고 후보 비교로 이동한다.

## 5. 화면 3. 저해상도 후보 비교

### 목적

동일 요청에서 만든 저해상도 후보 A·B·C를 같은 기준으로 비교하고 고해상도 제작 대상 하나만 고른다.

### 요소 순서

1. 제목과 후보 준비 상태
2. 시장·언어·취향·브랜드 context bar
3. 후보 A, 후보 B, 후보 C
4. 선택본 1개 고해상도 안내
5. 미선택 후보 추가 과금 안내
6. 질문 수정·선택 확인

### 후보 카드 공통 구조

1. 16:10 저해상도 preview
2. 후보 label과 차이 제목
3. 설명형·전후 대비형·공감 서사형 방식
4. 적용 근거
5. 고해상도 예상 비용
6. 예상 소요 시간
7. 후보 선택 CTA

### 레이아웃

- 1024 주축: `row`, 3열 `repeat(3, minmax(0, 1fr))`
- metric 주축: `row`, 2열
- 390 주축: `column`, A 다음 B 다음 C
- 후보 순서와 내부 정보 순서는 viewport가 바뀌어도 동일하다.

### 인터랙션

- 한 번에 후보 하나만 selected 상태가 된다.
- 선택 확인 CTA는 선택한 후보 이름을 다시 읽어준다.
- 질문 수정은 앞 단계로 돌아가며 현재 답을 보존한다.
- `선택한 하나만 고해상도로 만들어집니다.`를 neutral notice로 표시한다.
- `나머지를 나중에 고해상도로 만들면 추가 과금입니다.`를 warning notice로 표시한다.

## 6. 화면 4. 결과 편집

### 목적

고해상도 결과에서 무료 조정과 유료 재생성을 실행 전에 구분한다.

### 요소 순서

1. 고해상도 제작 완료 상태
2. 시장·언어 context bar
3. 결과 preview
4. 무료 편집 영역
5. 유료 재생성 영역
6. 후보로 돌아가기·저장 후 발행 검수

### 레이아웃

- 1024 주축: `row`, preview `5` + control `7`
- control 주축: `column`
- 컷 행 주축: `row`, 순번·이름·시간·행동
- 390 주축: `column`, preview 다음 무료 편집 다음 유료 재생성

### 인터랙션

- 자막 크기 A−·A+와 컷 순서 위·아래는 추가 크레딧 없이 즉시 반영한다.
- 나레이션 변경과 소재 교체는 새 결과 생성이므로 예상 비용·시간을 표시하고 `견적 보기` 뒤 실행한다.
- 저장 후 발행 검수는 발행 설정으로 이동한다.

## 7. 화면 5. 발행 설정

### 목적

사람 승인 후 발행을 기본으로 유지하고 자율 발행은 명시적으로 켜는 옵션으로 제한한다.

### 요소 순서

1. 승인 대기 상태
2. 시장·언어 context bar
3. 승인 후 발행 기본 카드
4. 자율 발행 option과 off toggle
5. 대상 계정·토큰 만료·예약 시각
6. 결과·수정·실제 사용·언어 readback
7. 승인하고 예약·편집으로 돌아가기

### 레이아웃

- 1024 주축: `row`, 발행 설정 `7` + 결과 readback `5`
- 390 주축: `column`, 기본·옵션·대상·readback 순서

### 인터랙션

- 초기값은 `승인 후 발행`이다.
- 자율 발행 toggle을 켤 때 적용 계정·시각·언어·실패 처리 범위를 확인한다.
- 예약 CTA는 계정과 `오늘 오후 8:30`을 함께 읽어준다.

## 8. 화면 6. 출력 언어별 취향

### 목적

한국어 수정이 다른 언어의 취향 프로파일을 오염시키지 않도록 언어별 상태와 변경 근거를 사람이 읽게 한다.

### 요소 순서

1. 마지막 갱신 시각
2. 한국어·English·日本語·ไทย 탭
3. 활성 언어 profile version
4. 선호·피해야 할 표현·학습 근거·적용 범위
5. 최근 변경 diff와 수정 이유
6. 현재 언어만 변경한다는 경계 안내

### 레이아웃

- 1024 주축: `row`, profile `8` + 변경 이력 `4`
- profile 행 주축: `row`, label `128px` + value
- 390 주축: `column`, profile 다음 변경 이력

### 인터랙션

- 탭을 바꾸면 해당 언어의 profile과 변경 이력만 교체한다.
- 취향 수정은 현재 언어 scope를 확인한 뒤 저장한다.
- 이전 버전 복원은 변경 전후를 확인한 뒤 실행한다.

## 9. 화면 7. 1인 운영자 예외함

### 목적

1인 운영자가 지금 복구해야 할 사건만 보고 다음 행동을 실행한다. 분석 dashboard가 아니다.

### 허용 범위

1. 잔액
2. 실패
3. 큐
4. 토큰 만료
5. 고객 막힘
6. 환불 근거

성과 지표, 예측 매출, 채널 성과, 퍼널 chart는 추가하지 않는다.

### 요소 순서

1. 지금 조치 건수
2. 6개 범위 탭
3. 지금 조치·보존된 고객 작업·가장 오래된 사건
4. 사건 시간·고객·근거·다음 행동
5. 운영 BI 비범위 안내

### 레이아웃

- 1024 주축: `column`, 통계 3열, 사건 행 `time + subject + action`
- 390 주축: `column`, 통계 1열, 사건 내부도 세로
- 탭 주축: `row`, 390에서는 component 내부 scroll

### 인터랙션

- 탭 선택 시 해당 예외만 교체한다.
- 조치 CTA는 고객·근거·예상 결과를 먼저 보여준다.
- 해결 후 사용자가 다음 예외 또는 제작 화면으로 이동할 수 있어 dead-end가 없다.

## 10. dead-end 감사

| 화면 | 앞으로 | 뒤로·대체 | 판정 |
|---|---|---|---|
| 제작 요청 | 다음 질문 | 추천값 사용, 건너뛰기, 저장 후 종료 | 0 |
| 질문 3개 | 다음 질문, 후보 비교 | 이전, 건너뛰기 | 0 |
| 후보 비교 | 선택 확인, 편집 | 질문 수정 | 0 |
| 결과 편집 | 발행 검수 | 후보로 돌아가기 | 0 |
| 발행 설정 | 승인·예약 | 편집으로 돌아가기, 자율 발행 off | 0 |
| 언어별 취향 | 수정·복원 | 다른 언어 탭, 제작 화면 | 0 |
| 운영 예외함 | 조치 | 다른 예외 탭, 제작 화면 | 0 |

## 11. 회수 필요

- ⛔ 회수 필요: 후보 preview는 구조 검증용 semantic 면이다. 실제 저해상도 asset이 준비되면 같은 frame에 넣어 판단 정확도를 재검증해야 한다.
- ⛔ 회수 필요: 비용·시간 계산식과 queue 예측 계약은 기술설계 합의가 필요하다.
- ⛔ 회수 필요: 자율 발행의 실패 정책과 검수 범위는 제품·기술·운영 합의가 필요하다.

## 12. 셀프심문과 레드팀

질문: 이 화면 계약이 틀렸다면 가장 그럴듯한 이유는 무엇인가?

답: 390px 후보 비교에서 세 후보를 한 화면에 동시에 볼 수 없어 기억 부담이 남는다. 동일한 정보 순서와 선택 후보 readback으로 부담을 줄였지만 실제 사용자 과제 전에는 충분하다고 단정할 수 없다.

수정: 후보별 label·metric·CTA 위치를 반복하고 최종 CTA에 `B 후보 선택 확인`을 표시했다. 본문을 가리는 floating tray는 첫 캡처 결함 때문에 채택하지 않았다.

까다로운 고객의 공격: 예상 비용과 실제 차감이 다르면 신뢰를 잃는다.

수정: 생성 전 화면은 `예상 범위`, 결과·발행 화면은 `실제 사용`으로 용어를 분리하고 유료 변경은 견적 확인 뒤 실행하게 했다.
