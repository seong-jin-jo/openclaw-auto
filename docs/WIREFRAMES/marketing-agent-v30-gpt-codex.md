## 1. PRD 문구 → 화면 요소 대응표 (이번 판의 합격 판정 기준)

| PRD 문구 (원문 근거) | 화면 요소 | 확인 위치 |
|---|---|---|
| "소재(asset) 제작의 재료인 기존 이미지·영상·음성·로고·문서. **업로드만으로 취향을 바꾸지 않음**" (379행) | 학습 정보 1번 탭 `소재`. 다섯 종류를 종류 배지와 함께 나열하고, 패널 머리에 `취향을 바꾸지 않음` 배지, 하단에 "취향이 바뀌는 곳은 학습신호 탭입니다. 소재를 빼도 지금까지 배운 취향은 그대로 남습니다" | `taste-asset` |
| "학습신호(signal) 선택·제안 채택·성과·트렌드처럼 취향 프로파일을 바꾸는 사건" (380행) | 학습 정보 2번 탭 `학습신호`. 후보 선택 2건, 편집 수정 지시 2건, 성과 관측 1건, 트렌드 관측 1건, 제안 채택 1건을 사건 단위로 나열 | `taste-signal` |
| "수정 지시는 취향의 약한 신호로 기록하되, 후보3 중 선택과 **같은 강한 신호로 취급하지 않는다**" (301행) | 같은 탭의 세기 배지 3종. `강한 신호`(후보 셋 중 선택) · `약한 신호`(편집 수정 지시) · `반영 보류`(성과·트렌드·제안 채택). 상단 수치 필드에 세 세기의 정의를 라벨과 값으로 고정 | `taste-signal` |
| "언어별 취향 프로파일: 출력 언어마다 분리되는 선택·수정·성과 근거의 **versioned 집계**" (377행) / "교차 언어 자동 이식을 금지" (FR-OS82-031) | 학습 정보 3번 탭 `취향 프로파일`. 한국어 판 7, English 판 2, 日本語 판 없음으로 언어 블록을 분리하고 "한국어에서 잘 먹은 것을 일본어로 옮기지 않습니다" 안내 | `taste-profile` |
| "언어가 다른데 근거가 없으면 공통 브랜드 사실과 해당 언어 기본 프로파일만 사용하고 `근거 부족`을 표시" (327행) | 日本語 블록이 항목 대신 `근거 부족` 상태와 "이 언어로 만든 기록이 없습니다"를 표시 | `taste-profile` |
| "변경 근거 ID·기간·표본·한계를 보여주며" (283행 근거 3종 필수 표시) | 프로파일 항목마다 `근거 sig-2418 · sig-2402 / 기간 7월 28일부터 8월 10일 / 표본 선택 4회 / 한계 같은 주제 안에서만 관찰됨` 네 값을 고정 배치 | `taste-profile` |
| "**고객 승인 전 취향 profile을 바꾸지 않아야 한다**" (AC-020 silent preference mutation 0) | 학습 정보 4번 탭 `승인 대기`. `아직 반영 안 됨` 배지, "회원님이 승인해야 바뀝니다", 제안마다 근거·기간·표본·한계와 반영·안 함 두 버튼 | `taste-pending` |
| "표본이 적을 때 나온 평균은 다음 판단을 잘못된 방향으로 끌고 간다" / 근거 없는 성과 점수 비범위(§3.10) | 승인 대기 하단 "게시 4건 이하에서 나온 차이는 우연일 수 있어, 반영하시더라도 그 표시를 함께 남깁니다" | `taste-pending` |
| "**출력 언어는 취향이 아니라 요청 제약이다**" (376행·FR-OS82-030) | 학습 정보에는 언어를 값으로 두지 않고 프로파일 분리 축으로만 쓴다. 언어를 고르는 자리는 제작 2단계 `시장과 언어` | `taste-profile` · `make-market` |
| "작업은 하나, 출력 플랫폼만 고른다. 플랫폼 선택이 제작의 **입구가 아니라 출구**" (결정서 §9.8 D8) | 제작 단계에서 플랫폼 고르기를 제거. 승인 인박스 3번 탭 `올림 여부`에서 곳마다 올림·올리지 않음, 4번 탭 `발행 결과`에서 그 결과 | `make-outlet` · `publish` |

## 2. 제작 흐름 (5단계)

| 단계 | 질문 | 화면 |
|---|---|---|
| 1 | 무엇으로 만들까요 (글·이미지·영상) | `make-medium` (첫 사용자는 앞에 `make-first` 학습 안내 한 질문) |
| 2 | 누구에게 어떤 말로 낼까요 (시장·출력 언어) | `make-market` |
| 3 | 세 방향 중 무엇으로 갈까요 | `cand-pick` |
| 4 | 이대로 갈지, 다른 안을 볼지, 품질을 높일지 | `judge` (학습 동의는 `judge-consent`로 분리) |
| 5 | 이 결과로 확정할까요 | `make-confirm` (Studio는 여기서 끝) |

## 3. 승인 인박스 (Studio에서 넘어온 뒤)

| 탭 | 하는 일 | 화면 |
|---|---|---|
| 1 검토 | 바뀐 내용, 승인과 수정 요청 | `inbox` 기본 |
| 2 미리보기 편집 | 텍스트 · 사진과 카드뉴스 · 짧은 영상 · 전달과 요약 | `edit-text` `edit-card` `edit-video` `edit-delivery` |
| 3 올림 여부 | 곳마다 올림 · 올리지 않음 | `make-outlet` `make-outlet-narrow` |
| 4 발행 결과 | 지금 올릴지 예약할지, 올린 뒤 세 갈래 | `publish` `publish-done` |

## 4. 비로그인 경계

| 상태 | 되는 것 | 화면 |
|---|---|---|
| 로그인 안 함 | 실제 결과 예시 보기 | `guest-tour` |
| 로그인 안 함 | 매체 고르기, 후보 받기 | `guest-tour` 2단계 |
| 계정 필요 | 저장, 발행, 학습 | `guest-wall` (지금까지 고른 값은 로그인 뒤 그대로 이어짐) |

## 5. 지우지 않은 것

화면 삭제 0건. 미리보기 편집 · 올림 여부 · 발행 결과는 삭제가 아니라 Studio에서 승인 인박스로 **소속만 이동**했다.
사이드바 24항목, 라우트, Studio 인벤토리(미리보기 7 · 직접 발행 4 · 텍스트 어댑터 8 · 영상 3) 모두 그대로다.
