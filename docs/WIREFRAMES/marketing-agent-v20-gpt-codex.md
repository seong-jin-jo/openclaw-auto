## 0. 구성 원칙

1. v19의 PageShell, 사이드바 9그룹 26목적지, 토큰, 컴포넌트를 그대로 쓴다. 새 primitive를 만들지 않았다.
2. 이번에 더한 것은 CSS 한 줄 수정 하나와 조합 컴포넌트 넷뿐이다.
   - `.grid > .panel + .panel{margin-top:0}` (기존 카드 어긋남의 실제 원인 수정)
   - `OriginChip`, `startStrip`, `accountReadback`, `onboardingDialog`
3. 화면 안 표시 3종. 무게는 12px 칩이고 제목보다 항상 작다.
   - `지금 제품에 있음` 초록 · `이번에 더함` 파랑 · `아직 없음` 주황
4. 목표 최소 44×44. 포커스는 3px accent 외곽선에 2px 오프셋.

| 요소 | 규칙 |
|---|---|
| 시작 체크리스트 | 4항목 완료 시 DOM에서 제거. 미완이면 항상 홈 최상단 |
| 강조 | `data-step-next="true"`는 화면 전체에 정확히 1개. 실측으로 강제 |
| 주 버튼 문구 | 다음 미완 항목 이름을 그대로 읽어 `<항목> 시작하기` |
| span-8 kicker | `확인이 필요한 문구`. v19의 `다음 할 일`은 체크리스트와 주장이 겹쳐 제거 |
| 보류 문구 | warning 색 12px. 숫자 밑에 붙어 숫자와 함께 읽힌다 |
| 예시 데이터 | 실데이터 아님을 뱃지로 명시. 뱃지 없는 숫자를 쓰지 않는다 |

상태별:

| 상태 | 화면 |
|---|---|
| loading | 실제 레이아웃과 같은 2줄 shimmer. 마지막 정상 화면 유지 |
| empty | 체크리스트만 남고 성과 카드는 0을 그리지 않는다 |
| error | 판정 실패 시 어떤 항목도 완료로 칠하지 않고 사유와 재시도 |
| 4항목 완료 | 체크리스트 영역 제거. 화면 최상단이 `확인이 필요한 문구`로 올라온다 |

## 2. 가입 직후 4단계 (Dialog)

```
┌─ overlay ──────────────────────────────────────────────┐
│ 가입 직후 · 3 / 4                              [닫기]  │
│ 첫 번째 채널 연결                                      │
│ ─────────────────────────────────────────────────────  │
│ [지금 제품에 있음]  Google 계정으로 계속 한 번          │
│                                                        │
│ 공식 로그인 화면으로 이동해 이 작업 공간에 계정을      │
│ 연결합니다.                                            │
│ 비밀번호는 받지 않습니다. 승인하고 돌아오면 자격증명이 │
│ 서버에 암호화 저장되고, 이 화면에는 어떤 계정이        │
│ 연결됐는지만 표시됩니다.                               │
│                                                        │
│ ┌ notice ─────────────────────────────────────────┐   │
│ │ 연결을 승인하고 돌아오면 아래 항목이 채워집니다. │   │
│ └─────────────────────────────────────────────────┘   │
│  연결된 계정        @monostudio                        │
│  계정 식별자 끝자리 …2390                              │
│  ... (계정 저장 내용 읽기 카드 §4)                     │
│                                                        │
│ [이전] [다음]  나중에 하기                             │
└────────────────────────────────────────────────────────┘
```

- 단계 이름과 본문 문구는 코드의 `OnboardingWizard` 4단계를 그대로 옮겼다.
- 3단계에만 저장 내용 읽기 카드를 미리 보여준다. 승인 전에 무엇이 저장될지 알고 누르게 한다.
- 390에서는 전체 화면 dialog. 머리가 sticky, 본문 스크롤, 버튼은 폭 100%.
- Escape로 닫힌다. 닫아도 어떤 선택도 잃지 않는다.
- 이메일·비밀번호 입력 화면은 없다. 코드에 없으므로 그리지 않았다.

## 3. 채널 화면의 탭 구조

```
Threads:
[Create*] [Queue] [Calendar*] [Analytics] [Growth] [Popular] [Settings]
   ↑신설              ↑신설

그 외 콘텐츠 채널:
[Create*] [Queue] [Calendar*] [Analytics] [Settings]
```

| 규칙 | 내용 |
|---|---|
| 상대 순서 보존 | Queue → Analytics → (Growth → Popular) → Settings 순서를 바꾸지 않았다 |
| 삽입 위치 | Create는 맨 앞, Calendar는 Queue 바로 뒤 |
| 신설 표시 | 탭 자체에는 표시하지 않고(탭 줄이 시끄러워진다) 해당 탭 본문 첫 줄에 `이번에 더함` 칩 |
| 유효하지 않은 탭 | 비-Threads에서 growth·popular를 요청하면 Create로 안전 복귀 |
| 390 | 탭 줄이 wrap. 가로 스크롤 없음. 각 탭 최소 44px |

### 3.1 Create

```
┌ span-7 이 채널에서 초안 만들기 ────────┐ ┌ span-5 검토와 게시 ────┐
│ [이번에 더함] 현재 제품의 대기열에는   │ │ 현재 수정본을 승인한   │
│               작성 칸이 없습니다       │ │ 뒤 지금 게시하거나     │
│ (Instagram만) [피드][카드뉴스][Reels] │ │ 예약합니다.            │
│ 문구                                   │ │ [검토 요청] [승인]     │
│ ┌────────────────────────────────────┐ │ │ [지금 게시] [예약]     │
│ │ AI 자동 게시보다, 고객이 확인할 수 │ │ │                        │
│ └────────────────────────────────────┘ │ └────────────────────────┘
│ [이 플랫폼에서 만들기] [현재 초안 편집]│
└────────────────────────────────────────┘
```

영상 채널은 본문이 다르다. 대본·9:16 원본·자막 안전 영역·사용 권리를 확인하는 영상 작업 계약을 쓰고,
텍스트 대기열로 평준화하지 않는다. `이번에 더함` 옆 문구는 `현재 제품은 영상 작업을 Videos에서 시작합니다`.


| 규칙 | 내용 |
|---|---|
| 필드 수 | 10개 고정. 저장 7 + 미구현 3. 미구현을 목록에서 빼지 않는다 |
| 미구현 표시 | 값 자리에 warning 색으로 왜 못 보여주는지 적는다. 빈칸이나 하이픈을 쓰지 않는다 |
| 경고 위치 | 읽기 목록 **위**에. 읽기 전에 알려준다 |
| 값 정렬 | 날짜와 식별자는 tabular-nums |
| 절대 금지 | 액세스·갱신 값 원문, 복호화 결과, 서버 환경변수 이름 |
| 390 | 라벨과 값이 위아래로 쌓인다. 라벨 폭 고정을 풀어 값이 잘리지 않게 한다 |

## 4. Settings 안 Channels, 끊긴 채널 우선

```
┌ 발행 채널 연결  [지금 제품에 있음] ────────────────────────────┐
│ 공식 로그인 한 번으로 연결됩니다. 비밀번호는 받지 않습니다.     │
│ 손이 필요한 채널은 그 이유를 함께 적었습니다.                   │
│ ┌ warning ───────────────────────────────────────────────────┐│
│ │ 다시 연결해야 하는 채널은 목록 맨 위에 올려 두었습니다.     ││
│ └────────────────────────────────────────────────────────────┘│
│ ┏━ warning-soft 배경, 강조 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓│

│ ┃         서버 자격증명 준비됨 · 다시 연결하면 초안과 예약은 ┃│
│ ┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛│
│  [정상] Threads · @monostudio                 [연결 확인]     │
│  [정상] Instagram · @monostudio               [연결 확인]     │
│  [정상] YouTube Shorts · Mono Studio          [연결 확인]     │
│  [연결 안 됨] X                               [연결](잠김)    │
│         서버 자격증명 미설정 · 운영자 확인 필요               │
│  [연결 안 됨] Facebook                        [연결]          │
│  [연결 안 됨] Bluesky                         [연결]          │
│         플랫폼 표준상 직접 입력 · 공식 로그인을 제공하지 않아 │
│ [선택한 계정 저장 내용 보기]  중앙 연결 앱 상태               │

┌ TikTok에 저장된 것  [이번에 더함] ────────────────────────────┐

└────────────────────────────────────────────────────────────────┘
```

| 규칙 | 내용 |
|---|---|
| 정렬 | 주의가 필요한 채널(만료됨·연결 해제됨)이 먼저. 나머지는 원래 순서 |
| 강조 | 배경만 바꾼다. 왼쪽 색 테두리는 쓰지 않는다(슬롭 목록 8번) |
| 버튼 상태 | 서버 자격증명이 없으면 disabled. 눌러서 오류를 보게 만들지 않는다 |
| 사유 문장 | 채널마다 다르게. `준비 중` 같은 뭉갠 문구를 쓰지 않는다 |
| 아래 카드 | 목록 첫 번째 채널의 저장 내용을 자동으로 펼친다. 지금 문제인 채널이 곧 보고 싶은 채널이다 |

- 페이지 머리와 패널 안에 같은 칩을 반복하기

## 9. 레드팀과 셀프심문

**경쟁자의 공격**: "칩으로 세 가지 상태를 표시하면 화면이 라벨 밭이 된다. 사용자는 라벨을 읽지 않는다."
받아들인 수정: 칩을 12px로 묶고 색 대비를 낮춰 제목보다 항상 뒤로 물렸다.
그리고 칩을 화면당 최대 2개로 제한했다. 페이지 머리에 칩이 있으면 패널에서 반복하지 않는 규칙을 §5에 넣었다.
실제로 운영자 화면에서 중복된 칩 하나를 스크린샷을 보고 제거했다.

**SOCRATIC_MARKER, 이 화면 정의가 틀렸다면 가장 그럴듯한 이유**:
정직 표시가 늘어난 만큼 화면의 인지 부담이 늘었다는 점이다.
`Don't make me think` 기준으로 보면 `이번에 더함`은 고객이 몰라도 되는 내부 사정이다.
반박: 이번 산출물의 1차 독자는 회장과 기술설계이고, 이 표시는 구현 범위를 정하는 도구다.
구현이 끝나면 표시가 제거되고 그 제거가 완료 증거가 된다. 즉 이것은 영구 UI가 아니라 단계 산출물의 장치다.
다만 이 장치를 고객 배포본에 그대로 내보내면 잘못이다. 그 경계를 §8 금지 패턴에 못 박았다.

⛔ 회수 필요: `이번에 더함`·`아직 없음` 표시가 설계 단계 장치인지, 실제 배포 UI에도 남길 신뢰 장치인지 회장 결정.
