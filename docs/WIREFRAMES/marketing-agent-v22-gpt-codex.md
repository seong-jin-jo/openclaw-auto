## W1. 연결 화면 (신설)

겹침 창. 고객 역할에서만 뜬다. `Esc`로 닫힌다.

### W1.1 공통 뼈대

```
┌───────────────────────────────────────────────┐
│ 채널 연결 · Threads                      [닫기]│
│ Threads 연결                                   │
│                                                │
│ (시작) (Threads 승인) (연결 완료)   ← 단계 표시  │
│                                                │
│ ─── 본문 (단계마다 다름) ───                    │
│                                                │
│ [주 행동]  [보조]  [취소]                       │
└───────────────────────────────────────────────┘
```

단계 표시는 세 칸이며 현재 칸은 강조색, 지나온 칸은 성공색, 남은 칸은 중립이다.

### W1.2 시작

| 요소 | 내용 | 근거 |
|---|---|---|
| 도입 문장 | `Instagram을 이 작업 공간에 연결합니다. 다음 화면은 Instagram이 직접 보여주는 승인 화면입니다.` | `lib/social-connect.ts` 주석 (비밀번호는 provider 화면에서만) |
| 권한 목록 | 채널마다 4줄 고정. 마지막 줄은 항상 `비밀번호는 받지 않습니다` | 각 provider scope |
| 필요한 계정 종류 | `제한 없음`이 아닌 채널에서만 표시 | 정책 매트릭스 §2 |
| 안내 | 채널별 주의사항 1줄 (토큰 수명·비용·심사 전 비공개 등) | 매트릭스 + 코드 |
| 주 행동 | `Instagram 승인 화면 열기` 또는 `값 입력하러 가기` | |
| 보조 | `나중에 하기` | |

**상태:** 이 단계에 로딩·오류 상태는 없다. 아직 외부로 나가지 않았기 때문이다.

### W1.3 제공자 승인 (대체 표현)

```
┌─ 회색 바 ────────────────────────────────────┐
│ Threads 승인 화면 · 우리 제품이 아니라        │
│ Threads가 보여주는 화면입니다                 │
├───────────────────────────────────────────────┤
│ 모노스튜디오가 다음을 요청합니다               │
│  ✓ 이 계정으로 글을 올립니다                   │
│  ✓ 올린 글의 반응 숫자를 읽습니다              │
│  ✓ 계정 이름을 읽습니다                        │
│  ✓ 비밀번호는 받지 않습니다                    │
│  비밀번호는 Threads 화면에서만 입력하고        │
│  우리를 거치지 않습니다.                       │
└───────────────────────────────────────────────┘
ℹ 이 프로토타입은 Threads의 실제 화면을 대신 그린 것입니다.
  실제 연결은 개발 단계에서 확인합니다.

[승인하고 돌아오기] [연결 실패해 보기] [취소]
```

`연결 실패해 보기`는 검수용 갈래다. 실제 제품에서는 제공자가 실패를 돌려줄 때 자동으로 열린다.
프로토타입에서 실패 경로를 눌러볼 방법이 없으면 그 경로는 설계되지 않은 것과 같다.

### W1.4 값 직접 입력 (Bluesky · Telegram · Discord)

공식 로그인 화면이 없는 채널. 같은 자리에 입력 칸이 들어간다.

| 채널 | 첫 칸 | 둘째 칸 | 경고 |
|---|---|---|---|
| Bluesky | 핸들 | 앱 비밀번호(가림) | `로그인 비밀번호가 아닙니다` |
| Telegram | 봇 토큰 | 없음 | `봇을 보낼 채널의 관리자로 넣어야 실제 전달이 됩니다` |
| Discord | 웹훅 주소 | 없음 | `주소를 지우면 전달도 즉시 끊깁니다` |

고정 문장: `여기 받은 값은 암호화해 저장하고 다시 보여주지 않습니다.`

### W1.5 실패

```
⚠ 이 계정으로는 연결할 수 없습니다. 필요한 계정 종류가 아닙니다.
  계정 종류를 바꾼 뒤 다시 시도해 주세요.

ℹ 이렇게 하면 됩니다
  Instagram 앱에서 프로페셔널 계정으로 바꾸고, Facebook 로그인으로
  연결한다면 Facebook 페이지도 연결해 주세요.

ℹ 만들던 초안과 예약은 그대로 있습니다. 연결 실패로 잃은 것은 없습니다.

[다시 시도] [다른 실패 사유 보기] [닫기]
```

- `서버에 앱 값이 없음`일 때만 주 버튼이 `운영자에게 알리기`로 바뀐다. 고객이 재시도해도 소용없기 때문이다.
- `일시적 오류`일 때만 문의번호 `req_8f31c2`가 붙는다. 코드가 상관 ID를 남기는 갈래가 이것뿐이다.
- 보존 안내는 5종 모두에 고정으로 붙는다.

### W1.6 연결 완료

| 필드 | 값 예시 | 비고 |
|---|---|---|
| 연결된 계정 | `@monostudio.official` | |
| 계정 식별자 | `…5514` | 끝자리만 |
| 연결 방식 | `공식 로그인` 또는 `값 직접 입력` | |
| 다시 확인 필요 | `2026-10-08` 또는 `앱 비밀번호 폐기 전까지` | |
| 저장 형태 | `암호화 저장 · 원문은 어느 화면에도 표시하지 않음` | 고정 |

아래에 다음 행동 카드. `Threads에서 초안 만들기`(주) / `다른 채널도 연결` / `닫기`.
`다른 채널도 연결`은 창을 닫지 않고 다음 연결 가능 채널로 갈아탄다.

## W2. 채널 상세 · 지금 이 채널 상태 (모습 변경)

v21 구성(3분류 배지 + 사유 + 해결 방법 + 보낼 수 있는 양 + 필요한 계정 종류)을 유지하고
사유 블록 끝에 **지금 하실 일 카드**를 더한다.

### W2.1 미연결

```
[미연결] [내가 할 일]
이 채널은 준비돼 있는데 아직 연결하지 않았거나, 계정 종류가 맞지 않습니다.
개인 계정으로는 연결할 수 없습니다.

ℹ 이렇게 하면 됩니다
  Instagram 앱에서 프로페셔널 계정으로 바꾸고 …

┌ 강조 테두리 ─────────────────────────────────┐
│ 지금 하실 일: Instagram 연결                  │
│ 승인 화면에서 무엇을 허용하는지 먼저           │
│ 보여드립니다. 비밀번호는 받지 않습니다.        │
│ [Instagram 연결 시작] [연결 없이 초안만 저장]  │
└───────────────────────────────────────────────┘
```

카드 본문은 바로 위 `이렇게 하면 됩니다`와 같은 문장을 되풀이하지 않는다.
같은 말을 두 번 하면 둘 다 안 읽힌다.

### W2.2 오픈 준비중

```
[오픈 준비중] [우리가 할 일]
Google 민감 권한 검증과 YouTube 컴플라이언스 감사를 아직 통과하지 못했습니다.

ℹ 기다리시면 됩니다. 이 채널은 고객이 할 수 있는 일이 없고,
  우리가 준비를 끝내면 자동으로 열립니다.

┌ 중립 카드 ───────────────────────────────────┐
│ 지금 하실 일은 없습니다                        │
│ 플랫폼 심사가 끝나면 이 채널이 자동으로        │
│ 열립니다. 그동안 초안은 미리 만들어 둘 수      │
│ 있고, 열리는 즉시 그대로 게시됩니다.           │
│ [먼저 초안만 만들어 두기] [열리면 알림 받기]   │
└───────────────────────────────────────────────┘
```

카드 배경이 강조색이 아니라 중립이다. 색이 곧 재촉이기 때문이다.

### W2.3 카드가 한 화면에 두 번 나올 때

같은 화면의 게시 패널에도 같은 행동이 필요하다. 이때 두 번째 자리는
온전한 카드가 아니라 **같은 버튼 하나만** 놓는다. 같은 카드를 두 번 놓으면 강조가 반으로 준다.
어느 자리가 원본인지는 그리는 순서가 아니라 화면 설계가 정한다. 원본은 항상 상태 블록이다.

## W3. 채널 상세 · 게시 패널 (모습 변경)

### W3.1 발행 가능

v21 그대로. `검토 요청` `승인` `지금 게시` `예약`. 게시 후 결과 문구.

**v22 추가:** 게시가 확인되면 그 아래에 주소 줄과 다음 행동 카드가 붙는다.

```
┌ 성공 배경 ───────────────────────────────────┐
│ 게시된 글 주소  https://www.threads.net/…     │
└───────────────────────────────────────────────┘
┌───────────────────────────────────────────────┐
│ 다음에 하실 일                                 │
│ 반응 숫자는 제공자가 집계하는 데 시간이         │
│ 걸립니다. 지금은 게시된 것만 확인되고,          │
│ 성과는 확인되는 대로 채워집니다.                │
│ [게시 결과 열기] [이 채널 성과 보기] [다음 초안]│
└───────────────────────────────────────────────┘
```

### W3.2 미연결 또는 오픈 준비중

패널 제목이 `게시는 아직 열려 있지 않습니다`로 바뀐다.

```
Instagram 계정을 연결하면 이 자리에 승인과 게시가 나타납니다.
지금 누를 수 있게 두면 반드시 실패합니다.

[연결 후] 검토 요청   연결이 끝나면 이 자리에 버튼으로 나타납니다
[연결 후] 승인        연결이 끝나면 이 자리에 버튼으로 나타납니다
[연결 후] 지금 게시    연결이 끝나면 이 자리에 버튼으로 나타납니다
[연결 후] 예약        연결이 끝나면 이 자리에 버튼으로 나타납니다

[Instagram 연결 시작]
```

네 줄은 버튼이 아니라 예고다. 오픈 준비중이면 표시가 `열린 뒤`로 바뀐다.

**초안 만들기는 계속 활성이다.** 미연결에서는 `연결 없이 초안만 저장`,
오픈 준비중에서는 `먼저 초안만 만들어 두기`.

### W3.3 TikTok 심사 전 예외

TikTok은 심사 전에도 비공개 게시가 실제로 된다. 그래서 이 채널만 예고가 아니라 실제 갈래 둘을 준다.
`비공개로 시험 게시` / `심사 통과까지 기다리기`. 누른 결과 문구도 그 패널 안에 남는다.

## W4. 홈 · 시작 체크리스트 (모습 변경)

### W4.1 진행 중

```
┌ 강조 테두리 ──────────────────────────────────────────────┐
│ 여기까지 하면 혼자서도 돌아갑니다              0 / 4 완료   │
│ [1 채널 1개 연결] [2 브랜드 위키] [3 콘텐츠 발행] [4 성과]  │
│ 발행 가능 0  미연결 7 [내가 할 일]  오픈 준비중 3 [우리가]  │
│ 오픈 준비중인 3개는 우리가 … 지금 하실 일은 없습니다.       │
│ [Threads 연결 시작]  [가입 직후 4단계 다시 보기]            │
└─────────────────────────────────────────────────────────────┘
```

- 완료된 단계는 성공색 배경 + `✓`. 다음 단계는 강조 테두리.
- **주 버튼이 다음 단계에 따라 바뀐다.** 1단계가 남아 있으면 연결 시작이 곧 주 버튼이다.
- 각 단계 카드를 직접 눌러도 그 단계의 실제 행동으로 간다(§W4.3).
- 1024에서 4칸이 2×2로 접힌다. 390에서는 1열.

### W4.2 완료

```
┌───────────────────────────────────────────────────────────┐
│ 첫 흐름을 끝까지 돌렸습니다                    4 / 4 완료   │
│ 연결, 브랜드 자료, 게시, 성과 확인까지 한 바퀴가 끝났습니다.│
│ Instagram을 더 연결하면 같은 글이 그 채널로도 나갑니다.     │
│ [Instagram 연결 시작]  [성과 다시 보기]                     │
└─────────────────────────────────────────────────────────────┘
```

### W4.3 단계별 목적지

| 단계 | 누르면 |
|---|---|
| 1 | 연결 화면이 열린다. 대상은 지금 연결 가능한 첫 채널 |
| 2 | 브랜드 자료 편집 단계가 열린다 |
| 3 | 연결된 첫 채널의 Create 탭 |
| 4 | 성과 화면. 이 이동 자체가 4단계의 완료 조건이다 |

이미 끝난 단계를 누르면 그 화면으로 이동만 하고 상태를 되돌리지 않는다.

## W5. 홈 빈 상태 (신설)

연결 0개이고 게시 확인이 없으면 홈의 결과·제안·막힌 일 패널을 그리지 않는다.
가입 직후인 사람에게 게시 18건과 다음 실험 제안을 보여주면 그 화면 전체가 거짓말이 된다.

```
성과
아직 보여드릴 결과가 없습니다. 첫 게시가 확인되면 이 화면이 채워집니다.

[시작 체크리스트 0/4]

┌ 여기에 무엇이 생기나 ───────┐ ┌ 지금 하실 일 하나 ────────┐
│ 지금은 비어 있는 것이 정상   │ │ 채널을 하나 연결하면 초안 │
│ 입니다. 없는 숫자를 만들어   │ │ 만들기부터 게시까지       │
│ 채우지 않습니다.             │ │ 이어집니다.               │
│ [아직 없음] 게시 결과        │ │ [Threads 연결 시작]       │
│ [아직 없음] 측정 가능한 게시 │ │ [브랜드 자료 먼저 쓰기]   │
│ [아직 없음] 다음 제안        │ │ ℹ 순서를 바꿔도 됩니다.   │
│ [아직 없음] 막힌 일          │ └───────────────────────────┘
│ ℹ 게시 4건 이하 채널은 평균을│
│   계산하지 않고 보류로 둡니다│
└──────────────────────────────┘
```

`아직 없음` 네 줄은 무엇이 생길지를 미리 알려준다. 빈 화면에 이유가 없으면 고장으로 읽힌다.

## W6. Settings · 계정 저장 내용 빈 상태 (신설)

v21은 연결이 하나도 없어도 `Threads에 저장된 것`으로 남의 계정을 보여줬다.
연결 0개일 때는 읽기 카드 대신 빈 상태를 둔다.

```
아직 연결한 계정이 없습니다
채널을 하나 연결하면 어떤 계정이 저장됐는지 여기서 읽을 수 있습니다.
저장된 값 자체는 어느 화면에도 보여주지 않습니다.
[Threads 연결 시작]
```

읽어줄 계정도 고정이 아니라 지금 연결된 첫 채널을 따라간다.

## W7. 운영자 · 고객 목록과 상세 (신설)

### W7.1 목록


## W12. 역할 전환 (신설, 2026-08-10 갱신)

v22까지 역할 전환은 검수 바 안의 네이티브 `select` 하나뿐이었고 그 바는 기본 숨김이었다.
평소 화면에서 운영자 콘솔로 들어갈 방법이 없었다. 제품 요소로 승격한다.

### W12.1 배치

| 화면 | 위치 | 형태 |
|---|---|---|
| 고객 셸 | 상단바 우측, 테마 토글 왼쪽 | `보는 사람` 라벨 + 분절 버튼 2개 |
| 운영자 셸 | `OPERATOR CONSOLE` 상단바 우측 | 같은 컴포넌트, 어두운 배경 변형 |

### W12.2 요소

- 라벨 `보는 사람` (11px, subtle). 무엇을 바꾸는 조작인지 버튼만으로는 모호해서 붙인다.
- 버튼 2개: `고객` / `운영자`. 알약 안 알약. 선택된 쪽만 accent 배경 + 흰 글자.
- 상태는 `aria-pressed`로 전달한다. `disabled`나 색만으로 전달하지 않는다.
- 최소 높이 44px. 최소 너비 56px.
- 네이티브 `select` 금지. 마우스·자동화 양쪽에서 열리지 않는 사고가 여기서 났다.

### W12.3 인터랙션

| 조작 | 결과 |
|---|---|
| 현재 역할 버튼 클릭 | 아무 일도 없음 (재렌더 없음) |
| 다른 역할 버튼 클릭 | 셸 교체 + 상대 역할의 열린 오버레이 8종 전부 닫힘 + 스크롤 최상단 |
| 키보드 Tab | focus-visible 링 3px |

닫는 오버레이 8종: 캠페인 단계, 채널 문구 비교, 영향 범위, 예약, 상세, 가입 직후 4단계, 채널 연결, 운영자 비밀값.
역할이 바뀌었는데 이전 역할의 모달이 위에 남으면 화면 전체가 거짓이 된다.

### W12.4 상태

| 상태 | 모습 |
|---|---|
| 고객 선택 | `고객` accent, `운영자` 투명 |
| 운영자 선택 | `운영자` accent, `고객` 투명 |
| 다크 | accent가 밝아짐. 전경은 흰색 유지 (아래 미결 참고) |

**미결:** 다크에서 accent(`#60a5fa`) 위 흰 글자는 2.46:1로 AA 미달이다.
이 컴포넌트만의 문제가 아니라 `button.primary` 전량이 같아서 토큰 결정으로 이월했다. DESIGN.md v22.12 참고.

### W12.5 운영자 상단바

`position:sticky; top:0`. 운영자 화면은 표가 길어 아래로 내려가면 되돌아올 문이 화면 밖으로 나간다.

## W13. 연결 시작 화면 갱신 (W1.2 수정)

경쟁 3사 조사 결과를 반영해 블록 1개를 추가했다. 순서는 아래와 같다.

1. 무엇을 연결하는지 한 문장
2. 권한 목록 (`scope-list`, 체크 마크)
3. 필요한 계정 종류 (해당 채널만)
4. **[신설] 승인 화면을 열기 전에 두 가지만 확인해 주세요** (warning 톤 1블록, 안에 2줄)
   - 지금 {제공자}에 로그인된 계정으로 연결됩니다. 다른 계정을 쓰려면 먼저 {제공자}에서 계정을 바꿔 주세요.
   - 요청한 권한은 하나도 끄지 말아 주세요. 하나라도 끄면 연결은 되지만 게시할 때 실패합니다.
5. 콜백 안내
6. 동작: `{제공자} 승인 화면 열기` / `나중에 하기`

**규칙:** 이 블록은 상자 2개가 아니라 1개 안의 2줄이다.
상자를 4개 쌓으면 벽이 되어 아무도 읽지 않는다. 값을 직접 받는 채널에는 붙이지 않는다.

## W14. 운영자 고객 상세 갱신 (W7.2 수정)

한 화면에 `일시 정지`가 두 개 있고 어느 고객이 멈추는지 알 수 없던 문제를 고쳤다.

### W14.1 조치는 한 곳

상세 패널 안에만 둔다. 아래 작업 공간 패널에서는 조치 버튼을 뺐다.

조치 위: `아래 조치는 모두 {고객명}에게만 적용됩니다` (source-label 톤)

| 버튼 | 조건 | 라벨 |
|---|---|---|
| 안내 보내기 | 이슈 있을 때만 | `고객에게 안내 보내기` (primary) |
| 정지·재개 | 항상 | `{고객명} 일시 정지` / `{고객명} 다시 시작` |
| 공유 AI | 항상 | `공유 AI 승인` / `공유 AI 승인 회수` |
| 지원 모드 | 항상 | `15분 지원 모드` (quiet) |
| 닫기 | 항상 | `닫기` |

조치 아래에 현재 상태 한 줄을 둔다.
`현재 상태 · 일시 정지됨. 예약과 자동화가 멈춰 있습니다. · 공유 AI 허용`
누른 뒤 무엇이 달라졌는지 같은 자리에서 읽히게 한다.

### W14.2 작업 공간 패널의 범위

| 선택한 고객 | 아래 패널 |
|---|---|
| 모노스튜디오 | `모노스튜디오 작업 공간 · 읽기 전용` + `이 고객에 대해 지금 알 수 있는 것` |
| 그 외 3명 | "선택한 고객의 상세 카드는 아직 이 프로토타입에 옮기지 않았습니다. 모노스튜디오만 실제 값을 가지고 있어 다른 고객의 숫자를 만들어 채우지 않았습니다." |

옮겨온 값은 그 대상에서만 편다. 숫자를 돌려쓰면 화면이 거짓말을 한다.

## W15. 연결 실패 화면 갱신 (W1.5 수정) · 5종에서 6종

`테스터 초대를 아직 수락하지 않음`을 `앱 권한 부족`에서 분리했다.
근거는 `dashboard/src/lib/oauth-errors.ts`가 두 분기를 따로 잡는다는 것이고,
분리 이유는 고치는 사람이 다르다는 것이다.

- 문구: "초대가 아직 수락되지 않았습니다. 운영자가 보낸 테스터 초대를 먼저 수락해야 연결됩니다."
- 다음 행동: "제공자에서 온 초대 메일 또는 알림에서 수락한 뒤 다시 시도해 주세요. 이건 운영자가 대신 눌러줄 수 없습니다."
- 주 버튼: `다시 시도` (운영자 알림 아님)
- 톤: warning

6종 모두 하단 고정 문장은 유지한다.
`만들던 초안과 예약은 그대로 있습니다. 연결 실패로 잃은 것은 없습니다.`
