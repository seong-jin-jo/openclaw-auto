## 계산형 확인

- 1024 정상: prototype 가로 넘침 0, 세로 넘침 0, content 가로 넘침 0, display stage 세로 넘침 0.
- 1024 펼침: 패널 top 443, bottom 987. workarea top 427, bottom 1242. 패널 전체가 workarea 안에 있음.
- 금지 문구 가시성: `크게 보기`, `담당에게 이걸로 말하기`, `내 에이전시`, `되짚어 보기` 0건.

- DESIGN.md는 착수 시 314줄에서 v43 반영 뒤 320줄로 증가. 기존 절을 축약하지 않음.

## 레드팀과 셀프심문

**까다로운 고객 공격:** 원형 단추가 결과 카드 위에 겹치면 카드 내용을 가릴 수 있다. 수정으로 단추를 56px로 제한하고 기본 결과의 텍스트 영역과 겹치지 않는 오른쪽 구석에 고정했다. 펼침 패널은 카드 열수를 흔들지 않으며 접기 행동이 머리에 고정된다.

**이 결론이 틀렸다면 가장 그럴듯한 이유:** 넓은 화면과 좁은 화면에서 호출 위치가 달라 학습 비용이 생길 수 있다. 양쪽 모두 오른쪽 구석이라는 공간 규칙은 유지하고, 모바일에서는 엄지 접근을 위해 아래, 데스크톱에서는 결과를 가리지 않기 위해 위를 썼다.
