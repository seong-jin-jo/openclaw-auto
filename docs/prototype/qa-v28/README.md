## 2. 리테이크 5건 (전부 실측으로 잡아 고친 뒤 재측정)

1. **선택 카드 안 문장이 칸 밖으로 113px 밀림.** 앞판의 "라벨은 줄바꿈하지 않는다" 규칙이 `button` 전체에 걸려 있었고, 선택 카드는 라벨이 아니라 설명을 품는 카드라 그 규칙에 걸렸다. 카드에만 예외를 줬다.
2. **설정 탭 마지막 항목이 1024에서 41px 잘림.** 옆으로 밀어서 찾게 두지 않고 두 줄로 접었다.
3. **화면 안 `small`이 12.5px.** 브라우저 기본값이 먹어 글자 크기 7단 밖의 값이 생겼다. 캡션 12px로 되돌렸다. 신규 토큰 0.
4. **1단계에서 정작 매체 고르기 카드가 첫 화면에 안 보임.** 화면 이름이 "매체 종류 고르기"인데 그 결정이 네 번째 블록이라 접힘선 아래 있었다. 결정을 맨 위로 올렸다(처음 오신 분 화면만 학습 안내가 먼저).

덤으로 1600 폭에서 프레임 옆 근거 패널이 아래로 떨어지던 것도 잡았다(여백 한 단 축소). 매거진 형식의 요지가 "프레임 옆에 근거"라 그 줄바꿈은 형식 파괴였다.

5. **역할 전환 라벨만 명암비 4.40 대 1로 AA 미달.** 색 토큰을 새로 만들지 않고 한 단 진한 기존 토큰으로 옮겨 7.73 대 1이 됐다. 재측정에서 미달 0.

### 흐름 색인 범위에 대한 고지 (화면 삭제 아님)

좌측 흐름 색인 35항목은 **이번에 바뀐 여섯 가지를 따라가는 순서**로 다시 짰다. 앞판 색인에 있던 자산·키워드·블로그·운영자 세부 화면 일부는 색인에서 빠졌지만, **그 화면과 라우트는 프로토타입 안에 그대로 살아 있고 프레임 안 사이드바로 들어가면 전부 열린다.** 지운 화면은 0건이다. 색인은 목차이지 화면 목록이 아니다.

### 4.2 이번에 새로 만든 것 (전부 기존 부품 조합, 새 시각 언어 0)

| 새로 만든 것 | 무엇으로 만들었나 | 왜 필요했나 |
|---|---|---|
| 매체 종류 고르기 | 기존 `source-choice` + `choice` 카드 | 회장 직접 지시로 매체가 첫 결정이 됐다. 앞판에는 이 화면 자체가 없었다 |
| 발행 플랫폼 고르기(매체로 걸러진 목록) | 기존 `list-row` + 상태 배지 | 앞판은 표 하나에 8개를 전부 깔았다. 매체를 먼저 고르므로 못 올라가는 곳을 지웠다 |
| 판단 세 갈래 | 기존 `choice` 카드 | 회장 요청 원문의 "바로 올릴지·다른 안 볼지·품질 높일지"가 화면으로 존재하지 않았다 |
| 학습 동의 카드 | 기존 `notice` + 눌림 상태 버튼 | 후보를 고른 그 자리에서 동의를 받아야 한다 |
| 학습 정보 입력 경로 4가지 | 기존 `choice` + `rewrite-step` 블록 | 코드에 0건, 앞판에도 0건이었다 |
| 발행 후 세 갈래 | 기존 `choice` 카드 | 발행이 끝난 뒤 화면이 끊겨 있었다 |
| 로그인 전용 화면 | 기존 `panel` + `list-row`, 폭만 520px로 | 앞판은 로그인을 14단계 덮개 창 안에 넣어 두었다. 회장이 지적한 "이상한 모달"의 정체 |
| 채널 뺀 기능 안내 | 기존 `list-row` | 헤더를 통일하며 없앤 탭을 숨기지 않기 위해 |

CSS 신규 규칙은 예외 3건뿐이다(선택 카드 줄바꿈, 설정 탭 줄바꿈, `small` 캡션 고정). 색·서체·크기 단·간격·형태 신규 0.

## 5. 현행 사이드바 항목 수 (부수 과제)

**정적 판정 23항목. 다만 브라우저에서 고객 사이드바를 실제로 렌더해 세는 것은 실패했다.**

- 로컬 대시보드는 떴다(`npm run dev`, Next 16.2.2, `http://localhost:3000`, Ready 1.5초).
- 그런데 `.env.local`의 `DASHBOARD_AUTH_TOKEN`으로 들어가면 신원이 **운영자**로 풀려 `OperatorSidebar`가 그려진다. 실측값은 `aside` 1개 · 링크 **1개**("고객 관리")였다.
- 고객 사이드바(`CustomerSidebar`)를 그리려면 Supabase 테넌트 계정 로그인이 필요하고 그 자격은 이 세션에 없다. 그래서 **고객 23항목은 눈으로 세지 못했다.**
- 대신 코드에서 결정적으로 확인했다. `Sidebar.tsx`의 `CustomerSidebar`가 그리는 `<Link>`는 전부 무조건 렌더이고 조건부가 하나도 없다. 직접 작성 13개(Overview 4 · Data 1 · Keyword 3 · Custom 1 · Assets 3 · System 1)에, `channel-capabilities.ts`의 `CHANNEL_GROUPS`가 5+3+2 = 10개를 더한다. 합계 **23**.

즉 23은 코드 판정으로 확정이고, 실렌더 확인만 인증 때문에 미완이다.
