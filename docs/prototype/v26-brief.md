# v26 브리프 — 유저 흐름별 매거진 형식으로 재구성

> STAMP | v26-brief | 2026-08-16 | opus-5 | 회장이 잘한 예시로 지목한 `romeo-vnext-magazine-v13-opus.html` 형식을 표준으로 채택
> 규율: 화면 콘텐츠는 v25에서 이어받고, **바깥 컨테이너 형식을 매거진 형식으로 교체**한다. 새 IA 창작 금지.

## 왜 v25가 반려됐나

회장 지적: 스탬프 없음, 타입별 반응형 없음, 플로우 없음, 벤치마크와 심리 법칙 안 보임.
원인: v25 브리프(컨트롤러 작성) 완료 기준에 이 요건들이 없었다. 에이전트는 "브리프에 없어 만들지 않았다"고 사전 고지했다.

## 표준 형식 (회장 지목 예시에서 추출)

기준 예시: `http://localhost:8911/romeo-vnext-magazine-v13-opus.html` (268KB, 46화면). 아래 5개 영역을 그대로 갖춘다.

### 1. 최상단 헤더
- 제목 + 버전 (예: `OSMU Marketing Hub · 매거진 HiFi v26`)
- **STAMP 한 줄**: 버전, 날짜, 회장 지적 반영 사항을 가운뎃점으로 나열. 접지 말고 항상 보이게.

### 2. 상단 컨트롤 바 (세 축 토글)
- **뷰포트**: 390 / 768 / 1024 / 1440. 누르면 가운데 프레임 크기가 실제로 바뀐다. 이것이 "타입별 반응형"이다.
- **유저 타입**: 비로그인 / 신규 가입자 / 활성 고객 / 운영자. 누르면 같은 화면이 그 사용자 기준으로 바뀐다.
- **데이터 상태**: 정상 / empty / loading / error / overflow.

### 3. 좌측 흐름 색인 (핵심)
화면을 **사용자 흐름 단계별로 묶어** 번호를 매겨 나열한다. 각 항목에 번호, 이름, 괄호로 상태 표기(예: `히스토리 (3열·empty)`).

OSMU의 흐름 그룹 제안(실제 라우트와 v25 화면에 맞춰 조정):
1. 진입: 랜딩, 로그인, 가입, 첫 로그인
2. 온보딩과 취향 수집: 브랜드 자료 연결, 초기 취향 질문, 채널 연결
3. 제작 시작: 추천 받기(성과·이전 선택·트렌드 근거), 타깃 시장과 출력 언어 선택, 질문 3개
4. 후보와 선택: 저해상도 후보 3개, 선택, 고해상도 생성 대기, 완성
5. 편집: 자막·컷 조정(추가 크레딧 없음), 나레이션·소재 교체(과금)
6. 출력 플랫폼 결정: 하나의 작업에서 어느 플랫폼으로 낼지 고르기
7. 승인과 발행: 승인 후 발행 기본, 자율 발행 옵션, 예약, 발행 결과
8. 성과와 학습: 성과 화면, 학습된 취향 열람과 수정
9. 자산: 이미지, 영상, 블로그
10. 설정: 채널, 크레딧 충전, 알림, 계정
11. 운영자: 잔액, 실패, 큐, 토큰 만료, 고객 막힘, 환불 근거

### 4. 가운데 화면 프레임
선택한 화면 하나를 기기 프레임 안에 실제 렌더. 데이터가 채워진 상태.

### 5. 우측 설명 패널 (화면마다)
- 화면 번호와 이름 (예: `제작 시작 · 12 / 40`)
- **실구현 경로**: 이 화면에 대응하는 실제 파일 (예: `dashboard/src/app/studio/page.tsx`)
- 현재 뷰포트, 유저 타입, 데이터 상태
- 설명 문단: 이 화면에서 무엇을 하고 왜 이렇게 배치했는지
- **심리 근거 줄**: 적용한 법칙과 발현 방식 (예: `Hick 법칙 = 선택지 3개로 제한 · 손실회피 = 미선택 후보 추가 과금 문구`)
- **벤치마크 줄**: 실제 참조한 제품과 URL 요지 (예: `Runway Gen-4 초안·마스터 2단 · Adobe Firefly Boards 변형 격자`)
- 이전 / 다음 버튼, 키보드 단축키 안내

## 화면 콘텐츠 (v25에서 이어받고 신규 결정 반영)

v25가 만든 신규 4개 블록의 내용을 버리지 말고 이 형식 안으로 옮긴다. 추가로 회장이 2026-08-16에 확정한 3건을 화면으로 반영한다.

| 신규 결정 | 화면 요건 |
|---|---|
| D6 학습된 취향 상시 열람·수정 | 취향 상태 화면. 사람이 읽는 문장으로 항목 나열, 각 항목의 근거(어느 선택에서 나왔는지), 항목별 수정과 삭제. 언어별 분리 |
| D7 작업 시작 지점 추천 | 제작 시작 화면에 추천 카드. 근거는 지난 성과, 이전 후보 선택, 현재 트렌드 세 가지. 빈도는 미결정이므로 화면에는 "가끔 제안" 수준으로 |
| D8 작업 하나, 플랫폼은 출구 | 제작 입구에서 플랫폼을 고르지 않는다. 만들고 나서 출력 플랫폼을 고르는 화면이 별도 단계로 존재 |
