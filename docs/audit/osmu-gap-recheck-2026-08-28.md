# 갭 감사 재확인 2026-08-28

한 줄 결론: 8월 초 갭 감사에서 "없음"으로 적힌 열한 줄 중 여섯 줄은 그 사이에 구현되어 지금은 실제로 동작한다. 내가 도는 앱에 직접 요청을 보내 확인했다. 남은 다섯 줄은 전부 댓글 계열이고, 새 테이블 없이는 못 만든다.

이 문서는 `docs/audit/osmu-v62-api-gap-audit-v1-gpt-codex.md` 를 대체하지 않는다. 그 문서는 그대로 두고, 그 뒤에 무엇이 바뀌었는지만 여기 적는다.

## 확인 방법

앱이 `localhost:3456` 에서 실제로 돌고 데이터베이스가 붙은 상태에서, 각 동작에 해당하는 요청을 직접 보내 상태 코드와 응답 본문을 읽었다. 워커가 통과했다고 적어 놓은 문장은 근거로 쓰지 않았다.

## 이제 되는 것

| 옛 감사의 판정 | 지금 | 내가 관찰한 것 |
|---|---|---|
| 성과 0건에서 방향 3개 제안: 없음 | 됨 | 가설 3건과 함께 표본 0건, 문턱 5건을 숨기지 않고 답한다 |
| 장면 순서 변경: 없음 | 됨 | 두 장면이 실제로 자리를 바꾼다 |
| 문장 삭제와 복원: 없음 | 됨 | 지우면 보임 값이 거짓, 되살리면 참으로 돌아온다 |
| 낡은 판으로 고치기 | 됨 | 거절한다. 두 사람이 같이 고쳐도 덮어쓰지 않는다 |
| 이 결로 한 편 더 만들기: 없음 | 됨 | 제안이 큐로 넘어가고 출처가 함께 저장된다 |
| 첫 댓글 발행: 없음 | 됨 | 발행 경로에 첫 댓글 처리와 상태 미확인 표시가 있다 |

출처 보존은 특히 확인할 값이 있었다. 큐에 들어간 글에 제안 번호, 근거 갈래, 표시 이름, 검증 여부, 그리고 어떤 신호에서 나왔는지가 함께 남는다. 표시 이름이 "가설, 우리 검증 기록 아님" 으로 붙는 점이 좋다. 검증된 성과인 척하지 않는다.

같은 제안을 두 번 넣으면 새 글을 만들지 않고 이미 만든 것을 돌려준다.

## 아직 못 하는 것

전부 댓글 계열이고 원인이 하나다. 댓글을 담을 곳이 없다.

- 댓글과 반응의 본문 목록
- 댓글 답글 초안 만들기
- 답글 보내기
- 댓글 좋아요와 나중 처리
- 댓글에서 편집실로 넘기기

지금 있는 것은 `GET /api/metrics` 의 답글 개수뿐이다. 개수는 있고 내용이 없다.

이 다섯은 저장 구조를 정하기 전에는 손댈 수 없다. 선택지는 `docs/audit/osmu-v62-db-options-v1-gpt-codex.md` 에 정리되어 있다.

## 이 문서를 쓰는 이유

옛 감사는 지금 읽으면 실제보다 훨씬 비어 보인다. 그 문서만 보고 일을 시키면 이미 있는 것을 다시 만들게 된다. 앞으로 갭 감사를 근거로 발주할 때는 이 재확인을 함께 읽어야 한다.
