# 네 방 릴리스 후보 0.2.0

이 문서는 회장이 병합 뒤 직접 눌러 보고 개선할 범위와, 아직 운영에서 약속할 수 없는 범위를 한 장에 정리한다. 현재 상태는 병합 요청 전 릴리스 후보다. 운영 배포는 하지 않았다.

## 이번에 새로 되는 것

### 네 방 흐름

- 생성실에서 주제를 적고 후보를 확인하는 화면이 열린다.
- 편집실에서 작업물의 목차, 미리보기, 대사와 편집 도구를 한 흐름으로 볼 수 있다.
- 발행실에서 채널별 미리보기와 발행 상태를 확인할 수 있다.
- 성과실에서 채널 성과와 다음 행동 제안을 확인하고 생성 큐로 넘길 수 있다.
- 좁은 화면에서도 네 방을 오갈 수 있고, 빈 화면에는 다음 행동이 표시된다.

### 운영 안전

- 개발용 Studio 신원 우회는 운영에서 어떤 예외값을 넣어도 열리지 않는다.
- 설정이 없을 때 주요 API는 서버 오류 500 대신 준비되지 않음 503으로 응답한다.
- 댓글 답글과 좋아요, 발행, 무료 재생성, 숏폼 공장의 중복 실행과 작업 공간 격리를 보강했다.
- 운영 사건 원장과 선택적 외부 알림을 추가했다.
- 신규 데이터 구조는 기존 운영 스키마에서 이름순으로 적용되고, 최신 스키마에 다시 적용해도 깨지지 않는다.

## 배포 후 회장이 확인할 주소와 클릭 경로

기준 주소는 운영 설정 `OSMU_PUBLIC_URL`의 값이다. 아래 경로를 그 주소 뒤에 그대로 붙인다.

| 확인할 것 | 정확한 주소 | 클릭 경로 | 정상 관찰 |
|---|---|---|---|
| 성과실 | `${OSMU_PUBLIC_URL}/` | 로그인 후 첫 화면 | 성과 요약과 다음 행동 제안이 보인다 |
| 생성실 | `${OSMU_PUBLIC_URL}/studio?room=create` | 왼쪽 메뉴 `생성실` | 주제 입력과 후보 영역이 보인다 |
| 편집실 | `${OSMU_PUBLIC_URL}/studio?room=edit` | 왼쪽 메뉴 `편집실` | 목차, 미리보기, 대사, 도구가 보인다 |
| 발행실 | `${OSMU_PUBLIC_URL}/studio?room=publish` | 왼쪽 메뉴 `발행실` | 채널별 미리보기와 상태가 보인다 |
| 운영자 고객 화면 | `${OSMU_PUBLIC_URL}/operator/customers` | 운영자 로그인 후 `고객 관리` | 고객 목록과 외부 연결 설정이 보인다 |
| 상태 확인 | `${OSMU_PUBLIC_URL}/api/health` | 주소 직접 열기 | 필수 운영 설정과 DB가 준비되면 200을 돌려준다 |

390px 안팎의 휴대전화 폭에서는 메뉴 단추를 열고 네 방을 각각 한 번씩 눌러 본다. 1024px 이상에서는 왼쪽 메뉴와 본문이 겹치지 않는지 확인한다.

## 아직 안 되는 것과 이유

1. 운영 Studio 생성 API는 아직 사용할 수 없다. 현재 구현된 신원 어댑터는 개발 전용이며 운영 어댑터가 승인된 API 계약으로 연결되지 않았다. 운영에서 개발 신원을 켜는 우회는 안전상 완전히 막았다.
2. 첫 생성은 내부 스킬 버전 식별자가 화면에 공급되지 않으면 중단된다. 개발 검증은 값을 주입해 통과했지만 운영 사용자 동선에는 정식 공급 경로가 없다.
3. 편집실의 일부 변경은 브라우저 저장소 수준이고, 장면 재정렬과 영속 저장의 전체 동선은 승인되지 않았다.
4. 실제 외부 채널의 응답 불명 시간 초과, 실제 좋아요와 실제 운영 발행은 계정과 운영 배포가 없어 미검증이다.
5. `pipeline-state.osmu.md`에서 design과 qa가 승인되지 않았다. 최신 디자인 정합 행렬도 전체 v63 정합을 NG로 판정했다. 따라서 이 문서는 기능 확인용 릴리스 후보이지 배포 승인서가 아니다.

## 되돌리는 방법

1. 배포 전에는 병합 요청을 닫으면 된다. 현재 운영에는 아무 변화가 없다.
2. 배포 뒤 문제가 생기면 GitHub Actions의 수동 배포 화면에서 병합 전 안정 커밋 `a7b2b435e7ea13a191ecca55a6c8166d59ff5c42`을 선택하고 `openclaw-dashboard-osmu` 서비스만 다시 기동한다.
3. 앱 이미지는 이전 안정 이미지로 되돌리되, 신규 테이블은 삭제하지 않는다. 이번 DB 변경은 추가형이라 이전 앱이 사용하지 않는 테이블과 인덱스를 남겨도 된다.
4. 새 기동 자체가 실패하면 배포 워크플로가 직전 컨테이너 이름을 복원하도록 구성돼 있다. 실제 복원 뒤 `/api/health` 200과 네 방 첫 화면을 다시 확인한다.
