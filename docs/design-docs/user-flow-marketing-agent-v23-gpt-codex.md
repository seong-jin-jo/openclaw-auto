# OpenClaw Marketing Agent 유저플로우 v23

기반 산출물: `docs/user-flow-marketing-agent-v22-gpt-codex.md` (v22 경로 전량 승계),
실제 코드 `dashboard/src/app/studio/page.tsx`, `dashboard/src/components/studio/PlatformPreview.tsx`,
정책 `docs/platform-policy-matrix-v1-gpt-codex.md`.
프로토타입: `docs/prototype/openclaw-auto-marketing-agent-fidelity-v23-gpt-codex.html`

v23은 v22 경로를 지우지 않는다. v22에서 부모가 직접 클릭해 확인한 5개 경로(온보딩 1단계에서
채널 연결 목록으로 이동 / 연결 3단계 모달과 완료 카드 / 미연결 채널에서 게시 4동작 예고와 초안 저장 활성 /
역할 전환 버튼 2개 / 운영자 상세의 이름 붙은 조치 버튼)는 그대로 유지된다.
이 문서는 그 위에 **미리보기 경로**를 되살려 적는다.

## 1. v22에서 끊겨 있던 경로: 미리보기

### 무엇이 끊겨 있었나

v22 프로토타입의 OSMU Studio에는 미리보기가 두 가지 형태로만 있었다.

1. 텍스트 묶음 아래 `Threads 미리보기` + `Threads 게시 전 확인` 버튼을 5개 플랫폼으로 곱한 버튼 10개
2. 그 버튼을 누르면 열리는 모달 한 장. 내용은 문구를 평문으로 다시 적은 것뿐이었다

실제 코드에는 `PlatformPreview` 7개 플랫폼 프레임이 있다. 프로토타입에는 그 프레임이 0개였다.
결과적으로 "이 글이 Threads에서 어떻게 보이는가"라는 질문에 답하는 화면이 제품에 없는 것처럼 그려졌다.
게다가 버튼 10개는 좁은 폭에서 라벨이 잘려 `Threads 미라`, `X 미리보7`처럼 뜻을 잃었다.

### v23 경로

```
/studio 진입
  └─ 묶음 1 텍스트 (실제 코드 GROUPS[0] = threads, x, facebook)
       ├─ 공통 초안 / 채널별 문구 편집  (v22 유지)
       └─ [실제 화면에 보일 모습]                       ← v23 복원
            ├─ 플랫폼 탭 3개: Threads · X · Facebook   (브랜드 로고 + 라벨, 잘림 없음)
            ├─ 글자수 카운터: 53/500 · 0/280 · 0/63206 (한도 = channel-text-limits.ts)
            ├─ 프레임: 선택한 플랫폼의 실제 게시물 골격
            │    Threads → 아바타, 핸들, 1시간, 본문, 반응 4개, "답글 18개 · 좋아요 124개"
            │    X       → 확인 배지, @핸들 · 1분, 본문, 지표 5개
            │    Facebook→ 흰 카드, 방금 · 전체 공개, 반응 바, 좋아요·댓글·공유 3열
            └─ [Threads 게시 전 확인] → 기존 게시 전 확인 모달 (v22 경로 그대로 재사용)
  └─ 묶음 2 사진·카드뉴스 (GROUPS[2] = instagram)
       └─ [실제 화면에 보일 모습]
            ├─ 탭 1개: Instagram
            ├─ 캐러셀 5장: 1/5 표시, 좌우 이동, 점 표시, 카드 문구
            ├─ 좋아요 1,284개 / 캡션 / 해시태그 3개
            └─ [Instagram 게시 전 확인]
  └─ 묶음 3 짧은 영상 (GROUPS[1] = shorts, reels, tiktok)
       └─ [실제 화면에 보일 모습]
            ├─ 탭 3개: Shorts · Reels · TikTok
            ├─ 9:16 프레임 + 플랫폼 크롬 + 오른쪽 반응 레일(12.4K / 318 / 공유·저장)
            ├─ @monostudio + 캡션 2줄 자름
            └─ 각주: 반응 수와 시간은 예시 값. 발행 뒤 실제 값으로 바뀜
```

### 상태별 경로 (해피패스만이 아니다)

| 상태 | 어디서 생기나 | 화면이 하는 말 | 다음 행동 |
|---|---|---|---|
| 정상 | 문구가 한도 안 | 카운터가 회색 `53/500` | 게시 전 확인 |
| 한도 초과 | 문구가 한도 초과 | 카운터가 붉은 굵은 글씨로 전환 (`.pv-count.over`) | 문구를 줄이거나 채널별 문구로 분리 |
| 한도 없음 | 영상 3종 선택 | "영상은 본문 글자 한도가 없습니다" | 대본 저장 |
| 카드 없음 | 카드뉴스 0장 | 스테이지가 "카드 생성 대기" (실제 코드 IgCarousel 동일 문구) | 카드뉴스 열기 |
| 미리보기 값이 예시 | 항상 | 프레임 하단 각주가 예시임을 밝힘 | 없음. 오해를 막는 것이 목적 |
| 발행 미지원 | shorts·reels·tiktok | 실제 코드는 "발행 미지원(생성 전용)" 라벨. 프로토타입은 전달 표에서 같은 뜻을 유지 | 영상 작업 열기 |
| 계정 권한 확인 필요 | TikTok | 묶음 3의 경고 1줄 유지 (v22) | 계정 다시 연결 |

### 막다른 길 점검

이 경로에서 나갈 문이 없는 화면은 없다.
- 미리보기에서 문구가 틀렸다 → 같은 패널 위쪽 편집 영역(데스크톱에서는 왼쪽 열)으로 바로 돌아간다.
- 미리보기에서 게시로 가고 싶다 → `게시 전 확인` 한 개 버튼. v22의 버튼 10개가 이 1개로 줄었다.
- 카드가 비었다 → `카드뉴스 열기`.
- 영상이 비었다 → `영상 작업 열기`.

## 2. 데스크톱과 모바일이 다른 배치인 이유

실제 코드 `app/studio/page.tsx:478`은 `flex gap-6`으로 본문(미리보기 카드 행)과 오른쪽 발행 이력을
나란히 둔다. 편집은 별도 드로어에서 편집 필드와 큰 미리보기를 위아래로 붙여 보여준다(`page.tsx:573`).
즉 이 제품의 원래 배치는 "정하는 곳"과 "결과를 보는 곳"이 같은 화면에 함께 있는 것이다.

- 데스크톱 1024 이상: 묶음마다 왼쪽은 정하는 곳(문구·카드·대본), 오른쪽 372px는 결과를 보는 곳.
  오른쪽 열은 스크롤을 따라온다(`position:sticky`). 폭만 늘린 모바일이 아니다.
- 모바일 390: 정하는 곳 아래에 결과가 온다. 프레임은 폭 전체를 쓴다(`--pv-w:100%`).
  탭은 가로로 밀어 본다. 라벨은 줄어들지 않는다.

## 3. v22에서 승계한 경로 (변경 없음)

아래는 이번에 손대지 않았다. 부모가 v22에서 직접 클릭해 확인한 항목이다.

1. 홈 시작 체크리스트 1단계 → 채널 연결 목록으로 이동, 그 자리에서 연결이 시작된다.
2. 연결 3단계 모달(안내 → 입력·검증 → 완료 카드).
3. 미연결 채널 화면: 게시 관련 4동작은 예고 상태로 두고 초안 저장은 활성.
4. 상단 역할 전환 버튼 2개(고객·운영자), 양쪽 화면 같은 자리.
5. 운영자 상세의 조치 버튼에 대상 이름이 붙는다(`바른치과 일시 정지`).

전체 26개 목적지와 14단계 여정 표기도 그대로다. 이번 판에서 목적지 수는 26개로 확인했다(실측).

## 4. 이번 판에서 정직하게 남긴 것

- 미리보기 안의 반응 수(12.4K, 318, 1,284, 124)와 시간(1시간, 1분, 방금)은 실제 코드에 하드코딩된
  예시 값이다. 프레임 하단에 각주로 밝혔다. 실제 수치로 바꾸지 않았다.
- Instagram은 캡션 2,200자 중 피드에서 앞부분만 보이고 나머지가 접힌다는 것이 Hootsuite 문서에
  나오지만, 정확한 자름 지점은 앱 버전·기기 폭·이미지 유무에 따라 달라진다고 같은 문서가 밝힌다.
  그래서 프로토타입에 자름 지점 숫자를 그리지 않았다. 추후 확정 시 반영 대상이다.
- `docs/platform-policy-matrix-v1-gpt-codex.md`의 `[미확인]` 수치는 이번에도 확정 사실로 그리지 않았다.
