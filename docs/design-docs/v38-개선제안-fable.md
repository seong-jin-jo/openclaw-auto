# v38 개선 제안 (흐름 · UX 라이팅 · 디자인)

**한 줄 결론: 뼈대(4방·헤더 단계·되돌리기)는 회장 확정대로 섰다. 남은 문제는 세 가지다. ①옛 흐름 화면과 새 방 화면이 한 프로토타입에 두 문법으로 공존하고, ②화면 안 영문 명칭과 용어가 통일되지 않았고, ③A-에서 A로 못 가는 원인은 장식이 아니라 표 잘림·제목 과부하·상태 뱃지 문법이다.**

이 문서는 제안만 한다. 프로토타입은 고치지 않았고, 대장 R01~R23은 전부 유지가 전제다.

## 1. 흐름 제안 (생성 → 편집 → 발행 → 성과)

하루 3건을 만드는 사용자(PRD 페르소나 박도윤)로 전 흐름을 걸었다. 단계 안은 잘 돌아간다. 막히는 곳은 전부 **단계 사이의 이음새**다.

### 1-1. 생성 진입: 두 문법 공존 (당장 고칠 것 #1의 상세)

- 현상: 방 화면(Studio 생성)은 "오늘의 제안 카드 + 직접 쓰기"로 시작하는데, 별도 화면군(screen-make-*)은 "OSMU Studio, 4단계 스테퍼(오늘의 제안·결과 후보·판단·결과 확정)"로 돈다. 결과 후보·판단·학습 동의 화면은 이쪽에만 있다.
- 제안: 4단계 스테퍼 화면군을 **Studio 생성 방의 내부 진행 상태**로 흡수한다. 방 제목은 항상 "Studio 생성", 스테퍼는 방 안 2층으로. 헤더 단계바(방 사이)와 방 안 스테퍼(방 내부 단계)의 2층 구조를 명시하면 R01(한 화면 하나)과 R14(헤더 단계)가 충돌 없이 선다.
- 얻: 이름 하나, 지도 하나 / 잃: 화면 수는 그대로, 제목·빵부스러기만 정리.

### 1-2. 다음 단계로 넘어가는 순간: CTA 위치가 세 가지

- 현상: 생성→편집은 하단 "다음 단계" 버튼, 편집→발행은 우상단 "발행실로 보내기 전에 미리보기"(버튼인지 안내인지 모호), 발행→성과는 발행 완료 화면에서 끝나고 성과실로 가는 손잡이가 없다.
- 제안: **모든 방의 오른쪽 아래 같은 자리에 "다음 방으로" 고정 CTA** 하나. 문구는 "편집실로 보내기", "발행실로 보내기", (발행 완료 후) "성과실에서 반응 보기". Buffer가 queue 어느 화면에서든 다음 행동 버튼을 같은 자리에 두는 패턴을 빌렸다.
- 얻: 반복 사용자의 손이 외운다(Jakob의 법칙) / 잃: 화면별 맞춤 배치의 자유.

### 1-3. 되돌아가는 순간: 도착은 있는데 출발 안내가 약하다

- 현상: 되돌려서 도착 배너(R13 반영)는 좋다. 원본 보존 문구도 정확하다. 그런데 "배너 닫기"를 누르면 그 항목을 다시 찾는 경로가 없다. 또 성과실의 "비슷하게 만들기"로 생성에 도착했을 때는 이 배너가 없어서 비대칭이다.
- 제안: ①배너를 닫아도 방 작업 목록 맨 위에 "되돌려서 옴" 뱃지가 남게 한다. ②성과실→생성(유사 콘텐츠) 진입에도 같은 도착 배너를 쓴다. "들고 온 맥락"(원 글·성과 수치)을 동일 형식으로 보여주면 회장 08-17 원문의 "컨텍스트를 들고 생성으로"가 화면에 선다.
- 얻: 되돌리기와 유사 만들기가 한 문법 / 잃: 없음.

### 1-4. 여러 작업물 동시 진행: 헤더가 일을 안 한다 (당장 고칠 것 #2의 상세)

- 현상: 상단 "작업물 전체 4"와 단계바 뱃지 (1)(1)(1)(1)이 서로 무슨 관계인지 알 수 없다. 발행실 뱃지만 주황인데 이유 미표기.
- 제안: 뱃지 = **그 방에서 내 손을 기다리는 작업물 수**로 정의하고, 0이면 숨긴다. 주황 = 막힘(채널 확인 필요 등)으로 한정하고 눌렀을 때 해당 작업물로 바로 간다. 현재 열어 둔 작업물이 어느 방에 있는지는 단계바 아래 가는 점 하나로 표시한다. Linear가 밀도 높은 상단 표시로 "지금 어디를 봐야 하나"를 픽셀로 답하는 방식을 빌렸다.
- 얻: R16(보관·이어서 작업)이 헤더에서 완성 / 잃: 뱃지 계산 로직 한 줄.

### 1-5. 발행실 하위와 좌측 채널 목록의 관계

- 현상: 발행실 하위 탭(미리보기·승인 인박스·발행 캘린더)은 회장 구상 그대로 좋다. 문제는 사이드바 하단 채널 목록(Instagram 확인 필요 빨강 등)을 누르면 어디로 가는지, 그 채널 연구실과 발행실 미리보기의 관계가 화면에 없다.
- 제안: 역할을 문장으로 박는다. **발행실 = 이번 작업물을 채널별로 내보내는 곳, 채널 연구실 = 그 채널 계정 자체를 관리하는 곳**(R06 세 갈래의 셋째). 발행실 미리보기의 채널 칩에서 "이 채널 설정 열기"로 연구실에 건너가고, 연구실 상단에 "발행실로 돌아가기"를 둔다. Planable이 플랫폼 네이티브 미리보기와 계정 관리를 분리하되 서로 링크로 잇는 구조를 빌렸다.
- 얻: R06·R07과 정합, 빨간 "확인 필요"가 실행 가능해짐 / 잃: 없음.

### 1-6. 발행 직후의 공백 시간

- 현상: "4곳에 올렸습니다" 다음, 반응 수집은 "글 즉시 · 영상 24시간 뒤"다. 그 사이 성과실에 가면 무엇이 보이는지 미정의. design.md §1 상태 완전성 관점의 구멍.
- 제안: 성과실 발행물 행에 "수집 대기 · 내일 18:30부터" 상태를 명시하고, 값 없는 칸은 0이 아니라 "대기"로. (이미 "값이 없는 항목은 0으로 세지 않습니다" 원칙이 있으니 그 원칙을 행 단위까지 내리는 것.)
- 얻: 정직한 톤앵커 유지, 빈 성과 화면 오해 방지 / 잃: 없음.

### 1-7. 학습 동의의 타이밍

- 현상: "이 취향을 기억해둘까요"(3단계 학습 동의)가 판단 단계 안에 카드로 들어 있다. 동의하지 않아도 결과물은 그대로라는 문구는 정확하고 좋다.
- 제안: 유지하되 한 가지만. 동의 카드가 **다음 단계 진행을 가로막지 않게** 시각적으로 옆줄(보조 카드)로 내려라. 지금은 본류 카드와 같은 급이라 R01(한 화면 한 결정)이 순간 둘이 된다.
- 얻: 결정 1개 유지 / 잃: 학습 동의율 소폭 하락 가능(대신 신뢰 상승, 뱅크샐러드식 의도된 마찰).

## 2. UX 라이팅 제안 (전수 훑기, 35건)

기준: 한국어 평문, 코드명·영문 약어 제거, 라벨과 문장 분리, 버튼은 결과를 말한다. 회장 지정 문구("지금 발행하기", "승인 인박스에 보관하기", "캘린더로 예약하기")는 손대지 않고, 오히려 이 셋을 용어의 기준점으로 삼아 나머지를 맞췄다(동사 = 발행, 명소 = 승인 인박스·발행 캘린더).

통일 규칙 먼저 세 줄:
- **동사 통일: 올리다·게시하다 → 발행하다.** 회장 지정 문구가 이미 "발행"이다.
- **용어 통일: 학습신호·취향 프로파일 → "학습 정보" 하나.** 내부 구분(소재/신호)은 학습 정보 화면 안 탭 이름으로만 남긴다.
- **문체 통일: 화면 본문은 합니다체, 담당자 말풍선만 해요체.** 토스처럼 전면 해요체로 가지 않는 이유: 이 제품의 톤앵커가 "담백·정직"이고, 대화 레일(챗봇)과 지면의 목소리를 구분하면 R10(담당자가 안내)이 더 또렷해진다.
