## 1. 한 줄 결론

v9.6은 화면을 충분히 나열했지만 **뼈대가 없었다.** 제작 순서가 회장이 말한 순서와 달랐고, 학습 정보 화면이 아예 없었으며, 재방문 사용자가 같은 질문을 다시 받았고, 발행 이후가 한 갈래뿐이었다. v10.0은 화면을 늘리지 않고 **7개 흐름 갈래로 재배열**한다. 순 화면 수는 v9.6 대비 늘지 않고, 사이드바 항목은 21개에서 9개로 줄인다.

## 3. 설계 원칙 (이 문서의 판정 기준)

1. **작업 단위는 하나, 플랫폼은 출구다.** "인스타용 만들기"가 아니라 "이 주제로 만들기"를 하고 플랫폼을 고른다 (제품구조 §9.8 D8).
2. **한 화면 한 결정.** 질문 화면은 한 번에 하나만 묻는다. 질문은 최대 3개 화면이다.
3. **백지를 주지 않는다.** 모든 질문은 추천안 1개를 첫 카드로 펼치고, 대안 2~4개를 비교 카드로 둔다. 자유 입력은 항상 열되 기본 경로가 아니다 (제품구조 §3.7).
4. **두 번째부터는 다시 묻지 않는다.** 학습 정보가 있으면 질문 3화면이 **확인 카드 1장**으로 접힌다. 바꿀 것만 펼친다.
5. **막다른 골목 0.** 모든 화면에 다음 행동 1개와 나가는 경로 1개가 있다. "돌아가기"만 있는 화면은 결함이다.
6. **모든 채널 화면은 같은 골격을 쓴다.** 채널이 기능을 덜 가진 것은 탭을 없애서 표현하지, 비활성 탭을 남겨 표현하지 않는다.

### 7.1 첫 사용자 전용 규칙

- 추천 카드에 `우리 실험 로그` 라벨을 쓰지 않는다. 이 사용자의 로그가 없으므로 `공개 사례` 또는 `가설`만 허용한다 (PRD §3.7 근거 라벨 3종).

- 대신 **각 화면에 안전 기본값이 이미 선택돼 있다.** 사용자는 확인만 하고 넘어갈 수 있다. 이것이 "건너뛰기"보다 나은 이유는 프로파일에 값이 남기 때문이다.

### 8.2 판단을 돕는 것

2. **셋 중 추천 1개에 배지.** 근거를 붙인다. 예: "저해상도에서도 훅과 자막 가독성이 판단 가능해 보입니다. 이대로 진행을 권합니다."
3. **품질 높이기의 정직한 한계.** "품질을 올려도 구성과 대본은 그대로입니다. 방향을 바꾸려면 다른 안 보기를 쓰세요." 이걸 안 적으면 사용자가 품질 상향에 돈을 쓰고 방향 불만이 그대로 남는다.
4. **L-04 학습 동의 배너** (§7 표).

⛔ 회수 필요 D-11이 여기 걸린다 (§13).

회장 요청을 두 방향으로 나눈다. **사용자가 밀어 넣는 것(§10.1~10.3)**과 **제품이 던지는 것(§10.4)**이다.

| 단계 | 사용자가 보는 것 | 사용자가 하는 것 | 시스템이 하는 것 | 다음 조건 | 빠져나가는 경로 |
|---|---|---|---|---|---|
| L-00 | 항목 목록 | 항목 훑기 | 언어별 필터 | 항목 클릭 또는 입력 버튼 | 어디로든 (사이드바 상시) |

### 10.2 입력 경로 4가지 (회장 명시)

| 경로 | 화면 | 사용자가 하는 것 | 시스템이 하는 것 | 확인 지점 |
|---|---|---|---|---|
| 1. 직접 수정 | L-01 | 문장을 고치거나 새 항목 추가 | 근거를 `직접 입력`으로 기록 | 즉시 |
| 2. 외부 자료 반입 | L-02 | 노션·위키 링크 붙여넣기, 문서 업로드, URL 입력 | 문서를 읽어 **후보 항목을 뽑아 제시**한다. 자동 반영하지 않는다 | "이 자료에서 이런 것들을 봤어요. 어떤 걸 학습할까요?" 체크박스 목록 |

### 10.4 추천 유입 3가지 (회장 명시)

전부 **H-01 홈의 같은 자리**에 카드로 놓인다. 별도 화면을 만들지 않는다 (§9.8 D7 "빈 화면에서 시작하지 않는다").

| 유형 | 카드 문구 예 | 발동 조건 | 누르면 | 무시하면 |
|---|---|---|---|---|
| 가끔 던지는 질문 | "질문 하나만 드릴게요. 결과물에서 가장 중요한 건 조회수인가요, 문의인가요?" | ⛔ D-12 (빈도 미결정) | 답 → 학습 항목 1개 생성 → 홈으로 | 카드 닫힘. 같은 질문 재노출 금지 |
| 성과 기반 | "지난주 B안 형식이 저장 12건으로 가장 좋았어요. 같은 형식으로 하나 더 만들까요?" | 발행물 성과 데이터가 유의미하게 쌓였을 때 | Q-00에 그 형식이 미리 채워진 채 진입 | 카드 닫힘 |
| 트렌드 기반 | "이번 주 교육 분야에서 이런 형식이 늘었어요 (출처·관찰일). 이런 류로 만들어볼까요?" | 트렌드가 크게 바뀌었을 때 | Q-00에 진입 + 트렌드 근거가 D-01 후보 근거로 전달 | 카드 닫힘 |

**공통 규칙 3개**
1. 카드는 홈에 **최대 2장.** 3장 이상이면 그건 추천이 아니라 소음이다.
2. 모든 카드에 출처와 관찰일을 붙인다. 근거 없는 추천은 시그마인의 "알아서 최적화"와 같아진다 (제품구조 §3.7).
3. 카드를 닫는 것에 비용이 없다. 닫아도 다음에 다른 카드가 온다. 같은 카드를 다시 밀지 않는다.

추가로 발견된 구조 결함 3건:
- **`variant`가 사실상 무의미하다.** `blog`·`video`는 `text`와 `QueueList variant`·`showSeo`만 다르고, `VIDEO_CAPABILITY`는 `STANDARD_TEXT_CAPABILITY`와 바이트 단위로 동일하다 (`channel-capabilities.ts:22-27` vs `43-48`). 갈래를 6개로 나눈 값을 못 쓰고 있다.
- **탭 상태가 전역 하나다.** `subTab`이 `useUIStore`의 단일 값이라 채널을 옮겨도 유지되고, 보정 로직의 기본값이 페이지마다 다르다 (`ChannelPage.tsx:112,116`은 `connected ? "queue" : "settings"`, `InstagramPage.tsx:459`는 `"queue"`). 같은 상황에서 다른 탭이 열린다.
- **닿을 수 없는 채널 라우트 4개.** `midjourney`·`seo_keywords`·`custom_api`·`rss`가 `CH_LABELS`에 있어 `/channels/<key>`가 발행 지원도 capability 정의도 없는 완전한 소셜 페이지를 렌더한다 (`constants.ts:24-28`).
- **미사용 컴포넌트 2개.** `TestSendCard.tsx`·`NotifStatusCard.tsx`는 레포 전체에서 import 0건이다.

#### 11.4.1-c 발견된 헤더 불일치 5건
1. **디자인 토큰 위반.** ChannelPage만 시맨틱 spacing 토큰(`px-region`, `text-subheading`, `text-caption`)을 쓰고 나머지 3개는 raw Tailwind(`px-8`, `text-xl`, `text-xs`)를 쓴다. `dashboard/CLAUDE.md`가 시맨틱 토큰 사용을 명시하는데 3개 파일이 위반이다.
2. **제목 위계 불일치.** 같은 급 화면인데 `text-subheading` vs `text-xl`, 그리고 Data만 `text-muted`로 제목이 흐리다. 제목을 회색으로 둘 이유가 없다.
3. **아바타 규칙 불일치.** Instagram만 보라·노랑 그라디언트다. 이건 §4 안티슬롭 블랙리스트(그라디언트 남발) 항목이기도 하다.
4. **죽은 탭바.** Messaging은 탭 5개 중 4개가 `removedTabs`로 제거돼 `settings` 하나만 남는데(`lib/channel-capabilities.ts:54`), 탭바를 여전히 렌더하고 클릭 핸들러는 빈 함수다. 탭이 하나뿐인 탭바는 UI 소음이다.
5. **탭 유무 불일치.** Data 채널만 탭이 통째로 없다. 사용자는 "이 채널은 왜 다르지"를 학습해야 한다.

## 16. 레드팀 (반대 관점 1회)

**공격자: 경쟁 도구(Buffer·Publer)를 이미 쓰는 마케팅 대행사 실무자**

> "질문 3개 받고 A/B/C 고르는 게 뭐가 새롭냐. 나는 이미 뭘 만들지 안다. 너희 흐름은 '뭘 만들지 모르는 사람'만 위한 거고, 그런 사람은 돈을 안 낸다. 그리고 나는 계정 12개를 굴리는데 너희 홈은 '작업 하나 만들기'가 전부다. 대량 운영이 안 된다."

**이 공격을 견디게 바꾼 것 3가지**

1. **Q-00을 흐름 2의 입구로 못 박았다.** 두 번째 제작부터는 질문이 확인 카드 1장으로 접힌다. 아는 사람은 카드 한 번 보고 `이대로 진행`을 눌러 바로 T-01로 간다. 흐름 1의 3화면은 평생 한 번만 겪는다.
2. **J-01의 `다른 안 보기`가 후보를 버리지 않게 설계했다.** 아는 사람은 A/B/C를 "제안"이 아니라 "3배수 산출"로 쓴다. 세 후보를 각각 다른 채널에 쓰는 사용을 막지 않는다.
3. **대량 운영은 이 문서 범위 밖임을 인정한다.** 12계정 운영은 A-07 계정 관리(v9.6 계승)가 다루지만, 배치 제작은 1단계 범위가 아니다. 제품구조 §5.5가 타깃을 "판단은 되는데 정의는 못 하는 사람"으로 이미 좁혔다. 이 공격은 **타깃이 아닌 사람의 공격**이고, 그렇다고 답한다. 다만 이 답이 성립하려면 대행사를 타깃으로 홍보하지 않아야 한다.

견디지 못한 지적 1건: "그런 사람은 돈을 안 낸다"는 아직 반박 근거가 없다. 제품구조 §9.6 D3이 자체 사용 우선으로 검증을 미뤘고, 그래서 이 문서도 답을 못 한다. **이건 유저플로우로 닫을 수 없는 구멍이라 기록만 남긴다.**
