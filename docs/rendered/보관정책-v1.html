한 줄 결론

손님이 만든 결과물과 올린 자료는 계정이 유지되는 동안 맡아 두는 손님 자산이다. 구독 해지는 자산 삭제가 아니며, 삭제는 손님이 명시적으로 지우거나 충분한 사전 경고를 거친 장기 미사용 계정 정리 때만 실행한다.

기존의 "손님 입력 30일 보관 후 삭제"는 폐기한다. 손님이 친 요청 문장은 손님이 다시 보고 재현할 작업 기록으로 보관하되 손님이 기간을 바꿀 수 있게 하고, 모델에 실제로 보낸 요청 전문만 개인정보 노출이 큰 민감 사본으로 분리해 최대 30일로 제한한다.

1. 결론: 종류별 보관 정책

1.1 종류별 정책표

종류 성격 기본 보관 기간 손님이 바꿀 수 있는가 구독 해지 시 손님이 삭제할 때 삭제 뒤 남는 것
1. 손님이 만든 결과물 글, 이미지, 영상 같은 손님 자산 계정 또는 작업공간이 존재하는 동안 예. 항목 삭제, 일괄 내보내기, 계정 삭제 가능 결제 주기 종료 후 무료 계정으로 전환한다. 기존 자산의 보기와 내려받기는 유지하고, 무료 한도를 넘으면 새 생성과 새 업로드만 막는다 일반 삭제는 30일 휴지통 후 영구 삭제한다. 손님이 "지금 영구 삭제"를 고르면 즉시 복구 불가 처리한다 내용은 남기지 않는다. 삭제 일시, 대상 종류, 처리 상태만 담은 삭제 확인 기록이 남는다
2. 손님이 올린 자료 회사 소개, 브랜드 문서, 사진 같은 원본 자산 계정 또는 작업공간이 존재하는 동안 예. 결과물과 같은 권리와 조작을 제공한다 결과물과 같다. 해지만으로 삭제하지 않는다 일반 삭제 30일 휴지통, 즉시 영구 삭제 선택 가능 파일 내용과 추출문은 남기지 않는다. 파일과 연결된 검색 색인, 미리보기, 파생 썸네일도 함께 지운다. 삭제 확인 기록만 남는다
3. 손님이 이번에 친 요청 문장 작업 이력이며 손님이 다시 보고 재현할 수 있어야 하는 기록 계정 또는 작업공간이 존재하는 동안 예. 30일, 90일, 365일, 계정 유지 기간 중 선택할 수 있다. 기본은 계정 유지 기간이다 결과물과 함께 보기와 내보내기를 유지한다 작업 단위 또는 전체 삭제가 가능하다 원문은 남기지 않는다. 중복 삭제 방지용 비가역 해시, 삭제 일시, 작업 식별자만 남길 수 있다
4. 모델에 실제로 보낸 요청 전문 시스템 지시, 첨부 내용, 검색 결과가 합쳐진 재현용 민감 사본 내부 보관은 30일 이내. 민감 모드는 내부 0일을 기본으로 한다 예. 0일, 7일, 30일 중 선택할 수 있다. 30일보다 길게 늘릴 수는 없다 이미 정한 만료일까지 보관한 뒤 자동 삭제한다. 해지가 기간을 늘리지 않는다 내부 사본은 즉시 접근 차단 후 7일 안에 운영 저장소에서 지운다. 모델 제공사 사본은 제공사 계약과 보관 기한에 따라 삭제 요청 또는 자동 만료된다 내용은 남기지 않는다. 제공사, 모델, 전송 시각, 제공사 요청 식별자, 삭제 기한과 처리 상태만 남는다
5. 결과에 붙는 제작 정보 어느 층, 스킬, 모델, 버전으로 만들었는지 나타내는 개인정보가 거의 없는 제작 이력 연결된 결과물 또는 계정이 존재하는 동안 일부 가능. 손님은 작업 이력과 함께 삭제할 수 있으나, 결제와 분쟁에 필요한 최소 기록은 바꿀 수 없다 기존 결과물의 출처 설명을 위해 유지한다 결과물과 함께 삭제한다. 다만 법정 보관 대상은 별도 금고로 분리한다 내용 없는 최소 감사 기록, 법정 거래 기록, 완전히 익명화된 집계만 남을 수 있다
6. 성과 숫자 조회, 클릭, 전환처럼 손님 계정과 게시물에 연결된 사업 데이터 계정 또는 작업공간이 존재하는 동안 예. 연결 해제, 원천 재수집 중단, 작업공간 삭제 가능 과거 숫자의 보기와 내보내기는 유지한다. 새 수집은 손님이 연결을 끊으면 멈춘다 계정별 원본과 게시물 연결값을 삭제한다 개인이나 계정을 다시 알아볼 수 없는 전체 집계만 남길 수 있다. 결제와 분쟁 기록은 별도 법정 기간 동안 남는다

1.2 무료 손님과 유료 손님의 차이

소유권, 삭제권, 내보내기, 30일 휴지통은 무료와 유료가 같다. 돈을 내지 않는다는 이유로 손님 자산의 안전을 낮추거나 삭제권을 유료 기능으로 만들지 않는다.

차이는 저장 용량, 새 생성 횟수, 버전 이력의 깊이, 협업 기능에만 둔다. 유료 구독을 해지하면 결제 주기 말에 무료 계정으로 바뀐다. 무료 한도를 넘은 기존 자산은 읽기와 내려받기를 허용하고 새 생성과 새 업로드만 제한한다.

따라서 구독 해지 뒤 별도의 "내려받기 유예 기간"은 필요하지 않다. 계정과 자산이 그대로 남기 때문이다. 서비스가 향후 무료 계정을 폐지하는 별도 사업 결정을 할 때만 90일 내보내기 전용 유예와 30일, 7일, 1일 전 경고를 새로 설계해야 한다.

1.3 삭제 사건을 서로 분리한다

사건 뜻 자산에 생기는 일
구독 해지 다음 결제를 중단하는 행위 무료 계정으로 전환한다. 자산은 삭제하지 않는다
개별 항목 삭제 특정 결과물, 업로드, 요청 기록을 지우는 행위 30일 휴지통으로 옮긴다. 즉시 영구 삭제를 별도로 제공한다
작업공간 삭제 한 브랜드나 팀의 전체 데이터를 지우는 행위 내보내기 안내와 강한 확인을 거친 뒤 그 작업공간 범위만 삭제한다
계정 삭제 모든 작업공간과 계정 정보를 지우는 행위 접근을 즉시 막고 운영 저장소는 7일 안에, 백업은 35일 안에 소거한다
개인정보 삭제 요청 특정 개인정보 처리를 중단하고 삭제해 달라는 법적 요청 관련 원문, 색인, 파생물, L5 규칙과 증거 연결까지 조사해 삭제하고 결과를 알린다
장기 미사용 무료 계정 정리 24개월 동안 로그인과 활동이 모두 없는 무료 계정을 정리하는 행위 90일, 30일, 7일 전에 경고한다. 로그인하면 취소하며, 끝까지 반응이 없을 때 계정 삭제 절차를 시작한다

1.4 L5에 배운 규칙이 녹아든 경우

L5는 장기적으로 재사용되는 손님별 제작 규칙이다. 이름만 "규칙"일 뿐, 특정 손님의 자료나 행동에서 만든 값이면 손님 데이터다.

손님이 삭제를 요청하면 다음 범위를 함께 처리한다.

  1. 해당 손님이나 작업공간에 연결된 L5 규칙의 현재값과 과거값을 삭제한다.
  2. 규칙을 만든 근거 문장, 업로드 조각, 결과물 링크, 성과 숫자 연결을 삭제한다.
  3. 삭제된 규칙이 이후 작업에 다시 주입되지 않도록 검색 색인과 캐시를 무효화한다.
  4. 이미 만들어 손님이 보관 중인 결과물은 별도 삭제 요청이 없는 한 유지한다. 과거 결과를 몰래 다시 쓰거나 바꾸지 않는다.
  5. 여러 손님에게 쓰는 공통 모델을 손님 콘텐츠로 학습시키는 기능은 기본 비활성화한다. 별도 동의, 학습 대상 명시, 동의 철회와 학습 영향 제거 방법이 준비되기 전에는 도입하지 않는다.

손님을 다시 알아볼 수 없는 통계 규칙만 남길 수 있다. 단순히 이름을 번호로 바꾼 가명 정보는 익명 정보가 아니다. 합리적인 시간, 비용, 기술을 써도 다시 알아볼 수 없다는 검토를 통과해야 한다.

1.5 백업 정책

운영 저장소에서 삭제했다고 백업까지 즉시 물리적으로 덮어쓸 수 있는 것은 아니다. 그래서 손님에게 "즉시 모든 사본 소거"라고 과장하지 않고 두 단계를 정확히 알린다.

  • 삭제 요청이 접수되면 운영 화면과 검색에서 즉시 접근을 막는다.
  • 운영 데이터, 파일 저장소, 검색 색인, 미리보기, 캐시는 7일 안에 삭제한다.
  • 암호화된 순환 백업은 최대 35일 안에 만료시킨다.
  • 백업은 일반 조회와 복구 요청에 쓰지 않는다. 재해 복구에만 쓴다.
  • 백업을 복원할 때는 삭제 목록을 먼저 다시 적용한 뒤 서비스 트래픽을 받는다.
  • 가능하면 손님 또는 작업공간별 암호 키를 폐기해 백업 안의 값도 즉시 읽을 수 없게 한다.
  • 삭제 확인 기록에는 내용 대신 대상 종류, 접수일, 운영 삭제 예정일, 백업 만료 예정일, 모델 제공사 처리 상태만 남긴다.

1.6 손님이 "지워 달라"고 할 때의 범위

위치 삭제 처리 손님에게 알릴 내용
Studio 운영 DB와 파일 저장소 원문, 파일, 파생 썸네일, 추출문, 캐시를 7일 안에 삭제한다 접근 차단 시각과 운영 삭제 완료 시각
검색 색인과 L5 색인 문서, 손님별 규칙, 규칙의 과거값, 증거 연결을 삭제하고 재주입을 막는다 지워진 규칙 수와 이후 결과에 더는 적용되지 않는다는 점
순환 백업 일반 접근을 차단하고 최대 35일 안에 만료한다. 복원 시 삭제 목록을 다시 적용한다 최종 백업 만료 예정일
모델 제공사 실제 요청 식별자로 삭제할 수 있는 끝점은 삭제를 요청한다. 자동 만료 방식은 계약상 만료일을 추적한다 제공사별 삭제 요청 상태, 예상 만료일, 정책 위반 조사와 법적 예외
Studio가 관리하는 외부 발행 채널 권한과 API가 허용하면 별도 확인을 받고 삭제한다 채널별 성공과 실패, 손님이 직접 해야 하는 조치
손님이 이미 내려받은 파일이나 제3자에게 복사한 자료 Studio가 원격으로 삭제할 수 없다 우리 통제 밖 사본은 삭제 범위에 포함되지 않는다는 한계
법정 거래와 분쟁 기록 제품 데이터와 분리해 법정 만료일까지 최소 항목만 보관한다 남는 항목, 법적 근거, 최종 삭제일
완전히 익명화된 통계 재식별할 수 없다는 검토를 통과한 집계만 남길 수 있다 어떤 집계가 남는지와 원문 복원이 불가능하다는 점

삭제 범위는 계정, 작업공간, 작업, 특정 자산 중 손님이 고른 단위로 집행한다. 단, 특정 자산을 지울 때 그 자산의 파생물과 L5 증거 연결을 기본 포함해 겉에 보이는 원본만 사라지는 불완전 삭제를 막는다.

2. 근거: 실제 정책과 우리 적용 판단

2.1 한국 개인정보 보호법과 전자상거래 기록

조사 대상 확인한 실제 내용 우리 적용 기각하거나 주의할 점
개인정보 보호법 제15조 동의를 받을 때 목적, 수집 항목, 보유와 이용 기간, 동의 거부 권리와 불이익을 알려야 한다 여섯 데이터 종류를 설정 화면과 개인정보 처리방침에서 따로 알린다 "서비스 개선을 위해 보관" 같은 포괄 문구로 서로 다른 데이터를 한꺼번에 동의받지 않는다
개인정보 보호법 제21조 보유 기간이 끝나거나 목적을 달성해 불필요해지면 지체 없이 파기해야 한다. 다른 법률 때문에 보관하면 다른 개인정보와 분리해야 한다. 복구 또는 재생되지 않게 조치해야 한다 계정 유지라는 서비스 목적이 끝난 자산은 정한 일정대로 파기한다. 법정 거래 기록은 제품 DB와 분리한다 "손님 자산이니 영원히 보관"도 허용되지 않는다. 계정 삭제 뒤 목적 없이 계속 두면 위험하다
개인정보 보호법 제36조 정보주체는 정정과 삭제를 요구할 수 있다. 사업자는 조사 후 지체 없이 삭제 등 필요한 조치를 하고 결과를 알려야 한다. 다른 법률이 수집을 요구하는 경우는 예외다 화면에서 삭제 요청을 접수하고 L5, 검색 색인, 모델 제공사 사본까지 범위를 추적한 삭제 확인서를 제공한다 화면의 원본만 지우고 파생 색인이나 L5 규칙을 남기면 삭제 요청을 온전히 처리한 것이 아니다
개인정보 보호법 제37조 처리 정지와 동의 철회 요구를 받으면 지체 없이 처리를 멈추고 필요한 조치를 해야 한다. 법률상 의무나 계약 이행 때문에 거절할 수 있는 예외가 있으며 이유를 알려야 한다 성과 수집과 외부 연결을 중단하는 별도 조작을 제공한다. 삭제할 수 없는 법정 거래 기록은 사유와 만료일을 알린다 법정 보관 예외를 이유로 손님 자산 전체를 계속 쓰지 않는다
개인정보 보호법 제58조의2 시간, 비용, 기술을 합리적으로 고려해도 개인을 더는 알아볼 수 없는 정보에는 법이 적용되지 않는다 삭제 뒤 남기는 성과 집계는 재식별 가능성을 검토한 진짜 익명 집계로만 제한한다 이름만 지우거나 계정 번호로 바꾼 가명 정보는 익명 집계로 간주하지 않는다
개인정보 보호법 시행령 제43조 정정과 삭제 요구의 조치 결과 또는 삭제하지 않은 이유를 10일 이내 알리는 절차를 둔다 삭제 요청 접수 즉시 예정표를 보여 주고, 늦어도 10일 이내 조사 결과를 통지한다 백업 만료가 35일이라는 이유로 접수 결과 통지까지 35일 미루지 않는다
전자상거래법 시행령 제6조 표시와 광고 6개월, 계약 또는 청약철회 5년, 대금결제와 재화 공급 5년, 소비자 불만 또는 분쟁 3년을 보존한다. 탈퇴한 소비자 기록은 별도로 보존한다 해당되는 거래, 결제, 환불, 분쟁 기록만 별도 법정 금고에 보관한다. 손님이 열람하거나 내려받을 수 있게 한다 제작 결과물, 업로드, 모델 요청 전문 전체를 5년 보관하는 근거로 확대하지 않는다

이 정책은 제품과 기술의 기준이다. 출시 전 한국 변호사 또는 개인정보 보호 책임자가 실제 수집 항목, 해외 이전, 위탁사, 개인정보 처리방침 문구를 최종 검토해야 한다.

2.2 손님 자산을 맡는 SaaS 사례

서비스 공개 정책의 실제 숫자와 행동 우리에게 차용 우리에게서 기각
Canva 계정 삭제 계정 삭제 요청 뒤 14일 동안 로그인하면 취소할 수 있다. 이후 디자인, 폴더, 템플릿, 업로드를 영구 삭제하므로 먼저 내려받으라고 안내한다 계정 삭제 전에 자산 범위와 내보내기를 강하게 알리고 실수 방지 절차를 둔다 모든 개인정보 삭제 요청을 무조건 14일 지연하지 않는다. 손님이 즉시 삭제를 원하면 그 선택을 제공한다
Canva 요금제 전환 요금제를 바꿔도 기존 디자인은 저장되며 요금제 전환 때문에 삭제하지 않는다고 밝힌다 결제 상태와 자산 수명을 분리한다 "절대 삭제하지 않는다"는 표현은 장기 미사용과 법적 파기 의무 때문에 그대로 쓰지 않는다
Notion 내보내기와 휴지통 작업공간을 HTML, Markdown, CSV와 업로드 파일로 내보낼 수 있다. 내보내기 링크는 7일간 유효하다. 휴지통의 기본 보존 기간은 30일이다 전 계정 내보내기, 7일짜리 안전한 내려받기 링크, 30일 휴지통을 차용한다 내보내기 파일을 영구 공개 주소에 두지 않는다
Notion 요금제 하향 하향 시 기능과 맞춤 보존 기간은 바뀌지만 콘텐츠 삭제로 처리하지 않는다. 기본 휴지통 보존은 30일이다 구독 해지를 자산 삭제가 아닌 기능 변경으로 처리한다 유료 보존 기간이 끝났다는 이유로 손님 원본을 지우는 구조는 채택하지 않는다
Notion 장기 미사용 계정 대상 계정에 30일 전 경고를 보내며 삭제 계정은 30일 동안 복구할 수 있다. 유료 계정과 다중 사용자 계정은 대상에서 제외한다 미사용 무료 계정만 별도 정책으로 다루고 사전 경고와 로그인 취소를 둔다 30일 단일 경고만으로 손님 브랜드 자산을 지우지 않는다. Studio는 90일, 30일, 7일 세 번 알린다
Figma 요금제 하향 취소 또는 하향 뒤 결제 주기 말에 무료 Starter로 전환한다. 무료 한도를 넘은 파일과 팀은 편집이 잠길 수 있지만 계정 삭제로 보지 않는다 무료 전환 뒤 기존 자산의 보기와 내려받기를 유지하고 새 쓰기만 제한한다 한도 초과 파일을 손님 몰래 골라 삭제하지 않는다
Dropbox 요금제 하향 결제 주기 말에 무료 Basic으로 내려가며, 요금제 취소는 계정 삭제가 아니라고 명시한다 해지와 계정 삭제를 명확히 분리하는 문구를 차용한다 용량 초과를 곧바로 삭제 동의로 해석하지 않는다
Dropbox 삭제 파일 보존 Basic, Plus, Family는 삭제 파일을 30일, Professional 계열과 일부 팀은 180일, Advanced와 Enterprise 등은 365일 복구할 수 있다 Studio 전 손님에게 이해하기 쉬운 30일 휴지통을 제공한다 복구 기간을 유료 차등으로 과도하게 늘려 개인정보 노출을 키우지 않는다
Dropbox 계정 삭제와 익명 정보 계정 삭제 뒤 저장 파일 삭제를 30일 후 시작할 수 있고, 익명 또는 집계 정보는 남을 수 있다고 밝힌다 백업과 익명 집계가 남는 범위를 숨기지 않고 설명한다 "익명"이라는 이름만 붙여 계정별 원본을 남기지 않는다
국내 NAVER MYBOX 이용권 종료 이용권이 끝나도 데이터를 임의 삭제하지 않고 유지한다. 무료 30GB를 넘으면 일부 기능을 제한한다. 2년 미사용 시 저장 파일을 삭제하며 만료 1주 전과 만료일에 알린다 국내에서도 결제 종료와 자산 삭제를 분리하는 관행을 확인했다. 무료 한도 초과 시 기능 제한 원칙을 차용한다 2년 미사용 삭제는 채택하되 1주 경고만으로는 부족하므로 90일, 30일, 7일로 강화한다
NAVER MYBOX 휴지통 삭제 휴지통에서 완전히 삭제한 파일은 복구할 수 없다고 명시한다 "지금 영구 삭제" 앞에 복구 불가 경고와 이중 확인을 둔다 영구 삭제를 일반 삭제 버튼과 같은 모양이나 위치에 두지 않는다

2.3 모델 제공사에 남는 입력 데이터

Studio가 내부 사본을 지워도 모델 제공사에 보낸 사본은 별도 수명주기를 가진다. 손님에게 작업마다 실제 제공사와 해당 정책을 보여 줘야 한다.

제공사 공식 정책에서 확인한 실제 보관 Studio 적용 제한과 기각
OpenAI API 데이터 관리 API 입력과 출력은 명시적 동의가 없으면 모델 학습에 쓰지 않는다. 기본 악용 감시 로그는 최대 30일이다. 승인된 고객은 수정된 감시 또는 저장하지 않는 ZDR을 쓸 수 있다. Responses API의 응답 상태는 기본 30일일 수 있으며 대화, 스레드, 파일처럼 삭제 전까지 남는 끝점도 있다 유료 API를 사용하고 학습 동의를 끈다. 민감 모드는 store=false와 ZDR 계약을 우선하며, 파일과 대화처럼 지속 저장되는 끝점은 명시적 삭제 작업을 둔다 "OpenAI는 전부 30일 후 자동 삭제"라고 단정하지 않는다. 사용한 끝점과 설정에 따라 삭제 전까지 남을 수 있다
Anthropic 상업용 데이터 보관 일반 API 입력과 출력은 원칙적으로 30일 안에 삭제한다. 정책 위반으로 표시된 입력과 출력은 최대 2년, 안전 분류 점수는 최대 7년, 사용자가 보낸 피드백은 5년 보관할 수 있다 기본 작업에는 30일 제공사 잔존 가능성을 표시한다. 민감 작업은 승인된 ZDR 사용 여부를 실행 전에 확인한다 "30일이면 어떤 경우에도 사라진다"고 쓰지 않는다. 정책 위반 조사와 법적 예외를 표시한다
Anthropic ZDR 적용 범위 ZDR은 승인된 API와 API 키 기반 제품에 적용된다. Files API는 삭제할 때까지 남을 수 있고 일부 캐시와 일괄 처리에는 별도 조건이 있다 ZDR 표시는 계정 계약뿐 아니라 실제 호출 끝점까지 검사해서 작업 기록에 남긴다 ZDR 계약이 있다는 이유로 별도 파일 저장까지 자동으로 0일이라 가정하지 않는다
Google Gemini API 데이터 기록과 ZDR 유료 API의 입력과 출력은 제품 개선에 쓰지 않는다. 현재 공개 문서는 일반 악용 감시 로그를 "제한된 기간" 보관한다고 설명하지만 숫자는 공개하지 않는다. Search 또는 Maps 기반 연결은 입력, 맥락, 출력을 30일 보관하며 끌 수 없다. Live 세션 재개는 최대 24시간, 암시적 메모리 캐시는 24시간이다. 승인된 ZDR은 내용과 식별 가능한 정보를 로그 전에 제거한다 Google을 쓸 때 일반 보관 기간이 미공개임을 그대로 알린다. 민감 모드는 ZDR을 확인하거나 숫자 상한이 분명한 다른 제공사로 보낸다. 검색 연결을 쓰면 30일을 별도 표시한다 공개되지 않은 기간을 30일이라고 추정하지 않는다. 유료 API라는 이유만으로 보관 0일이라고 말하지 않는다

모델 제공사 정책은 바뀔 수 있다. 제공사 이름, 정책 버전 확인일, 사용 끝점, 저장 설정, 예상 삭제일을 제작 정보에 남기고 분기마다 공식 문서를 다시 확인한다.

3. 법적 하한과 상한

3.1 최소 이만큼은 둬야 하는가

손님의 창작 결과물, 업로드, 요청 문장에는 모든 서비스에 공통인 법정 최소 보관 연수가 없다. 계정이 활성화되어 있고 손님이 보관과 재사용을 기대하는 동안에는 계약 이행을 위해 맡아 두는 것이 제품 원칙이다.

반대로 다음 거래 기록에는 법정 최소가 있다.

  • 계약 또는 청약철회 기록: 5년
  • 대금결제와 재화 공급 기록: 5년
  • 소비자 불만 또는 분쟁 처리 기록: 3년
  • 표시와 광고 기록: 6개월

이 최소 기간은 손님 자산 전체에 적용하지 않는다. 거래 번호, 금액, 상태, 필요한 당사자 정보처럼 법이 요구하는 최소 기록만 제품 데이터와 분리해 보관한다.

3.2 이 이상 두면 위험한가

개인정보 보호법에는 모든 개인정보에 적용되는 하나의 숫자 상한이 없다. 대신 처음 고지한 보유 기간과 처리 목적이 상한이 된다. 목적이 끝났거나 더는 필요하지 않으면 지체 없이 파기해야 한다.

Studio의 운영 상한은 다음과 같이 정한다.

대상 운영 상한 이유
손님 결과물과 업로드 계정 또는 작업공간 유지 기간 손님 자산 보관이 서비스의 본래 목적이다
장기 미사용 무료 계정 활동 중단 24개월, 90일 사전 경고 시작 무기한 방치를 막으면서 국내 보관 서비스 관행보다 경고를 강화한다
손님이 친 요청 문장 손님 선택에 따라 30일, 90일, 365일, 계정 유지 기간 재현 가치와 개인정보 노출을 손님이 조절한다
내부에 복제한 모델 전송 전문 최대 30일 문제 재현에 필요한 짧은 기간만 허용한다
운영 저장소 삭제 요청 뒤 7일 이내 검색 색인과 파생 파일을 포함한 삭제 작업의 기술적 상한이다
순환 백업 삭제 요청 뒤 35일 이내 만료 백업에서 개별 덮어쓰기보다 짧은 순환과 복원 시 삭제 재적용을 결합한다
모델 제공사 사본 제공사별 공식 상한 또는 계약 우리 저장소 밖의 사본이므로 실제 끝점과 계약을 기준으로 알린다
거래와 분쟁 기록 5년 또는 3년, 표시와 광고는 6개월 전자상거래법 시행령의 법정 보관 기간이다

4. 손님에게 보이는 화면

4.1 처음 맡길 때

가입과 첫 생성 전에 "내 데이터" 요약을 한 화면에 보여 준다.

  • 결과물과 올린 자료는 계정이 있는 동안 보관한다.
  • 구독을 해지해도 자산은 삭제되지 않는다.
  • 손님이 친 요청 문장과 모델 전송 전문은 서로 다른 보관 설정을 가진다.
  • 어떤 모델 제공사에 무엇이 전송되는지 작업 전에 확인할 수 있다.
  • 삭제하면 운영 저장소와 백업에서 언제 사라지는지 알려 준다.

필수 서비스 제공과 선택 동의를 분리한다. 손님 콘텐츠를 공통 모델 학습에 쓰는 동의는 기본 해제하며, MVP에서는 해당 학습 자체를 제공하지 않는다.

4.2 생성 버튼을 누르기 전

생성 확인 영역에 짧은 데이터 안내를 둔다.

이번 작업은 Anthropic Claude에 전송됩니다. Studio의 모델 전송 전문 보관은 30일입니다. Anthropic의 일반 API 보관은 원칙적으로 30일이며 정책 위반 조사와 법적 예외가 있을 수 있습니다. 민감 자료라면 민감 모드를 켜세요.

제공사, 모델, 내부 보관 만료일, 제공사 보관 상한, ZDR 적용 여부를 표시한다. "ZDR"을 쓸 때는 바로 옆에 "제공사가 요청 내용을 저장하지 않는 계약 설정"이라고 풀어 쓴다.

4.3 데이터 설정

설정의 데이터와 보관 화면에서 여섯 종류를 같은 말로 뭉치지 않고 각각 보여 준다.

설정 카드 손님이 보는 조작
결과물 사용량, 내보내기, 휴지통, 전체 삭제
올린 자료 사용량, 연결된 결과물, 내보내기, 휴지통, 전체 삭제
내가 친 요청 문장 30일, 90일, 365일, 계정 유지 기간 선택
모델 전송 전문 0일, 7일, 30일 선택, 민감 모드 기본값
제작 정보 작업별 제공사와 모델, 삭제 시 남는 최소 기록 설명
성과 숫자 연결 원천, 마지막 수집 시각, 수집 중단, 내보내기, 삭제

보관 기간을 줄이면 "기존 데이터 중 새 기간을 지난 항목이 언제 삭제되는지"를 변경 전에 보여 준다. 변경을 저장한 뒤에는 되돌릴 수 있는 마지막 시각과 영향을 알린다.

4.4 구독 해지

해지 화면의 첫 문장은 다음과 같이 명확해야 한다.

구독을 해지해도 결과물과 올린 자료는 삭제되지 않습니다. 결제 주기 말에 무료 계정으로 바뀌며, 무료 한도를 넘으면 새 생성과 새 업로드만 제한됩니다. 기존 자산은 보고 내려받을 수 있습니다.

계정 삭제를 해지 버튼 근처에 혼합하지 않는다. 해지는 결제 설정, 계정 삭제는 데이터 설정에 둔다.

4.5 개별 삭제와 휴지통

일반 삭제는 "30일 동안 휴지통에 보관 후 영구 삭제"라고 버튼 바로 옆에 표시한다. 영구 삭제는 별도 조작으로 두고 다음 경고를 보여 준다.

영구 삭제하면 이 결과물과 연결된 원본, 미리보기, 검색 색인, 요청 기록을 복구할 수 없습니다. 이미 외부 채널에 발행한 게시물은 해당 채널에서 별도로 지워야 합니다.

삭제 범위를 체크박스로 보여 주되 안전한 기본값은 연결 파생물까지 함께 삭제하는 것이다.

4.6 작업공간과 계정 삭제

삭제 전 화면에 다음을 한 번에 보여 준다.

  • 지워질 작업공간, 결과물, 업로드, 요청 기록, L5 규칙, 성과 연결의 개수
  • 남아 있는 법정 거래 기록의 항목과 최종 삭제일
  • 현재 사용 중인 모델 제공사 사본의 예상 만료일과 예외
  • 전체 내보내기 버튼과 내보내기 링크의 7일 만료
  • 운영 저장소 삭제 예정일과 백업 만료 예정일
  • "이 계정을 삭제하면 나중에 다시 찾을 수 없습니다"라는 복구 불가 경고

손님이 내보내기를 끝낸 뒤 삭제하도록 권하지만 내보내기를 강제하지 않는다. 개인정보 삭제 요청을 90일 다운로드 유예 때문에 미루지 않는다.

4.7 장기 미사용 경고

무료 계정이 21개월 동안 활동이 없을 때 90일 경고를 시작한다. 이메일과 앱 알림을 90일, 30일, 7일 전에 보낸다.

각 알림에는 삭제 예정일, 자산 개수, 로그인으로 취소하는 방법, 전체 내보내기 링크, 계정 삭제 범위를 넣는다. 로그인이나 내보내기 요청이 발생하면 정리 일정을 취소하고 새 활동 시각을 기록한다.

4.8 삭제 확인서

삭제 접수 직후 화면과 이메일로 확인서를 제공한다. 확인서에는 민감한 원문을 넣지 않고 다음 상태만 표시한다.

  • 접수 번호와 범위
  • 운영 접근 차단: 완료 시각
  • 운영 저장소와 검색 색인 삭제: 완료 또는 7일 이내 예정일
  • 모델 제공사: 제공사별 삭제 요청 또는 자동 만료 예정일
  • 백업: 최대 35일 이내 만료 예정일
  • 법정 분리 보관: 남는 항목, 근거, 만료일
  • 익명 집계: 남는 경우 재식별 불가 검토 기준

조사와 삭제 여부 통지는 10일 이내 제공한다. 기술적 백업 만료가 남아 있으면 "삭제 완료" 대신 "운영 삭제 완료, 백업 만료 대기"라고 정확히 쓴다.

5. 회장께 남는 선택

없다.

이번 정책의 핵심은 사업 취향을 고르는 문제가 아니다. 손님 자산을 구독 상태와 분리해 맡아 두고, 개인정보 노출이 큰 모델 전송 전문만 짧게 보관하며, 명시적 삭제와 법정 예외를 투명하게 처리하는 것이 일관된 답이다.

출시 전 개인정보 보호 책임자와 법률 검토는 필요하지만, 이는 회장께 제품 원칙을 다시 선택받을 문제가 아니라 고지 문구와 실제 처리 흐름이 법에 맞는지 검증하는 단계다.

6.2 사용자 흐름 1:1 매핑 점검

현재 docs/user-flow.md에 아래 다섯 단계가 없으므로 endpoint, frontend component, DB table에 1:1로 매핑할 수 없다. 계약과 스키마를 이 조사 문서에서 임의 확정하면 기술설계 합의 게이트를 우회하므로 모두 gap으로 남긴다.

누락 사용자 단계 endpoint frontend component DB table 판정
구독 해지 뒤 무료 전환, 자산 보기와 내보내기 미정 미정 미정 GAP-01
개별 자산의 휴지통 이동, 복원, 즉시 영구 삭제 미정 미정 미정 GAP-02
작업공간 또는 계정의 전체 내보내기, 경고, 삭제 미정 미정 미정 GAP-03

삭제 요청의 L5, 검색 색인, 제공사, 백업 전파와 확인서 미정 미정 미정 GAP-05

매핑 gap은 5개다. 이 다섯 단계가 docs/user-flow.md와 DESIGN.md에 승인된 뒤에만 FDD, API 계약, ERD, 테스트 계획에서 각각 1:1 매핑할 수 있다.

6.3 구현 전 수용 기준

다음 조건을 모두 충족해야 build stage 진입 가능으로 바꿀 수 있다.

  1. docs/user-flow.md에 GAP-01부터 GAP-05까지 사용자 단계와 예외 흐름이 추가된다.
  2. DESIGN.md에 데이터 설정, 해지, 휴지통, 계정 삭제, 삭제 확인서 화면과 경고 문구가 추가된다.
  3. 손님 요청 문장과 모델 전송 전문의 API 자원과 DB 경계가 분리 합의된다.
  4. 기존 tenant, subscription, usage, growth 구조의 재사용 경계가 명시된다.
  5. 제공사별 보관 설정과 삭제 상태, 백업 만료, L5 삭제 전파를 검증하는 테스트가 설계된다.
  6. 개인정보 처리방침, 국외 이전, 처리 위탁, 모델 제공사 계약을 개인정보 보호 책임자가 검토한다.

현재 build stage 진입은 불가다. 사용자 흐름 5개가 endpoint, component, table에 매핑되지 않았고, 현재 pipeline의 기술설계 승인도 이루어지지 않았다.

6.4 셀프심문과 레드팀 반영

셀프심문: 이 결론이 틀렸다면 가장 그럴듯한 이유는 무엇인가?

손님이 친 요청 문장을 계정 유지 기간 동안 보관하는 기본값이 재현 편의보다 개인정보 노출을 더 키울 수 있다는 점이다. 그래서 손님 요청 문장에는 30일, 90일, 365일, 계정 유지 기간 선택권을 주고, 더 민감한 모델 전송 전문은 별도로 최대 30일에 묶었다. 저장 시 암호화, 작업공간별 접근 통제, 삭제 요청 전파는 이후 기술설계의 필수 조건으로 올렸다.

까다로운 손님 관점의 공격: "삭제했다고 하면서 백업과 모델 회사에는 남겨 두는 것 아닌가?"

이 공격은 타당하다. 그래서 "즉시 완전 삭제"라는 표현을 금지하고, 운영 접근 차단, 운영 삭제 7일, 백업 만료 35일, 제공사별 자동 만료와 예외를 삭제 확인서에 따로 표시하도록 수정했다. 제공사의 기간이 공개되지 않은 Google Gemini 일반 로그는 숫자를 꾸며 내지 않고 "공개 숫자 없음"으로 알리며, 민감 모드는 ZDR 또는 숫자 상한이 분명한 제공사를 요구한다.
