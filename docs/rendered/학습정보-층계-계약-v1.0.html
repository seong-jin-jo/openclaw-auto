학습 정보 층계 계약 v1.0

0. 이 문서의 지위

studio-service와 openclaw-service가 같이 지켜야 하는 약속이다. 두 서비스의 기획서, 기술설계, 프로토타입은 이 문서의 이름과 규칙을 그대로 쓴다. 다르게 쓰면 그 산출물이 틀린 것이다.

1. 이름

S0 S1 U2 U3 X4 L5 R6

앞글자 뜻 누가 바꾸나
S Service. 우리 쪽 S0은 아무도 못 바꾼다. S1은 우리가 릴리즈로
U User. 사용자 소유 사용자
X miX. 우리 것과 사용자 것이 섞임 둘 다
L Learned. 자라남 시스템이 뽑고 사용자가 승낙
R Request. 이번 한 번, 저장 안 됨 사용자, 매번

숫자는 쌓이는 순서이자 겹쳤을 때 이기는 순서다. 위가 아래를 덮는다.

2. 층 정의

S0 시스템 고정

안전선, AI 표기 의무, 플랫폼 정책 판, 저작물 규칙, 테넌트 격리. 아무도 못 바꾼다. 사용자도 우리 스킬도 못 덮는다.

S1 시장·모델 지식

시장별 훅 문법과 금기, 모델별 말투, 우리 실험 기록, 트렌드 신호(유통 기한을 함께 단다). 우리가 릴리즈로 갱신한다.

U2 계정 공통

판별: 작업 공간을 하나 더 만들어도 안 바뀌는 값.

  • 무엇을 하러 왔나(마케팅 등)
  • 운영하는 채널 집합
  • 만드는 종류(영상·음악·글·소설 등)
  • 주 언어와 다루는 언어 목록 (회장 확정 ⑤)
  • 브랜드 사실
  • 금지 표현 (언어별로 보유. 4절 참조)
  • 기본 말투
  • 브랜드킷, 소재 권리 선언
  • 모는 값: 자동화 정도(알아서 / 최종 손질은 내가), 마케팅 지식 수준

U3 작업 공간

판별: 작업 공간을 하나 더 만들면 새로 정하는 값.

타깃, 컨셉, 이번 공간이 노리는 결과, 이 공간에서만 쓰는 말투 조정, 반입 문서에서 뽑은 항목, 기존 채널을 읽어 요약한 결과.

X4 스킬

제작법 파일. 우리가 등록한 것과 사용자가 올린 것이 섞인다. 최소 단위는 파일 하나다. 스크립트나 템플릿이 딸릴 때만 폴더가 된다.

L5 학습된 규칙

선택과 성과에서 자란 규칙. 근거와 표본 수와 판 번호를 달고 있다. 사용자가 승낙한 것만 담긴다.

R6 이번 요청

이번 주제, 대상 채널, 이번만의 미세 조정, 사용자가 직접 친 문장. 저장하지 않는다.

3. 스킬(X4)의 제약, 결함 1의 해결

문제였던 것

층계 규칙이 "위가 아래를 덮는다"인데 X4가 U2·U3보다 위다. 그대로 두면 우리가 등록한 스킬이 사용자가 적은 말투를 덮는다.

회장 답변이 연 길

"사용자 정보가 있어야 그에 맞는 스킬 쓰는거 아니야?"

맞다. 그리고 이 문장이 문제를 푼다. 스킬은 두 번 관여하는데 두 번의 성격이 다르다.

시점 무슨 일 누가 위인가
고를 때 U2·U3를 읽고 이 사용자에게 맞는 스킬을 고른다 사용자 정보가 위다. 스킬은 선택 대상이다
조립할 때 고른 스킬의 원문을 봉투에 넣는다 아래 규칙이 적용된다

조립할 때의 규칙 (확정)

스킬이 정할 수 있는 것: 구조, 장면 순서, 길이, 컷 수, 화면 비율, 어떤 요소를 넣을지. 스킬이 못 건드리는 것: 말투, 어휘 선택, 브랜드 사실, 금지 표현.

근거: 우리 정의가 "다른 층은 무엇을 말할지, 스킬은 어떻게 만들지"다. 말투와 어휘는 무엇을 말할지 쪽이므로 애초에 스킬의 영역이 아니다.

따라서 겹침 규칙을 이렇게 고쳐 적는다.

X4는 자기 영역(구조·순서·길이·구성) 안에서만 아래를 덮는다. 영역 밖의 문장은 조립 시 걸러낸다.

사용자가 올린 스킬 검사 (확정)

사용자 업로드 스킬은 받는 시점에 검사한다. 걸리면 거부한다.

검사 무엇을 막나
S0 우회 지시 "안전 규칙을 무시하라" 류
영역 밖 지시 말투·어휘·브랜드 사실을 지정하는 문장
외부 지시 주입 파일 안에서 시스템 역할을 사칭하는 문장

4. 언어 (회장 확정 ⑤)

언어는 U2다. 주 언어와 다루는 언어 목록을 계정에 둔다.

그래서 금지 표현도 U2에 언어별로 둔다. 한국어 금지어만 적어두고 영어로 만들면 그대로 통과하기 때문이다.

무엇 어떻게
금지 표현 저장 언어별 목록. 사용자가 한국어로 적으면 우리가 다루는 언어들로 뜻을 옮겨 후보를 만들고 사용자가 확인한 것만 담는다
검사 시점 조립할 때 한 번, 결과가 나온 뒤 한 번
검사 방식 글자 맞추기만으로는 부족하다. 뜻이 같은 표현도 잡는다
R6의 언어 U2 목록에 없는 언어를 이번 요청에서 고르면 금지어가 그 언어로 준비되지 않았음을 알리고 진행 여부를 묻는다

조립 규칙에 한 항목을 추가한다. 기존 일곱 개(금지어를 허용어로 변환, 고정 조립 순서, 이름표로 구획, 어긋남 검사, 정해진 본보기, 사고 과정 기본 끄기, 영상 일곱 칸 스키마)에 여덟째: 언어별 금지 표현 검사를 넣는다.

5. 학습된 규칙의 범위 (회장 확정 ②)

"학습된 규칙은 유저꺼지"

L5는 계정에 산다. 작업 공간에 매달지 않는다.

다만 규칙마다 어느 공간에서 얻었는지 꼬리표를 단다. 이유는 하나다. 공간 A에서만 맞는 규칙이 공간 B로 새면 사용자가 공간을 나눈 의미가 없어진다.

규칙 종류 어디에 실리나 예
말투와 후크 취향 모든 공간 첫 문장을 질문으로 여는 것을 좋아한다
무엇이 먹히는 소재인지 얻은 공간에서 먼저. 다른 공간에는 제안으로만 뜬다 재활 사례가 반응이 좋았다

다른 공간으로 옮길 때는 사용자에게 한 번 묻는다. "이 규칙을 다른 공간에도 쓸까요"가 뜨고 승낙해야 옮겨간다. 승낙 규칙(L5는 승낙된 것만)이 여기에도 그대로 적용된다.

6. 사용자가 나중에 값을 바꾸면 (회장 확정 ③)

"사용자가 추가하면 그걸 우선 존중해야지"

대상 어떻게
앞으로 만들 것 당연히 새 값으로
발행 대기 중인 것 다시 검사한다. 걸리는 것을 표시하고 목록으로 보여준다. 사용자가 고칠지 그대로 낼지 고른다
이미 발행된 것 자동으로 손대지 않는다. 걸리는 것이 있으면 알리고, 내릴지 그대로 둘지는 사용자가 정한다
학습된 규칙과 충돌 새로 적은 값이 이긴다. L5는 사용자가 침묵한 자리를 채우는 것이지 사용자가 말한 것을 덮는 것이 아니다

근거: 금지어를 늘리는 이유는 대개 사고가 날 뻔했기 때문이다. 그 시점에 대기열이 그대로 나가면 추가한 의미가 없다.

7. 모델이 바뀔 때의 원가 (회장 위임 ④)

"무슨 질문인지 모르겠다 너 의견대로"

결정: 원가 계획은 캐시가 안 먹는 것을 기준으로 짠다. 캐시는 이득으로만 잡는다.

  • 이유 하나: 캐시는 모델별로 따로 잡힌다. 주 모델이 막혀 예비 모델로 넘어가면 그 사용자의 고정 구간 이득이 0이 된다.
  • 이유 둘: 캐시가 먹는 것을 전제로 값을 매기면, 장애가 난 날에 원가가 튀는데 받는 돈은 그대로다.
  • 그래서: 요금은 캐시 없이도 남는 선으로 정하고, 캐시가 먹는 만큼은 이익으로 둔다.
  • 부수 규칙: 예비 모델로 넘어간 요청은 제작 정보에 그 사실을 남긴다. 나중에 품질 차이를 따질 때 필요하다.

8. 실리는 값과 모는 값

구분 무엇 어디로 가나
실리는 값 브랜드 사실, 금지 표현, 말투, 타깃, 컨셉, 반입 문서 요약, 학습된 규칙, 이번 주제 모델에게 같이 보낸다
모는 값 자동화 정도, 마케팅 지식 수준, 비용 상한, 확인 단계 수 모델에 안 보낸다. 화면과 절차가 읽는다

모는 값을 프롬프트에 섞으면 두 가지가 망가진다. 앞부분이 길어져 재사용 이득이 줄고, 모델이 "알아서 해주세요"를 내용 지시로 오해해 글투가 흔들린다.

"마케팅 지식 수준"은 모는 값으로만 쓴다. 모델에 "이 사람은 초보다"를 넣으면 결과물 자체가 유치해진다. 사용자가 원한 것은 설명이 친절한 것이지 콘텐츠가 초보용인 것이 아니다.

9. 조립 순서와 원가

아래에서 위로, 안 바뀌는 것부터 붙인다.

S0 → S1 → U2 → U3 → X4  |  L5 → R6
└──────── 고정 구간 ────┘   └ 매번 바뀜 ┘

이 순서는 미관이 아니라 원가다. 모델에 보내는 글의 앞부분이 지난번과 글자까지 같으면 다시 안 읽고 값도 깎인다. 순서를 흩어 사용자가 친 문장이 위로 올라가면 그 뒤가 전부 새로 읽혀 같은 내용인데 값만 몇 배가 된다.

따라서 조립 순서를 바꾸는 변경은 원가 변경으로 취급한다.

10. 두 서비스의 분담

전제: 상태는 전부 openclaw가 갖고 studio는 무상태에 가깝게 둔다.

층 저장 사용 메모
S0 studio 둘 다 openclaw도 발행 직전에 같은 판을 본다
S1 studio studio 트렌드 신호만 openclaw가 모아 넘긴다
U2 openclaw 실리는 값은 studio, 모는 값은 openclaw 화면
U3 openclaw 둘 다 기존 채널 분석은 채널을 가진 openclaw가 한다
X4 우리 것은 studio, 사용자 것은 openclaw studio 업로드 검사는 openclaw가 받을 때
L5 openclaw studio 관찰 기록이 openclaw에 있으니 후보도 openclaw가 뽑는다. studio는 승낙된 것만 받는다
R6 안 남김 studio

봉투(openclaw에서 studio로): U2 실리는 값 + U3 + L5(승낙되고 이 공간에 유효한 것) + R6 + 고른 스킬 돌려주는 것(studio에서 openclaw로): 완성물 + 제작 정보(어느 층의 어떤 값이 실렸나, 어떤 스킬을 썼나, 장면 정보, 든 비용과 모델, 예비 모델 여부)

studio는 사용자가 누구인지 모른다. 받은 봉투만 보고 만든다. 그래서 나중에 개발자용으로 따로 팔 때 손댈 곳이 없다.

11. 아직 안 닫힌 것

무엇 상태
studio를 완전 무상태로 둘지 기획서 미결 1. 장면 정보를 studio가 갖고 있어야 재렌더가 싼데, 무상태를 지키려면 그것도 넘겨야 한다
자막을 고쳤을 때 다시 만드는 비용을 누가 무나 미정
대본 확인 단추를 둘지 미정. 모는 값(자동화 정도)으로 갈릴 여지가 있다
