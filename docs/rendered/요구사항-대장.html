2026-08-22 최신 확정 (R79~R99)

번호 확정 요구 갈래

2026-08-25 v49 반려 (계약 위반 2건 + 화면 구조 지적)

위반 1 (중대): R132로 "제목·캡션·해시태그는 발행실"을 확정하고 위임문에도 명시했는데 v49 편집실이 여전히 "플랫폼 화면을 보며 제목과 캡션을 고칩니다"를 유지했다. 지시 불이행이다. 위반 2 (중대): 확정 용어 학습 정보를 승인 없이 선택 기록으로 개명해 헤더에서 학습 정보가 사라져 보였다. 용어는 회장 확정 자산이며 에이전트가 바꿀 수 없다.

번호 확정 내용 원문 근거
R143 사업계획·PRD·기술설계를 갱신했으면 그 산출물도 함께 가져와 보여준다 "사업계획 기술설계 PRD 업데이트했으면 그거 안져오냐"
R142 정체 불명의 "채널운영 선택기록"을 없앤다 "채널운영 선택기록은 뭐고"
R141 발행실은 기존 OSMU 구현을 참고해 만든다. 플랫폼별 헤더를 통일한다 (반복 지시) "발행실에서 OSMU 기존에 어떻게 만들었는지 참고 안하냐고. 플랫폼별 헤더 통일성 진짜 30번은 얘기한듯"
R140 벤치마킹을 실제로 한다. 재생 화면은 유튜브 실물을 보고 만든다 "벤치마킹은 또 하나도 안했지? 유튜브에선 재생화면을 저렇게 좆같이 만들디?"
R139 편집실에서 제목·캡션·해시태그를 다루지 않는다. R132 재확인이며 v49가 이를 어겼다 "편집실에서 제목 캡션 해시태그 안하기로 했잖아. 대화를 어디에 쳐박았노"
R138 단계적으로 넘긴다. 한 화면에 다 때려박지 않는다. 유저 플로우를 따라 화면을 나눈다 "단계적으로 넘겨. 한 화면에서 다 쳐 보여주려고 하지말고. 유저 플로우 생각해서 안하냐?"
R137 디스플레이는 발표 화면이다. "후보 3개 중 하나를 고르세요" 같은 선택 창을 화면 아래에 덧붙이지 않는다 "내가 디스플레이는 PPT라고 했지. 이거 포함된 창은 왜 밑에 붙여놓은거야?"
R136 확정 용어 학습 정보를 임의로 바꾸지 않는다. 헤더에 학습 정보를 유지한다 "헤더에 학습정보는 또 왜 사라졌고"
R135 설명용 텍스트를 없앤다. 위치 표시줄("모노스튜디오 · Studio 생성"), 화면 안내문("지금 만들 수 있는 화면을 먼저 보여드립니다"), 대화창의 "근거 표시가 무슨 뜻인가요", "현재 단계 담당 · 이 자리에 계속 있습니다" 전부 제거 "쓸데없는 텍스트좀 없애라고. 이게 필요한 설명이냐?"

2026-08-24 소유 경계 기준 확립 + 디자인 담당 모델

번호 확정 내용 원문 근거
R134 디자인은 클로드 product-designer 에이전트로 돌린다. 병렬 가능한 다른 작업만 codex. 2026-08-15 기록에 이미 있던 결정이며 컨트롤러가 임의로 codex를 쓴 것이 이번 반려의 한 원인 "클로드로 하기로했잖아 디자인은"
R133 studio는 플랫폼 규격에 맞춘 원본 콘텐츠를 발행실로 보낸다. 규격 자체는 openclaw가 가지고 studio는 요청 시점에 받아 쓴다(저장하지 않음) "openclaw 발행실 보낼때는 플랫폼별 규격에 맞게 원본 컨텐츠 보내도록해야겠네"
R132 소유 경계의 기준 = 그 지식이 어느 DB에 사는가. studio는 콘텐츠 생성·편집 지식, openclaw는 플랫폼·마케팅 지식을 갖는다. 따라서 제목·문구·해시태그와 댓글 관리는 발행실(openclaw), 편집실은 콘텐츠 자체(영상 길이·자막 등) 조절이다. R31 부활, R38·R88 폐기 "studio는 컨텐츠 생성과 편집에 대한 정보이고 실제 플랫폼이나 마케팅 관련 지식은 openclaw가 관리할테니까 제목 문구이런건 발행실에서 관리하고 댓글관리같은거도 하는게 맞긴 해보여"

네 번의 변천 종결: R31(08-19 발행실) → R38(08-21 편집실) → R88(08-22 편집실 확정) → R132(08-24 발행실, 기준 명시). 앞의 셋은 "작업 흐름이 어디서 이어지나"로 정했고 매번 뒤집혔다. R132는 지식이 어느 DB에 사는가라는 검증 가능한 기준을 세웠으므로 다시 뒤집으려면 그 기준 자체를 반박해야 한다. 기준 없는 재논의는 하지 않는다.

2026-08-24 v47 프로토타입 전면 반려 (회장 실물 피드백)

회장이 v47을 직접 눌러 보고 낸 지적. 근본 원인은 기존 산출물(PRD·사업계획·이미 만든 화면)을 안 읽고 백지에서 창조한 것이다. product-designer 계약서 자체에 "백지에서 재창조 금지, 기존 레이아웃·컴포넌트·토큰 계승"이 있고, 검증 게이트도 "기존 자산 재사용 미기재"로 FAIL을 냈는데 컨트롤러가 그 FAIL을 흘려보냈다.

번호 확정 내용 원문 근거
R110 프로토타입 상단 검수 도구가 스크롤에 붙어 따라온다. 스크롤하면 안 따라오게 한다 "프로토타입 위에 스티키 되어있어서 스크롤다운했을때 좆같네"
R111 제품 화면 안에서 "보는 사람 고객/운영자" 토글을 뺀다. 검수용 장치를 제품 화면에 두지 않는다 "화면 내에 보는 사람 고객/운영자는 왜 있냐"
R112 어둡게(다크 모드) 전환을 이 자리에서 뺀다. 넣을 거면 헤더에 둔다 "어둡게는 왜 여기 있지? 다크모드 넣을거면 헤더에 두던가"
R113 학습 정보는 별도 창으로 뺀다. 본문에 상주시키지 않는다 "학습정보는 별도 창으로 빼"
R114 "읽고 쌓는 정보"를 매번 보여주지 않는다 "읽고 쌓는 정보를 왜 매번 보여주냐"
R115 디스플레이의 정체 확정. 실제 이미지·영상을 보고 판단·비교하는 메인 영역이거나, 대화 중 추가 설명·예시를 함께 보는 공유 화면이다. 그 외 텍스트 나열은 뺀다 "실제 이미지나 영상들 보고 판단 비교하는게 메인영역이고 혹은 챗봇에서 이것저것 결정할때 추가 설명이 필요하거나 예시 등 보여줄때 같이 공유하는 PPT같은 화면"
R116 왼쪽 01·02·03·04 목록과 "Studio 생성"을 눌렀을 때 나오는 화면의 관계를 명확히 한다. 지금은 무엇이 다른지 알 수 없다 "01 02 03 04 는 대체 뭔 페이지냐 studio 생성 누르면 보이는 페이지랑은 뭔 차이임?"
R117 생성실의 "제안"에는 실제 제안된 화면을 낸다. 실험 로그·공개 사례 같은 부속 텍스트를 넣지 않는다 "제안이라고 하면 실제 제안된 화면을 내야지 우리 실험로그, 공개사례이런건 왜 넣는거고"
R118 제안마다 "이걸로 후보 만들기"·"문구만 먼저 보기"를 반복해 붙이지 않는다. 직관적 UI로 구성한다 "제안 안마다 '이걸로 후보 만들기' '문구만 먼저보기' 반복하고 있네"
R119 학습 정보가 헤더에 있으면 본문에서 같은 설명을 다시 늘어놓지 않는다 "학습정보가 헤더에 있는데 왜 또 studio 생성 추천을 받으시거나 어쩌고저쩌고 구구절절"
R120 "제안 말고 직접 쓰기" 단추의 정체가 불명확하다. 필요 없으면 뺀다 "제안말고 직접쓰기는 대체 뭔 버튼이고"
R121 편집실의 "방금 바꾼 것 되돌리기"를 따로 두지 않는다 "방금바꾼것 되돌리기는 왜 따로 있는건지도 모르겠고"
R122 편집실 재생 화면을 키우고, 자막 크기·재생 속도·문구를 재생 플레이어 안에 직관적으로 넣는다. 화면 하나를 통째로 쓰지 않는다 "재생화면을 좀 더 키우고 자막 크기, 재생속도, 문구 등도 좀 직관적인 UI로 넣으면 되지않을까 재생 플레이어에 적절하게 잘 꾸미면 되지 않을까"
R123 편집실은 여러 플랫폼의 캡션·제목을 수정하는 자리다. 이것이 OSMU의 핵심인데 화면에 없다 "studio 편집실에서는 OSMU 처럼 여러 플랫폼에 대한 캡션 제목 수정 등 하지 않냐?"
R124 발행실에 "채널별 문구"를 따로 두지 않는다. 각 플랫폼 미리보기에서 보고 그 자리에서 고친다 "발행실 채널별 문구는 왜 있냐 미리보기에서 OSMU 각플랫폼 미리보기하고 바로 직관적으로 수정하는거 아니냐?"
R125 원본 내려받기는 편집실에 둔다 "원본 내려받기는 편집실에서 하는거아님?"
R126 발행 캘린더에 실제 달력을 넣는다. 설명 나열로 대신하지 않는다 "발행캘린더에는 캘린더가 없고 쓰잘데기없는 설명만 존나게 늘어놓노"
R127 성과실은 이미 만들어 둔 화면을 계승한다. 새로 창조하지 않는다 "성과실은 기존에 있던 화면들 또 개무시하고 혼자 개병신처럼 창조하고 있고"
R128 왼쪽 사이드바는 플랫폼 목록을 통일하고, 이미 있는 계정 연결·로그인 화면을 그대로 계승한다 "왼쪽 사이드바에서 역시 플랫폼별로 통일도 안했고 기존 계정연결 로그인 화면 다 무시하고"
R129 사이드바의 "처음과 배움"을 없앤다. 학습 정보를 사이드바에 또 두지 않는다 (R113과 한 쌍) "사이드바 보면 처음과 배움 저건 또 뭔 개지랄인지 학습정보는 또 왜있고"
R130 프로토타입 작업 전에 PRD와 사업계획을 반드시 읽는다. 안 읽고 만든 화면은 그 자체가 반려 사유다 "PRD나 사업계획 안보고 그냥 혼자 프로토타입 작업하는것 같노"
R131 Claude Code 대응은 studio 서비스 PRD에 자세히 쓰고, 사업계획에는 간략하게만 갱신한다 "studio service PRD에 자세하게 있는게 맞는거같고 사업계획에는 간략하게 업데이트해야지않겠어?"

2026-08-24 보관 정책과 비교 관점

번호 확정 내용 원문 근거
R109 Claude Code와의 기술 비교는 운영체제 관점으로 대조한다. 문맥 창=주기억, 조립층=메모리 관리자, 층 우선순위=덮어쓰기 순서로 놓고, 비유가 깨지는 자리도 함께 적는다 "기술비교할때는 운영체제 관점에서 잘 비교대조해줘"
R108 손님이 만든 결과물과 올린 자료는 손님 자산이다. 구독 해지는 자산 삭제가 아니다. "손님 입력 30일 뒤 폐기"는 폐기한다. 개인정보 노출이 큰 모델 전송 전문만 최대 30일로 따로 묶는다 "유저 정보를 우리가 보관하는데 개인정보 기밀을 temporary로 비교하면 그냥 폐기해버린다는거임? 나중에는?"
R107 상품 정의가 바뀌어도 새 상위 화면과 요금 변경은 하지 않는다. 기존 제작 정보에 결과별 연결을 붙이고, 기술설계에 손님용 조회 계약을 더한다 "반박은 좋다. 니가해야겠다고 생각하는거 codex로 써서 보고해라" 에 대한 판정 회신

2026-08-23 기술설계 결정 회신 (결정보드 v1)

번호 확정 내용 원문 근거
R106 작업 공간 추가는 요금제 기본 수량 + 초과분 추가 구매로 판다. 추가 구매의 갱신 주기는 구독과 같다 결정보드 3번 선택
R105 studio 단독 손님은 만료되는 내려받기 링크로 원본과 채널별 준비본을 받아 간다. 재발급·삭제·보관 기간은 studio 책임 결정보드 2번 선택
R104 studio가 회원·권한 장부를 직접 갖는다. 로그인·결제 업체는 갈아 끼울 수 있게 붙인다. R71의 재확인이며 앞으로 이 항목을 다시 묻지 않는다 결정보드 1번 선택 + "3번째 말하는데" 지적

2026-08-23 회장 지적 (v45 프로토타입 열람 후)

번호 확정 내용 원문 근거
R103 카드 여백 두 안은 벤치마크에서 유도한다. 출처 없는 안은 폐기한다 "스티치 참고 안했네. 벤치마킹 안하냐? 뇌피셜로 계속 쓰레기같은 UX 내놓네"
