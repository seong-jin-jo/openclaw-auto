# 학습 정보 계층 (구판, 대체됨)

## 1. 무엇을 기준으로 나눴나

**누가 바꿀 수 있는가.** 이것 하나가 기준입니다. 바꿀 수 있는 주체가 다르면 다른 층입니다.

바꿀 수 있는 주체가 다르면 저장 위치도, 갱신 주기도, 겹쳤을 때 누가 이기는지도 달라집니다. 그래서 이 기준 하나로 전부 정리됩니다.

## 2. 컴퓨터공학 관습을 따른다

이 구조는 새로 만든 것이 아니라 이미 있는 두 관습과 같은 모양입니다.

| 우리 구조 | 같은 모양의 관습 | 무엇이 같은가 |
|---|---|---|
| 아래는 못 바꾸고 위로 갈수록 자주 바뀜 | 컨테이너 이미지 층 | 바닥은 읽기 전용이고 위에 층을 얹는다. 같은 파일이 여러 층에 있으면 위층이 보인다 |
| 겹치면 위가 이기되 예외 둘은 못 덮음 | 스타일 시트의 우선순위 | 나중에 온 것이 이기지만 강제 표시가 붙은 것은 못 덮는다 |

**그래서 이름 앞에 바꿀 수 있는 주체를 붙입니다.**

| 앞글자 | 뜻 | 누가 바꾸나 |
|---|---|---|
| **SYS** | 시스템 고정 | 아무도 못 바꾼다. 우리가 릴리즈로만 |
| **OUR** | 우리 지식 | 우리가 갱신한다 |
| **USR** | 사용자 소유 | 사용자가 직접 |
| **MIX** | 섞임 | 우리도 넣고 사용자도 올린다 |
| **LRN** | 자라남 | 시스템이 뽑고 사용자가 승인 |
| **REQ** | 이번 한 번 | 사용자가 매번 |

## 3. 층 전체

아래에서 위로 쌓습니다. 위가 아래를 덮습니다.

| 층 | 무엇이 들어가나 | 누가 바꾸나 | 언제 받나 | 생성 | 편집 | 발행 | 성과 |
|---|---|---|---|---|---|---|---|
| **L6 이번 요청** `REQ` | 이번 주제, 언어, 대상 채널, 비용 상한, 이번만의 미세 조정. **사용자가 친 프롬프트** | 사용자, 매번 | 만들 때마다 | 쓴다 | 쓴다 | | |
| **L5 학습된 규칙** `LRN` | 선택과 성과에서 자란 규칙. **사용자가 승낙한 것만.** 근거와 표본 수와 판 번호를 달고 있다 | 시스템이 뽑고 사용자가 승인 | 쓰면서 계속 | 쓴다 | 쓴다 | 쓴다 | 여기서 만들어진다 |
| **L4 스킬** `MIX` | 제작법 파일. 우리가 등록한 것과 사용자가 올린 것 | 우리와 사용자 둘 다 | 아무 때나 | 쓴다 | 쓴다 | | |
| **L3 작업 공간** `USR` | 타깃, 컨셉, 업종, 이 공간의 스타일, **반입한 위키와 노션에서 뽑은 항목**, **기존 채널 분석 결과** | 사용자 | 공간 만들 때 | 쓴다 | 쓴다 | 쓴다 | |
| **L2 계정 공통** `USR` | 브랜드 사실, **금지 표현**, 기본 말투, 브랜드킷, 소재 권리 선언 | 사용자 | 처음 한 번 | 쓴다 | 쓴다 | 쓴다 | |
| **L1 시장·모델 지식** `OUR` | 시장별 훅 문법과 금기, 모델별 말투, 우리 실험 기록. **트렌드 신호는 여기 붙되 유통 기한을 함께 단다** | 우리 | 우리 릴리즈 | 쓴다 | 쓴다 | | |
| **L0 시스템** `SYS` | 안전선, AI 표기 의무, 플랫폼 정책 판, 저작물 규칙, 테넌트 격리 | 아무도 못 바꿈 | 고정 | 쓴다 | 쓴다 | 쓴다 | |

**L0과 L1이 바닥이고 우리가 넣습니다. L2와 L3이 사용자 것으로 쌓입니다. L4 스킬이 그 사이에서 섞입니다. L5가 쓰면서 자라고 L6이 매번 바뀝니다.**

## 4. 겹치면 위가 이긴다. 예외 둘

| 못 덮는 것 | 왜 |
|---|---|
| **L0 시스템 전부** | 법과 정책이다. 사용자가 해제할 수 없다 |
| **L2의 금지 표현** | 사용자가 직접 절대 쓰지 말라고 적은 것이다. 이번 요청이 뒤집으면 사고가 난다 |

나머지는 위가 이깁니다. 이번 요청이 작업 공간 스타일을 덮고, 학습된 규칙이 사용자가 침묵한 자리를 채웁니다.

## 5. 시스템이 넣는 것과 사용자가 주는 것

| 우리가 넣는다 | 사용자가 준다 |
|---|---|
| L0 전부 | L2 전부 |
| L1 전부 | L3 전부 |
| L4 중 우리가 등록한 스킬 | L4 중 사용자가 올린 스킬 |
| L5의 후보 제안 | L5의 승인 |
| | L6 전부 |

## 6. 어느 시점에 받나

| 시점 | 채우는 층 |
|---|---|
| 작업 공간을 만들 때 | L2, L3 |
| 만들려고 할 때 | L6. L4에서 스킬을 고른다 |
| 첫 콘텐츠가 나온 뒤 | 발행 운영 정보. L3에 붙는다 |
| 쓰면서 계속 | L5 |
| 우리가 알아서 | L0, L1 |

## 7. 스킬이 L4에 있는 이유

스킬은 우리가 등록하기도 하고 사용자가 올리기도 합니다. 그래서 우리 것만 있는 아래층에도, 사용자 것만 있는 층에도 못 넣습니다. **둘이 섞이는 자리가 따로 필요합니다.**

그리고 스킬은 다른 층과 성격이 다릅니다. 다른 층은 무엇을 말할지를 담고 스킬은 어떻게 만들지를 담습니다. 저장 형태도 다릅니다. 다른 층은 줄 단위로 쪼개 두고 스킬은 파일 원문 그대로 둡니다.

## 8. 이 표가 확정되면

사업계획과 두 기획서의 계층 표를 이 표로 일괄 교체합니다. 지금 세 문서가 옛 번호와 옛 순서를 쓰고 있어 미루면 계속 어긋납니다.
