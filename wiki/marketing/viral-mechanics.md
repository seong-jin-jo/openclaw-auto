## 0. 하위모델 사용 규칙

1. 장치는 번호(V1~V8)로 참조한다. 해당 글 큐 적재 시 feedback-loop §2.2 태그에 `vm=VN`을 붙인다 — 안 붙이면 효과 측정 불가.
2. **신규 장치 발명 금지** — 후보가 보이면 이 파일에 제안 append(회장 승인)로만 추가.
3. 장치별 `빈도 상한`은 판정 기준 숫자와 같은 급 — 임의 초과 금지(피로감·스팸 판정은 계정 단위 리스크다).
4. **엔게이지먼트 베이트 금지선**: "공유하면 추첨"·"친구 태그 필수"·"팔로우해야 정답 공개" 류 조건 걸기 금지 — Meta 계열은 강요형 참여 유도를 감점하며, 우리 윤리선(marketing.md §4-3 강제 공유 금지)과도 충돌. 참여는 **질문·퀴즈·제보처럼 독자가 답하고 싶어서 답하는 형태**만.
5. 같은 장치 연속 반복 금지 — Threads 알고리즘은 동일 포맷 반복을 저퀄리티 신호로 감점하므로 3~4개 포맷 회전이 기본 ([threadsauto.kr 2026 알고리즘 신호](https://www.threadsauto.kr/blog/threads-algorithm-2026-signals) — 외부 관찰, 자체 재검증 전 (unsourced) 급 취급).

## 2. 장치 8종 (V1~V8)

각 장치 = 작동 원리(심리 법칙 명명) · 적용 위치 · 측정 · 리스크와 상한.

### V1 — 저장 트리거: 사장님 보호 정보형

- **작동 원리**: 손실 회피(mistake family) + 도구 비축 심리 — "대행 견적 받기 전에 다시 볼 글"처럼 **미래의 돈 걸린 순간에 꺼내 쓸 정보**는 저장된다. 저장은 알고리즘에 가장 무거운 신호 중 하나이면서 팔로우보다 심리 저항이 낮다.
- **적용 위치**: S3(원가 해부 — D5 초안이 이미 "저장" CTA로 끝남), IG 카드뉴스(표지=숫자+타겟 명시, 마지막 장 저장 유도 — §1 카드뉴스 공식).
- **측정**: 글별 저장 수(G-1), IG 형식 실험은 growth-log **실험 3**과 공유. 태그 `vm=V1`.
- **리스크·상한**: "저장하세요" 남발 = 빈 CTA(writing.md §3-B). 저장 CTA는 **체크리스트·비교표·계산식이 실제로 들어있는 글에만** 부착. 주 2회 상한.

### V2 — AI 글 맞히기 퀴즈 (참여 장치)

- **작동 원리**: 자이가르닉(curiosity gap — 정답이 잠겨 있음) + 자기효능 과시(맞히는 행위가 "나는 AI 글 구분한다"는 정체성 수행). 48h 후 정답 공개가 **재방문 루프**를 만든다(H-12 사용 조건에 이미 내장).
- **적용 위치**: S1 화요일 생산 일지(H-12) — 캘린더 D13에 배치돼 있음.
- **측정**: 퀴즈 글 댓글 수(1순위), 정답 공개 글 도달(재방문 대리지표). 태그 `vm=V2`.
- **리스크·상한**: 반복 피로 — 매주 하면 게임이 시시해진다. **월 2회 상한**, 오답률이 실제로 흥미로운 회차(사람 글을 AI로 오인)만 리포트에 재인용. "팔로우해야 정답 공개" 금지(§0-4).

### V3 — 업종 제보 → 공개 데모 (UGC 순환 루프)

- **작동 원리**: 상호성(내 제보에 공장이 실물 데모로 응답) + IKEA 효과(자기 제보가 콘텐츠가 되면 그 글의 지분을 느끼고 공유한다) + 사회적 증거(제보가 쌓이는 것 자체가 수요 증거). **댓글이 다음 에피소드의 원료가 되는 소재 자급 구조** — 캘린더 D19("댓글로 받은 업종 1개 데모")에 이미 슬롯 존재.
- **적용 위치**: S2 마무리 CTA(C-01/C-07 "사장님 업종은? 댓글로"), 제보 채택 시 해당 댓글 작성자를 글에서 호명(닉네임)하고 답글로 알림 — 제보자가 자기 업종 데모를 자기 커뮤니티에 퍼가는 지점이 루프의 출구.
- **측정**: 업종 제보 댓글 수 → 제보→에피소드 전환 수 → 채택 글의 공유·제보자 반응. feedback-loop §4-3이 주간 수집. 태그 `vm=V3`.
- **리스크·상한**: 제보 0건일 때 어색 — 캘린더 D19 규칙(없으면 공방 편) 그대로, "제보가 많다"는 연출 금지(marketing.md §4-1). 데모는 반드시 "샘플 위키 데모" 명시(캘린더 §0-5 정직성 규칙 — 제보 업종이어도 실고객이 아니다).

### V4 — 논쟁각: 원가 해부 (댓글 연료 장치)

- **작동 원리**: challenge family — 반론 가능한 주장이 댓글 논쟁을 만들고, 댓글·체류가 도달을 증폭한다. 빌런은 사람이 아니라 구조("광고비·대행료 한 줄 묶음")로 설정해 저격 리스크를 구조 비판으로 치환(writing.md §4 빌런 원칙).
- **적용 위치**: S3 raw 슬롯(H-29/H-32/H-34 — 전부 raw 라벨, 토요일 검수 게이트 기존 규칙).
- **측정**: growth-log **실험 7**(도달 배율 vs 언팔 비용)이 이 장치의 정례화 여부를 판정한다 — 실험 결과 전 임의 증량 금지. 태그 `vm=V4 exp=EXP-7`.
- **리스크·상한**: 대행업 종사자 반발 → feedback-loop §5 에스컬레이션(논쟁≠항의 구분). 실험 7 판정 전 **월 1회 상한**. 숫자는 공개 출처 병기 필수(hook-bank §0-3).

### V5 — 메타 데모의 공유 유도 (타임스탬프·출고 증거)

- **작동 원리**: 신기성(novelty — "이 계정, AI가 굴린다"는 것 자체가 2026년 이야깃거리: AI 페르소나 계정의 화제성은 캘린더 §1 벤치마크의 Moltbook 사례로 이미 검증) + receipt(새벽 발행 타임스탬프·예약 큐 캡처 = 반박 불가 증거). **사람들은 주장보다 "증거 사진"을 퍼간다** — 캡처는 그 자체로 재공유 가능한 독립 자산.
- **적용 위치**: S1 생산 일지(H-11/H-13/H-14 — 캘린더 D6·D20에 배치). 캡처에는 계정 핸들이 보이게(퍼가도 출처가 남는 자기 서명 구조 — 워터마크의 콘텐츠판).
- **측정**: 리포스트/공유 수, 캡처 글 경유 프로필 방문(G-1·G-2 결합). 태그 `vm=V5`.
- **리스크·상한**: 캡처 없는 메타 주장 = 브랜드 파산(H-11 사용 조건 — 수동 글에 붙이면 거짓). 실제 자동 출고 글에만.

### V6 — "Made with OSMU" 워터마크 (제품 내장 루프)

- **작동 원리**: Powered-by 루프 — 고객(사장님) 채널에 나가는 모든 출고물이 유통 지면이 된다. Calendly는 이 배지로 신규의 25%를 만들었고 루프 1회전이 24h ([flowjam.com](https://www.flowjam.com/blog/viral-loop-examples-saas-the-definitive-playbook-for-engineering-self-sustaining-growth)), Typeform은 신규 80%가 입소문·바이럴 유래([openviewpartners.com](https://openviewpartners.com/blog/typeforms-viral-growth-and-its-disruption/)). 단 워터마크 루프의 K-factor는 0.15~0.3(같은 flowjam 출처) — **단독으로는 안 터지고, 발행량이 쌓일수록 복리로 도는 보조 루프**로 기대치를 고정한다.
- **적용 위치**: gtm-plan 병행 트랙 그대로 — 기능 플래그 기본 off, approve 통과 글에만, 링크 목적지는 랜딩 전=브랜드 계정 / 후=랜딩. 문구 "Made with OSMU" 확정(playbook 미결정 3 해소 상태). 유료 플랜의 제거 옵션은 가격 설계 시점 과제(§4 ⛔).
- **측정**: growth-log **실험 5**(utm 유입 주 3건+ & 인게이지먼트 하락 10% 이내 → 상시 on)가 판정 정본. 태그 `vm=V6 exp=EXP-5`.
- **리스크·상한**: 고객 글에 붙는 서명이므로 고객 브랜드보다 튀면 안 됨 — 본문 끝 1줄, 이모지·과장 금지. 스팸 판정 리스크는 낮으나(텍스트 1줄) 고객 동의 없는 부착 금지 — 온보딩 시 명시 동의 항목으로.

### V7 — 시리즈 이어보기 장치 (프로필 체류 → 팔로우 전환)

- **작동 원리**: 자이가르닉(다음 화 예고 = 열린 고리) + 일관성(연속 기록 자체가 "살아있는 공장" 증거 — H-16 출근부 논리). S1 리포트 구조 ⑤("다음 주 예약분 1줄")가 이미 예고 장치다 — 이 장치는 그걸 **역방향(과거 회차로의 동선)**으로도 완성한다.
- **적용 위치**: ①고정글 = 시리즈 인덱스(S1~S4가 뭔지 + 대표 회차 링크) ②매 리포트에 "지난 리포트" 링크 1줄 ③터진 글(G-1 viral 감지)에는 48h 내 답글로 관련 회차 링크 1개(터진 글의 유입을 시리즈로 회수 — 셀프 답글 도배 금지, 1개만).
- **측정**: 프로필 방문→팔로우 전환율(G-2, growth-log 실험 1과 지표 공유), 고정글 경유 체류. 태그 `vm=V7`.
- **리스크·상한**: 링크 도배 = 스팸 신호. 글당 내부 링크 1개 상한.

### V8 — 공개 성과 페이지 (인용 가능한 단일 URL)

- **작동 원리**: 검증 가능한 투명성(§1 build-in-public 벤치 — 검증 가능한 주장만 공개할 때 신뢰가 확산 자산이 됨) + 인용 유인(실측 숫자가 자동 갱신되는 페이지는 커뮤니티·블로그가 "사례"로 링크한다 — 백링크 = 무광고 유입).
- **적용 위치**: gtm-plan 단계 4(open metrics — 발행 수·채널 수·바이럴 감지·비용 자동 집계) 그대로. 이 문서는 바이럴 관점의 요구 1개만 추가: **페이지에 "이 숫자 인용 시 이 URL을 출처로" 한 줄** (인용 마찰 제거).
- **측정**: 백링크·외부 인용 수(GSC), 성과 페이지→waitlist 전환(gtm-plan §1 단계 4 지표 그대로). 태그 `vm=V8`.
- **리스크·상한**: 수기 갱신 금지(gtm-plan 규칙 — 죽은 대시보드는 신뢰를 역으로 깎는다). 숫자 부풀림·유리한 지표만 노출 = marketing.md §4 위반, 하락 주도 그대로 노출(H-38 정신).

## 4. 레드팀 셀프체크

- **공격 1**: "장치 8개면 계정이 참여 유도 기계처럼 보여 피로감·언팔을 부르지 않나?" → 방어: §3이 동시 가동을 막고(초기엔 사실상 V1~V3·V5뿐), 장치별 빈도 상한(V2 월 2회·V4 월 1회)을 판정 기준과 같은 급으로 박았다. 또한 V1·V3·V5는 독자 관점에서 "유도"가 아니라 정보·데모·증거다 — 참여 요청이 겉으로 드러나는 건 V2·V3의 댓글 질문 한 줄뿐.
- **공격 2**: "워터마크·성과 페이지는 고객·트래픽이 있어야 도는 루프인데 지금은 둘 다 없다 — 서류상 설계 아닌가?" → 방어: 맞다, 그래서 §3이 둘을 5~6순위에 놓고 착수 조건을 기존 정본(실험 5, gtm-plan 단계 4)의 선행 조건에 묶었다. 이 문서의 지금 가치는 1~2순위 장치(제보·캡처·저장·퀴즈)가 발행 첫 주부터 태그 달고 측정되게 하는 것.

⛔ 회수 필요 (회장 결정):
1. **V6 워터마크의 "제거 = 유료 기능" 채택 여부** — Calendly·Typeform 모델의 핵심 수익 연결부인데 가격 설계 사안이라 여기서 못 정함. 하면: 무료 플랜이 유통망이 되고 업셀 지렛대 확보 / 안 하면: 워터마크는 순수 마케팅 장치로만 남음. 추천: 가격 논의 시 기본 채택.
