## 2. Brand Positioning Kit (brand-positioning-kit 스킬 산출)

### 2.1 Core Position
- **one-liner**: "코딩 몰라도 만드는 사람들과, 그들을 끌어주고 싶은 개발자가 만나는 채널 — 운영 절반은 내가 만든 AI가 함"
- **audience**: ①비전공자 바이브코더(막히면 물어볼 사람이 없음, 동기부여 고갈이 최대 이탈 원인) ②사이드로 멘토링/영향력을 원하는 현직 개발자(가르칠 무대가 없음)
- **anti-audience**: 전통 CS 교육 원리주의자, "AI 코딩은 가짜" 논객(단, 논쟁유도 콘텐츠의 연료로는 사용), 단타 수익만 좇는 자동화 어뷰저
- **urgent pain**: 바이브코더 — "80%까진 됐는데 마지막 20%에서 3일째 막힘, 물어볼 사람이 없음". 개발자 — "실력은 있는데 콘텐츠/멘토링 시작이 막막함"
- **hidden desire**: 바이브코더 — 개발자로 인정받고 싶음. 개발자 — 존경받는 선생이 되고 싶음
- **promise**: 혼자 만드는 과정을 전부 공개한다. 성공만이 아니라 막힌 것, 실패한 것, 비용까지.
- **proof**: ①이 계정 콘텐츠의 상당 부분을 내가 만든 자동화(SoloClaw)가 발행함 — 계정 자체가 살아있는 데모 ②지표 정기 공개(팔로워, 발행 수, 절감 시간)
- **enemy/tension**: "코딩은 전공자만" vs "요즘은 AI가 다 해줌" — 둘 다 틀렸다는 제3의 자리. 진짜 적 = 혼자 막혀서 포기하게 만드는 고립.

### 2.2 Tone System
- voice: 동료 반말체 아님, 담백한 평서체+줄임말 혼합. "오늘 이거 만듦. 3시간 날림. 원인은 이거였음" 식. 문장 짧게, 자기연민 없이.
- emotional temperature: 낮은 흥분 + 높은 솔직함. 과장·확신 남발 금지. 자랑은 숫자로만.
- words to use: 만듦/돌아감/막힘/날림/뽑음, 실측 숫자, 도구 실명
- words to avoid: 여러분/~하시죠?/놀라운/혁신적인/게임체인저/꿀팁 대방출, 이모지 2개 이상, 해시태그 도배
- provocative edge: "개발자 안 뽑고 이만큼 함", "국비 6개월 vs 바이브코딩 6주" 같은 비교·논쟁 각. raw 버전은 발행 전 별도 검수.

### 2.3 Messaging Pillars
| pillar | message | proof | content examples |
|---|---|---|---|
| 과정 공개 (build-in-public) | 혼자 SaaS 만드는 전 과정, 실패 포함 공개 | 주간 지표, 에러 스크린샷 | "이번주 날린 시간 11시간, 원인 1줄" |
| AI가 굴리는 계정 (메타 데모) | 이 계정 발행 절반은 자동화가 함 | 발행 로그, 예약 화면 | "이 글 쓴 건 나, 올린 건 AI" |
| 비전공자도 만든다 | 코딩 몰라도 제품은 나옴, 단 막히는 지점은 정해져 있음 | 막힘 사례 아카이브 | "바이브코더가 반드시 막히는 5구간" |

| 지표·돈 공개 | 팔로워/비용/수익 투명 공개 | 대시보드 캡처 | "자동화 월 비용 전부 공개함" |

  > 콘텐츠 공장 돌리는 중. 이 글도 공장에서 나옴. 공장 만드는 과정 공개함

  >

  1. 공장일지 — 라인 증설/사고/개선 기록 (일상+통찰)
  2. 생산품 품평 — AI가 뽑은 콘텐츠 공개 검수 (반응파악)
  3. 라인 설계도 — 자동화 구조·도구 해설 (정보성)
  4. 원가 공개 — 콘텐츠 1개당 비용 실측 (통찰)
  5. 공장 vs 장인 논쟁 — "AI 콘텐츠는 공해인가" (논쟁유도)
- **두 목표 연결**: 제품 데모가 곧 콘텐츠라 SaaS 전환은 최단거리. 멘토링 커뮤니티는 "공장 짓는 법 알려줌" 각도로 연결 (단, 3안 중 가장 간접적).

## 4. 추천안 + steelman

### 추천: **안 1 — 빌드로그 SJ**

이유:
1. **기존 자산과 정합**: IG 2,390 팔로워는 사람을 팔로우한 것 — 사람 계정 리브랜딩이 이탈 최소. 커뮤니티/제품명 계정으로 갈아타면 기존 팔로워 맥락이 끊김.
2. **두 타겟을 한 서사로**: "비전공자인 내가 만들며 막히고 뚫는 과정" 자체가 바이브코더에겐 자기투영, 개발자에겐 훈수(=멘토링 본능) 유발 장치. 벤치마크(levelsio, 조코딩)에서 검증된 구조.
3. **미래 유연성**: 커뮤니티 이름도 SaaS 최종 이름도 미확정(SoloClaw는 가칭, vision.md). 사람 브랜드는 그 밑에서 뭘 런칭하든 안 깨짐. 안 2·3은 이름 확정 리스크를 계정이 짊어짐.
4. **메타 훅 흡수**: 안 3의 최강 무기("이 계정은 AI가 굴림")를 안 1의 필러 3으로 그대로 흡수 가능 — 안 3을 버리는 게 아니라 품는 구조.

### steelman (나머지 안의 가장 강한 논거)
- **안 2가 옳은 경우**: 최종 목표가 명확히 "플랫폼"이라면, 커뮤니티 브랜드는 일찍 심을수록 복리다. 노마드코더가 증명한 경로고, 사람 계정은 나중에 플랫폼으로 팔로워를 옮기는 비용(전환 손실 20~40% 통상)을 반드시 치른다. 지금 2,390명일 때 갈아타는 게 20,000명일 때보다 싸다.
- **안 3이 옳은 경우**: SaaS 판매가 1순위 KPI라면 데모의 힘이 서사의 힘을 이긴다. "이 계정이 자동으로 굴러간다"는 것 자체가 반박 불가능한 세일즈고, 공장 세계관은 숏폼 시대에 시각적으로 가장 차별적이다. 안 1의 빌드로그는 이미 레드오션(수천 명이 함)이지만 "공장 견학" 컨셉은 비어 있다.

### 셀프심문 (CoVe) — "이 추천이 틀렸다면 왜?"
- **Q1. 사람 브랜드는 회장 시간을 잡아먹지 않나? 자동화 SaaS와 모순 아닌가?** → 일부 맞음. 얼굴/일상 노출 부담이 있음. 다만 안 1의 필러는 대부분 지표·로그·해부 콘텐츠라 자동화 생성 적합 — "사람 서사의 껍데기 + 자동화 본문" 구조로 상쇄됨. 이 반박을 반영해 필러 1(주간 빌드로그)만 수동, 나머지는 자동화 가능하게 설계했음.
- **Q2. "발행 절반은 AI가 함"을 bio에 박으면 팔로워가 정 떨어지지 않나?** → 리스크 실존(AI 콘텐츠 피로감). 그러나 숨기다 들키는 것이 최악이고, 선공개는 오히려 제품 증거가 됨. safer 버전: bio에서 빼고 고정글로만 공개. raw 버전(bio 명시)을 기본 추천하되 반응 보고 조정 — 이건 발행 후 A/B 가능한 가역 결정.
- **Q3. IG 2,390 팔로워가 기존에 뭘 보고 팔로우했는지 모른 채 "이탈 최소"라고 단정할 수 있나?** → 못 함. (unsourced) 기존 팔로워 유입 맥락 데이터 없음 — 만약 기존 계정이 전혀 다른 주제였다면 안 2(새 브랜드) 신설이 나을 수도. 회수 필요에 등재.
- **Q4. 핸들이 다 선점돼 있으면?** → 각 안에 후보 2~3개를 뒀지만 가용성 미확인. 확인 전까지 이름 확정 불가. 회수 필요에 등재.

### 레드팀 1회 (회의적 투자자 관점 공격)
"빌드로그 계정은 널렸다. levelsio 아류가 한국에만 수백 개고 대부분 팔로워 1천에서 멈춘다. 네 차별점이 뭐냐?" → 방어: 차별점은 빌드로그가 아니라 **계정 자체가 제품의 가동 증명**이라는 메타 구조(필러 3)와, 멘토-멘티 양방향 타겟 설계(통상 빌드로그는 빌더만 봄). 이 두 개가 없으면 공격이 맞다 — 그래서 필러 3과 "막힌 거 물어봐도 됨" 창구를 bio 레벨에 박았음. 이 공격을 견디도록 안 1의 bio에서 "과정 공개"보다 "AI가 발행함" 훅의 비중을 올려 수정 완료.

## 5. 비주얼 디렉션 브리프 (디자이너 핸드오프용)

### 5.1 컬러 팔레트
| 역할 | hex | 용도 |
|---|---|---|
| Base (dark) | `#0B0F1A` | 배너·썸네일 기본 배경 (터미널/심야작업 무드) |
| Surface | `#151B2B` | 카드뉴스 배경, 썸네일 패널 |
| Accent (primary) | `#F59E0B` (amber) | 훅 텍스트, 숫자, 로고 포인트 — "가동 중인 공장 불빛" |
| Accent (sub) | `#34D399` (mint) | 성공/지표 상승 표시, 터미널 그린 무드 |
| Text | `#F8FAFC` / `#94A3B8` | 본문 화이트 / 보조 그레이 |
- 규칙: 한 아트웍에 accent는 1색만. amber=훅/행동, mint=데이터. 라이트 배경 변형은 카드뉴스에서만 (`#F8FAFC` 배경 + `#0B0F1A` 텍스트).

### 5.2 타이포 무드
- KR: **Pretendard** (Bold/ExtraBold — 훅), Regular — 본문
- 숫자·코드·로그 느낌: **JetBrains Mono** (지표, 파일명, 날짜에만)
- 무드: 기술적이되 차갑지 않게. 손글씨/세리프 금지. 자간 타이트, 좌측 정렬 기본.

### 5.3 로고 컨셉 2개
1. **커서 블록 모노그램**: "SJ" 뒤에 터미널 커서(■, amber) — "아직 입력 중 = 계속 만드는 중"이라는 build-in-public 은유. 소형(프로필 원형)에서도 생존.
2. **로그 라인 마크**: `> sj` 프롬프트 형태 워드마크 — 프로필·워터마크·썸네일 코너 뱃지로 동일 사용. (안 3 채택 시: 발톱/집게 모양을 컨베이어 라인 위에 얹은 팩토리 마크로 대체)

### 5.4 프로필 이미지 방향
- 3플랫폼 동일 이미지 (통일이 최우선).
- 1순위: 반신 실사진 — 심야 작업 무드(dark base 배경, amber 림라이트), 카메라 안 보고 화면 보는 컷. levelsio/조코딩 패턴 = 얼굴이 팔로우 전환을 올림.
- 얼굴 노출 기피 시 폴백: 로고 컨셉 1(커서 모노그램)을 amber on `#0B0F1A`로.

### 5.5 배너 레이아웃 (YouTube 2560×1440, safe zone 1546×423)
- safe zone 안에만: 좌측 60% = 태그라인(7~12단어, Pretendard ExtraBold, 2줄 이내) + 업로드 요일 한 줄(JetBrains Mono, mint). 우측 40% = 대시보드/터미널 스크린샷을 15° 기울여 배치.
- 배경: `#0B0F1A` + 미세한 그리드 패턴(2% 불투명). 이모지·장식 아이콘 금지.
- 동일 아트웍을 IG 하이라이트 커버·Threads 프로필 링크 카드에 변형 적용.

### 5.6 YouTube 썸네일 템플릿 규칙
1. 배경 `#0B0F1A` 고정, 좌측 정렬 훅 텍스트 최대 3줄·12자/줄.
2. 숫자는 amber + JetBrains Mono로만 강조 ("11시간 날림", "월 4만원").
3. 우측 1/3 = 얼굴 컷 또는 화면 캡처(둘 중 하나만, 겹침 금지).
4. 하단 좌측 코너에 `> sj` 뱃지 고정 (시리즈 인지 장치).
5. 시리즈별 상단 컬러바: 빌드로그=amber / 막힘해부=mint / 논쟁=화이트.
6. 텍스트-배경 대비 4.5:1 이상, 모바일 168px 축소에서 훅 판독 가능해야 통과.

## ⛔ 회수 필요 (회장 결정·확인 사항)
1. **핸들 가용성**: 각 안의 핸들 후보를 Instagram/Threads/YouTube에서 실제 검색해 선점 여부 확인 필요 (에이전트가 로그인 상태 확인 불가). 확인 후 이름 확정.
2. **기존 IG 2,390 팔로워의 유입 맥락**: 기존 계정이 어떤 콘텐츠로 팔로워를 모았는지 — 주제가 지금과 다르면 리네임 대신 신규 계정(안 2)이 유리할 수 있음.
3. **얼굴 노출 범위**: 프로필/썸네일에 실사진 쓸지, 로고 폴백으로 갈지.
4. **"발행 절반은 AI가 함" bio 명시 여부**: raw(명시) vs safer(고정글만) — 추천은 raw이나 브랜드 안전 결정은 회장 몫.
5. **업로드 요일 확정**: 배너에 박을 요일 (안 1 기준 "매주 목요일"은 가안).
