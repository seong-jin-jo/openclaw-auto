# ADR-005: 제품명 OSMU(오스무) 확정 · 계정 브랜드 = 콘텐츠 공장 "OSMU 팩토리" (사장님 done-for-you)

- 상태: **Accepted — 전체 확정** (컨셉·타겟·표시 이름·핸들 우선순위·v1 채널 범위·계정 셋업 주체·DM 정책 전부 확정. 남은 것은 회장의 물리적 실행뿐 — naming.md §5)
- 날짜: 2026-07-10 최초 · 2026-07-11 개정(계정 방향 전환) · 2026-07-16 개정(표시 이름·핸들·채널 범위·DM 정책 확정) · **2026-07-16 재개정(워딩 비서→공장, "OSMU 팩토리" 낙점)**
- 결정자: Fable 5 수렴 + 회장 컨펌(2026-07-10~11) · 회장 최종 낙점(2026-07-16, 동일자 "오스무 비서" 확정을 후속 지시로 대체)

## 맥락

- 제품명이 "가칭 SoloClaw"로 방치돼 랜딩·카피·하위모델 작업 전반에 이름 구멍이 있었다.
- 계정 아이덴티티는 2026-07-07 브랜드킷이 3안 제안 후 회장 미결정으로 정체 → 2026-07-10 Fable이 "빌드로그 SJ"로 확정 시도했으나 **회장 veto**("말같지도 않은 브랜드").
- 근본 원인 = 브랜드킷이 개발자·바이브코더 build-in-public 각도로 드리프트해, 제품의 실제 타겟(자영업자·사장님, done-for-you)과 어긋난 페르소나를 만든 것.

## 결정

1. **제품명 = OSMU(오스무)** — SoloClaw 기각(soloclaw.dev 선점, 2026-07-10 실조사). 내부 정본 이름 계승 + "원소스 멀티유즈" = 제품 기능 = 카테고리 검색어. 상표 방어력 낮음은 수용된 리스크.
2. **계정 브랜드 = 콘텐츠 공장** — 사장님(자영업자·1인 대표)이 공장을 대여한 것처럼 느끼는 done-for-you 브랜드. 계정=제품(OSMU)의 시설화, 계정 자체가 출고 라인 = 살아있는 데모. 얼굴 비노출(공장=시설 인격). 어휘 = 출고/생산/라인/가동/리포트. (경위: 07-11 "비서"로 확정 → **07-16 회장 재지시 "비서보다 공장 워딩"** — done-for-you 본질·타겟은 동일, 은유·어휘만 교체.)
3. **타겟 전환**: 개발자·바이브코더·멘토링 커뮤니티(직접 만드는 사람) → **사장님·자영업자(맡기는 사람)**. vision.md 제품 타겟과 정렬.
4. **표시 이름 = "OSMU 팩토리" — 2026-07-16 회장 직접 낙점(프리뷰 3안 중 선택).** 하드코딩 가능(문서·카피 전반). 동일자 앞선 "오스무 비서" 낙점은 본 결정으로 대체.
5. **핸들 우선순위 확정**: 1순위 `@osmu.official`, 확보 실패 시 2순위 `@osmu.factory`(구 @osmu.secretary는 워딩 전환으로 폐기). 실가용은 리네임 화면에서 회장이 직접 확인·실행.
6. **v1 채널 범위 = Instagram + Threads만. X 제외.** 이유: 기존 자산(IG 팔로워 2,390 + Threads Live) 재사용이 가장 빠른 경로, 리소스 집중.
7. **계정 셋업·리네임 실행 = 회장 수동 전용, 자동화 절대 금지 재확인.** 2026-07-01 Meta 개발자 계정 자동 운전 플래그 이력(ADR-004) — 동일 계정군 재시도 리스크 회피.
8. **DM 자동화 정책 확정**: 콜드 발송·대량 발송(cold/bulk outreach) 전면 금지. 허용 범위는 인바운드 문의 응대, 명시적 요청 후 댓글→DM 전환, 기존 지인(warm contact) 개별 연락, 후속(follow-up), 수신거부 처리뿐 — 전부 사람 승인 게이트 통과. 상세 = [marketing/dm-playbook.md](../marketing/dm-playbook.md).
9. 상세·조사 로그·표기 규칙·이름 계층 = [marketing/naming.md](../marketing/naming.md) (정본).

## 결과

- 모든 마케팅 문서·카피·에셋·하위모델 브리프는 naming.md를 참조 — 이제 "OSMU 팩토리" 문자열을 직접 써도 된다(하드코딩 금지 해제).
- 재캐스케이드 이력: 빌드로그→비서(2026-07-11~12 완료) → **비서→공장(2026-07-16 진행)** — hook-bank·content-calendar·channels·creative-briefs·landing-copy·launch-pack·dm-playbook·social-launch-v1.json 전부 공장 워딩으로 재전파 대상(발행 전 draft라 실계정 영향 0).
- vision.md "상품 이름" 절은 본 ADR을 가리킴. positioning.md("브랜드 위키를 아는 콘텐츠 자동화")는 비서 컨셉과 정합 → 유지.
- 2026-07-16 launch-pack 실행 산출물: [marketing/launch-pack-2026-07-16.md](../marketing/launch-pack-2026-07-16.md)(프로필·초안 큐), [marketing/dm-playbook.md](../marketing/dm-playbook.md)(DM 운영 규칙), [marketing/social-launch-v1.json](../marketing/social-launch-v1.json)(기계판 큐 — 전부 `status: draft`, `requires_manual_approval: true`).
- 도메인 등록·계정 리네임 물리적 클릭 = 여전히 회장 실행 항목(naming.md §5) — 이 ADR과 하위 문서는 그 실행에 필요한 모든 문안·규칙을 확정 상태로 준비해둔 것이지, 실행 자체를 자동화하지 않는다.
