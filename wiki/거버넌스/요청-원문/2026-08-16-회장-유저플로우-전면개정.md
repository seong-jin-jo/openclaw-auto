# 회장 요청 원문 (2026-08-16) — 유저플로우 전면 개정

kind: chairman-request
status: 정본. PRD·유저플로우·프로토타입은 이 요청을 기반으로 확장한다. 대체하거나 무시하지 않는다.

## 원문

- 대행 캠페 4/14 이렇게 왼쪽 사이드에서 클릭할때마다 모달이 뜨는데 이게 뭐냐니까? 01 02 04 05 06 누르면 이상한 모달이 뜬다고. 03은 첫로그인 빈성과라는데 성과가 또 왜있고? 지금 존나게 대충만들었지?
- 프로토타입이 좀 이상한데 생성할 때 한 화면에 하나씩 선택해서 프롬프트를 만들 정보를 만들어내고, 그다음 어느 플랫폼에 발행할건지 선택하고, 초안 생성하면 A/B/C안 나오고, 그중에 선택해서 바로 올릴지 다른 안이나 퀄리티 높여볼지 결정하고, 그렇게 최종 출력물이나오면 텍스트 이미지 영상 각플랫폼 별로 실제 미리보기 하면서 편집하고, 최종적으로 publish 하는거지.
- 자기 학습정보는 화면에서 언제든 볼 수 있고 수정도 할 수 있고, 이미 한 번이상 생성해서 정보가 있으면 다음에 생성할땐 학습입력 단계를 건너뛰거나 수정할수도 있을거고.
- 위키나 노션같은 자료도 입력해서 학습시킬수 있고 원본을 넣어서 비슷한결로 학습시킬수도있고.
- 유저가 직접 필요할때 들어가서 추가수정할수도 있고 혹은 A/B/C 선택할 때 자동으로 (이 취향을 학습하시겠습니까? 이런식으로 동의) 혹은 플랫폼에서 가끔씩 던지는 추천 질문들 혹은 성과나 핫트렌드 같은게 추천으로 들어가서 이런류의 컨텐츠를 생성하겠냐고 물어볼수도있고.
- 지금은 각 선택 화면이 복잡하고 user flow가 고려가 안된거같아. 처음 회원가입했을때부터 학습정보가 아무것도 없을때 플로우, 그다음 두번째 생성할때의 플로우, 또 추가정보를 입력시키거나 추천받고싶을떄 플로우 등이 있어야지.
- 발행후 각플랫폼 직접들어가서 보거나, OSMU에서 성과를 종합관리하거나, 각 플랫폼 탭해서 성과나 세팅을 보거나.
- 특히 플랫폼별로 헤더에 옵션이 일관적이지 않아서 이것도 맞춰줘야하고. 불필요한 옵션기능이 있는지없는지도 보고.
- 그냥 만드려고하지말고 유저플로우생각해서 깊게 만들어봐. 거의 다 갈아엎어야돼 지금.

## 이 요청에서 확정되는 것

### 제작 흐름 (한 화면에 하나씩)

1. 프롬프트를 구성할 정보를 한 화면에 하나씩 선택해 만든다
2. 어느 플랫폼에 발행할지 선택
3. 초안 생성 → A안 B안 C안 제시
4. 하나를 고른 뒤 판단: 바로 올릴지 / 다른 안을 볼지 / 품질을 높일지
5. 최종 출력물이 나오면 텍스트·이미지·영상을 **플랫폼별 실제 미리보기**로 보면서 편집
6. publish

### 학습 정보 (취향 프로파일)

- 화면에서 언제든 열람하고 수정할 수 있다
- 이미 생성 이력이 있으면 다음 제작에서 **학습 입력 단계를 건너뛰거나 수정**할 수 있다
- 입력 경로 네 가지: 사용자가 직접 수정 / 위키·노션 같은 외부 자료 반입 / 원본을 넣어 비슷한 결로 학습 / A·B·C 선택 시 동의를 받아 자동 학습("이 취향을 학습하시겠습니까?")
- 추천 유입 경로 세 가지: 플랫폼이 가끔 던지는 질문, 성과 기반 제안, 핫 트렌드 기반 제안. 모두 "이런 류의 콘텐츠를 생성하겠냐"고 묻는 형태

### 반드시 존재해야 하는 플로우 갈래

- 처음 회원가입해서 학습 정보가 하나도 없을 때
- 두 번째 이후 제작할 때(학습 정보가 있을 때)
- 추가 정보를 넣거나 추천을 받고 싶을 때
- 발행 후: 각 플랫폼에 직접 들어가서 보기 / OSMU에서 성과를 종합 관리 / 각 플랫폼 탭에서 성과와 설정 보기

### 일관성 요구

- 플랫폼별 헤더 옵션이 제각각이면 안 된다. 통일한다
- 불필요한 옵션 기능이 있는지 점검하고 정리한다
