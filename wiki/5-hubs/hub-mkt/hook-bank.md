# Hook Bank — 후킹 문장·제목 뱅크 정본

**갱신: 2026-07-16 (워딩 전환: 비서→공장 "OSMU 팩토리")** · 작성: content-growth-marketer (hook-angle-lab 스킬 + WebSearch 벤치마크)
이름·핸들·표기는 [naming.md](../../1-team-brand/naming.md), 톤·필러는 [brand.md](../../1-team-brand/brand.md)가 진실원. 이 파일은 **후크 원문의 유일한 참조 뱅크** — 하위모델은 여기 번호(H-XX)로 참조·변형한다.

> ⚠️ 워딩 이력(각주): 2026-07-11 구 개발자 타겟(빌드로그) 후크 폐기 → "AI 콘텐츠 비서" 각도 → **2026-07-16 콘텐츠 공장 "OSMU 팩토리" 어휘(출고/생산/라인/가동/주간 리포트)로 재전환**. 번호 체계(H-01~45)·family·심리축·raw/safer 라벨·{N} 규칙은 그대로 유지 — 후크 원문의 어휘·화자 층만 교체됐다. **구판(비서판) H-번호를 참조해 이미 생성된 큐 초안은 재사용 금지 — 전부 이 판 기준으로 재생성.**

## 0. 하위모델 사용 규칙 (필독)

1. **번호 참조**: 캘린더·브리프가 "H-24 변형"이라 하면 → 해당 후크의 **family·감정·구조를 유지**하고 소재·숫자만 바꾼다. 구조를 바꾸면 변형이 아니라 신규다(신규는 이 파일에 append 후 사용 — append는 상위모델 몫).
2. **risk 라벨**:
   - `safer` = 자동 발행 큐에 바로 넣어도 됨(사람 approve는 기존 큐 규칙대로).
   - `raw` = **발행 전 별도 검수 필수** — 큐에 넣되 status를 draft로 유지하고, 회장(또는 메인세션)의 명시 승인 없이 approved로 올리지 않는다. 논쟁각·대행업계 저격·가격 비교·(unsourced) 주장이 여기 속한다.
3. **숫자 placeholder**: 후크 안의 `{N}`, `{X}` 는 **실측 숫자로만 치환**한다. 실측이 없으면 그 후크는 못 쓴다 — 다른 후크로 대체. 추정치 발행 금지 (brand.md "자랑은 숫자로만"). **예외 절차**: 시장 가격류(대행비 등)는 실측 대신 **공개 출처 병기**(크몽·아이보스 등 공개 거래 데이터)로 대체 가능 — 출처 없는 시장 숫자는 금지.
4. **톤 체크 (발행 전 3초 검사)**: ①"여러분/놀라운/혁신적인/게임체인저/꿀팁" 포함? → 폐기 ②굽신 콜센터 톤("고객님~", 과잉 존대·과잉 사과)? → 담백한 출고 리포트체로 재작성 ③이모지 2개 이상? → 1개 이하로 ④숫자 없는 자랑? → 숫자 넣거나 자랑 삭제.
5. **첫 줄 원칙** (벤치마크 근거): Threads 알고리즘은 첫 줄 dwell time을 본다 — 첫 줄에 숫자·의외성·질문 중 하나를 반드시 배치. 숫자형 첫 줄이 일반 서술 대비 dwell 약 3배 (threadsauto.kr 2026 관찰 — 외부 소스, 우리 실측으로 재검증 예정 → growth-log 실험 4).
6. **공장 리포트체 원칙**: 계정 페르소나 = 사장님이 대여한 콘텐츠 공장 **"OSMU 팩토리"** ([naming.md](../../1-team-brand/naming.md) §2 — 표시 이름 확정, 하드코딩 가능). 화법 = **주어 절제 리포트체**("오늘 출고 3건. 반응 1위 이 글. 내일 라인 2건 예약.") — 1인칭 "저/제가"(구 비서체)는 쓰지 않고, 자칭이 필요할 때만 "OSMU 팩토리"(제품 언급은 "OSMU(오스무)"). 정중 종결("~올려뒀습니다")과 담백 줄임말체(~임/~됨) 혼용 OK. **굽신거림 금지 — 신뢰는 말투가 아니라 출고 기록·숫자로 증명.**
7. **family = 심리 장치 명명** ("법칙 이름 없는 장치 = 뇌피셜" 차단): receipt=증거 우선(신뢰=성과−기대) / curiosity gap=자이가르닉(잠긴 정보) / comparison=앵커링·대조 / reversal=에피파니 재프레임("네 탓이 아니라 X 때문") / forbidden truth=금기·내집단 결속 / identity=정체성 부여 / self-diagnosis=메타인지 필터 / confession=고백→독자 신뢰 전환 / challenge=논쟁 유도(반응 단계) / affinity=공감 폭격(PASONA의 A) / mistake=손실 회피. 변형 시 이 심리 축까지 유지해야 "변형"이다.

## 7. 피해야 할 패턴 (폐기 기준)

- "…하는 법 N가지 (총정리)" 류 무기명 리스티클 톤 — 우리 것은 반드시 1인칭 실측·실보고.
- 질문으로만 끝나고 근거 없는 낚시 ("과연 어떻게 됐을까요?").
- 성공 서사 선행형 ("드디어 해냈습니다") — 숫자 없이 감정만 있는 자랑.
- **굽신 콜센터 톤** ("고객님~ 도와드리겠습니다!") — 공장의 신뢰는 말투가 아니라 출고 기록·숫자 (brand.md §4).
- **1인칭 비서체 회귀** ("저는 ~합니다" 남발) — 2026-07-16 워딩 전환으로 폐기. 기본은 주어 절제 리포트체, 자칭은 "OSMU 팩토리"만.
- **사장님 훈계 톤** ("사장님들이 몰라서 그러는데") — 적은 사장님이 아니라 시간 압박과 헛소리 쓰는 대행/AI (brand.md §3).
- 금지어 5종 (brand.md): 여러분 / 놀라운 / 혁신적인 / 게임체인저 / 꿀팁 대방출.
- raw 후크를 safer 검수 없이 자동 발행 — 위 §0.2 규율 위반, 발견 즉시 큐에서 회수.
