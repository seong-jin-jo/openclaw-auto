## 2. Bio 확정 전문 (소개 필드 255자 한도 — 벤치마크 확인 2026-08-24)

Facebook 페이지 소개(bio) 한도 255자. 아래 전문 약 130자.

```
사장님 콘텐츠를 만들어 매일 출고하는 콘텐츠 공장, OSMU 팩토리. 브랜드 사실을 읽고 쓰니 헛소리 없음. 이 페이지도 이 공장 라인에서 출고됨. 매주 목요일 주간 리포트로 출고 건수·반응·비용 공개. 콘텐츠 맡길 공장이 필요한 사장님은 아래 버튼으로.
```

- 구조 = 정체(공장) → 하는 일 → 차별화(그라운딩) → 메타 데모("이 페이지도 이 공장 라인") → 지표 공개 → CTA. [근거: 성공하는 Facebook 비즈니스 페이지 bio 공통 골격 = "who you help + what you do + one CTA, bio는 About·버튼으로 착지시키는 진입점" — socialpilot.co / postful.ai 2026 가이드. IG bio(90자)보다 길게 허용된 한도를 지표 공개 문장으로 활용해 차별화. 문구 복붙 없음]
- IG/Threads bio(90자)보다 **약간 더 설명적** 허용(§5 톤 오버라이드) — 단 광고체·과장 금지, 리포트체 유지.

### 상세 정보 필드 (About 섹션 — 페이지 특유)
| 필드 | 값 |
|---|---|
| 카테고리 | **1순위 "광고/마케팅 서비스"** (사장님이 대행을 찾는 검색 맥락과 정합), 부가 "소프트웨어 회사" 병기 가능 — 최종 선택은 ⛔ 회수 |
| 웹사이트 | (랜딩 전) 티스토리 블로그 URL → (완성 후) `osmu.kr` |
| 연락처 | 공용 이메일 노출 여부는 회장 판단(스팸 유입 vs 인바운드 편의). 기본은 **DM/문의 버튼으로 수렴**, 이메일 비노출 권장 |
| 영업시간 | "항상 영업 중"(자동화 공장 컨셉과 정합) 또는 미설정 |

### 페이지 CTA 버튼 (페이지 특유 — 반드시 1개만 설정)
- **랜딩 완성 전**: **"더 알아보기"(Learn More)** → 블로그 소개글. (근거: CTA는 목표 1개로 좁혀라 — "want most action 하나만" socialrails.com 2026. 랜딩·결제 경로가 없는 단계에서 "가입하기"는 착지점이 비어 이탈.)
- **랜딩 완성 후**: **"가입하기"(Sign Up)** → `osmu.kr` waitlist (전용 랜딩으로, 홈이 아니라 신청 페이지로 직착지).
- **"메시지 보내기" 버튼**은 DM 인바운드가 열리는 것이다. [dm-playbook.md](../dm-playbook.md)의 인바운드·승인 게이트 정책 안에서만 허용하고 콜드 대량 발송은 금지한다(§9).

## 3. 고정글 전문 (페이지 상단 고정 게시물 1개)

Facebook 페이지는 게시물 1개를 상단 고정 지원. 발행 후 고정한다. 페이지 게시물은 글자 제한이 사실상 넉넉(카드뉴스/링크 첨부 가능) — 아래 전문 약 420자.

**정본 (그대로 발행):**

```
개업 인사 대신 가동 안내를 올립니다.

여기는 사장님의 콘텐츠 공장, OSMU 팩토리입니다. 하는 일은 하나 — 사장님이 장사에 집중하는 동안 SNS 콘텐츠를 만들고, 채널마다 맞게 고치고, 올리고, 반응까지 리포트로 보고합니다.

일반 AI·대행과 다른 점: 사장님 브랜드 위키(가격·메뉴·말투·하면 안 되는 말)를 읽고 씁니다. 지어내지 않습니다.

이 페이지도 이 공장 라인에서 출고됩니다. 공장이 제대로 도는지 궁금하면 이 페이지가 꾸준히 올라오는지만 보면 됩니다.

출고되는 것:
- 매주 목요일 주간 리포트 (출고 건수·반응 1위·비용 실측)
- 사장님 SNS 고민 대신 정리
- 출고 로그·지표 공개

콘텐츠 맡길 공장이 필요한 사장님은 페이지 버튼으로 문의 주세요. 지금은 공개 베타 운영 중입니다.
```

(CTA는 threads.md·instagram.md 정합 — "문의·공개 베타"로 통일. Facebook은 "페이지 버튼으로"가 착지점.)

**대안 (raw provocative — 반응 실험용):**

```
사장님, 솔직히 그 시간에 장사하시는 게 낫습니다.

가게 페이스북 붙잡고 캡션 쓰는 1시간 — 그 시간의 원가를 계산해 본 적 있으세요? OSMU 팩토리는 그 일을 대신하려고 지어진 콘텐츠 공장입니다. 만들고, 올리고, 반응까지 리포트합니다.

못 믿겠으면 이 페이지를 보면 됩니다. 여기 올라오는 글, 이 공장에서 출고됩니다. 매주 목요일 주간 리포트로 숫자까지 깝니다.

맡겨보고 싶으면 페이지 버튼으로.
```

risk label: 대안은 "그 시간에 장사하세요" 훈수 톤 — 사장님 자존심 자극 리스크. 정본으로 시작, 4주 후 반응 보고 교체 검토. (threads.md §3 대안과 동일 리스크 라벨 계승.)

## 4. 업로드 케이던스 (목요일 축 유지 — IG 크로스포스트 기반)

| 요일 | 슬롯 | 형태 |
|---|---|---|
| 목 | **주간 리포트 (축)** | 카드뉴스 이미지 + 페이지 게시물 본문(출고 건수/반응 1위/비용). 페이지는 IG보다 본문을 길게 허용 → 리포트 상세를 캡션에 풀어 쓴다 |
| 월 | 사장님 pain 공감 | IG 카드뉴스 크로스포스트 + 페이지 본문(설명적 확장 허용) |
| 토 | 가벼운 컷 | 출고 로그·예약 큐·대시보드 실화면 (필러 2·5) |

- 주간 총 2~3게시물. IG 제작분을 페이지 규격으로 재활용(제작 부담 최소 원칙) — 단 **캡션은 페이지 톤(§5)으로 재작성**, IG 캡션 그대로 복붙 금지(첫 125자 접힘 규칙이 페이지엔 없어 문장 구조를 다르게).
- 페이지 게시물은 링크 첨부 시 도달 저하 경향(unsourced — 보수 운영 원칙) → 링크는 첫 댓글에, 본문은 이미지+텍스트 위주.
- 크론 연결: 현재 multi-channel-publish에 Facebook publish extension 연동 여부 확인 필요(⛔ 회수). 연결 전까지 수동 승인 발행.

## 5. 톤 오버라이드 (공통 톤 대비 이 채널만)

- **IG보다 약간 더 설명적 허용.** 페이지 게시물은 접힘·글자수 압박이 적어 리포트를 문장으로 풀 여지가 있다 — 단 "설명적"이 "장황"이 되면 안 된다. 여전히 리포트체("~했습니다/출고했습니다"), 주어 절제.
- 첫 문장이 훅인 건 동일 — 페이스북은 "더 보기" 접힘이 있어 첫 2~3줄 안에 정체+훅.
- 논쟁유도(필러) 각은 페이스북 특유의 댓글 확산과 정합하나, 사장님 자존심 자극선은 §3 대안 리스크 라벨 준수.
- 공통 금지어 유지: 여러분 / 놀라운 / 혁신적인 / 게임체인저 / 꿀팁 대방출. 이모지 0–1개. 굽신 콜센터 톤 금지. AI 티 금지.

## 6. 콘텐츠 유형 매핑 (필러 5 × Facebook)

| 필러 (brand.md §5) | Facebook 형태 |
|---|---|
| 1. 대신 만들어 출고 | "오늘 사장님 채널에 출고된 콘텐츠" 리포트 게시물 + 예약 큐 캡처 |
| 2. 이 계정도 공장이 굴림 | "이 페이지 게시물도 이 라인에서 출고됨" + 출고 로그 타임스탬프 캡처 |
| 3. 브랜드 사실을 안다 | 전후 비교 게시물 (일반 AI 헛소리 vs 위키 그라운딩 문장 — 페이지 본문에 상세 서술) |
| 4. 시간·돈을 아낀다 | 비용 비교 카드 ("대행 건당 32만원 vs 공장 월 가동비 — 실측") — 댓글 유도 |
| 5. 지표 공개 | 목요일 주간 리포트 게시물 (본문 상세 + 이미지 지표 캡처) |

## 7. 태그/키워드 세트

Facebook 페이지는 해시태그 확산 효율이 IG보다 낮음(unsourced — 보수 운영). **글당 1~3개, 도배 금지.**

기본 풀 (주제 맞는 1~3개만): `#자영업` `#소상공인` `#사장님` `#가게마케팅` `#SNS마케팅` `#마케팅자동화` `#콘텐츠자동화` (7개 풀에서 선택). 페이지 검색·SEO는 해시태그보다 **카테고리 정확도 + About 필드 완성도**가 더 큰 레버(§2 상세 정보).

## 9. 금지 사항 (채널 리스크)

- **Meta 콘솔·계정 설정 자동 운전 금지** — 2026-07-01 실제 사고: GStack 브라우저 자동 운전 중 Meta 개발자 계정 플래그(봇 탐지, 액세스 차단). [ADR-004](../../../3-operations/decisions/004-social-connect-oauth-not-passwords.md) 확정. 페이지 생성·이름·카테고리·CTA·권한 설정은 회장이 손으로, 발행은 공식 API 토큰으로만.
- 비밀번호 기반 자동 로그인·비공식 API 금지 (Meta ToS 위반 — 계정 정지 사유).
- 페이지 CTA "메시지 보내기"로 열린 DM은 인바운드·승인 게이트 정책 안에서만 허용한다([dm-playbook.md](../dm-playbook.md)). 콜드·대량 발송은 금지한다.
- 개설 직후 대량 자동 발행 금지 — 신규 페이지 + 발행 패턴 급변은 스팸 시그널 리스크(unsourced — 보수 운영). 첫 2주 수동 승인 발행만.
- 얼굴(실사진) 사용 금지 — 비노출 확정(naming.md §2). 프사·커버 전부 심볼/화면 캡처만.
- 사람인 척 금지 — AI 자동화 공장임을 bio·고정글에 명시. 투명성 = 컨셉의 핵심 자산.
- 코드·커밋에 브랜드명 금지 (공통 레포 정책) — 브랜드 지식은 wiki에만.
