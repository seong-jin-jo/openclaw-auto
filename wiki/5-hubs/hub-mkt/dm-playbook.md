# DM Playbook — OSMU 팩토리 Instagram+Threads DM 운영 정본

**갱신: 2026-07-16(품질게이트 재작업 + 워딩 전환: 비서→공장 "OSMU 팩토리" — 표기 2건만 교체, 정책 내용 무변경)** · 최초 결정일 2026-07-14 · 출시일 2026-07-16 · 작성: content-growth-marketer (openclaw-creative-brief 스킬) · 정본 계층: [naming.md](../../1-team-brand/naming.md) §2, [ADR-005](../../3-operations/decisions/005-brand-naming.md), [brand.md](../../1-team-brand/brand.md) 톤.

**v1 운영 전제**: 수동 승인·수동 발송(크론은 초안까지만, 발송 버튼은 사람). 실제 서비스 진입 경로는 **공개 베타 가입**이며, 대기명단·대기자 등록 같은 "지금 못 들어감" 프레이밍은 이 문서 전 템플릿에서 제거했다 — 전부 "프로필 링크 가입/문의"로 통일.

**회장 확정 정책 (2026-07-16, 협상 불가):**
> **콜드 DM·대량 DM 자동화 전면 금지.** 허용 범위는 인바운드 문의 응대, 명시적 요청 이후의 댓글→DM 전환, 기존 지인(warm contact) 개별 연락, 후속(follow-up), 수신거부 처리뿐 — 전부 사람 승인 게이트를 거친다.

이 문서는 그 정책을 실행 규칙으로 구체화한 것이다. 여기 없는 시나리오(신규 콜드 리스트, 무단 스크레이핑 대상 발송 등)는 **금지**로 간주하고 만들지 않는다.

## 1. 원칙 (하위모델·크론 필독)

1. **자동 발송(auto_send) = 항상 false.** 이 문서의 어떤 템플릿도 크론이 스스로 발송하지 않는다. 전부 "초안 생성 → 사람 승인 → 사람이 직접 발송 또는 승인된 발송 버튼"까지만 자동화 범위.
2. **콜드 아웃리치(cold_outreach) = 항상 false.** 먼저 말 건 적 없는 상대에게 우리가 먼저 DM을 시작하지 않는다. 시작점은 항상 ①상대의 인바운드 문의 ②상대의 명시적 요청("DM 주세요"류 코멘트) ③기존 지인 관계 중 하나.
3. **비밀번호 기반 자동 로그인·세션 하이재킹 금지.** DM 발송은 공식 Instagram/Threads 클라이언트(사람이 직접 입력) 또는 공식 Messaging API 경로로만. 비공식 자동화 도구·브라우저 자동 운전으로 DM 발송 금지 — [ADR-004](../../3-operations/decisions/004-social-connect-oauth-not-passwords.md) 사고 이력(2026-07-01 계정 플래그) 재발 방지.
4. **스크레이핑 금지.** 잠재고객 리스트를 만들기 위해 팔로워·해시태그·댓글창을 긁어 타겟 리스트를 구성하는 행위 자체를 하지 않는다 — 콜드 리스트가 없어야 콜드 발송이 구조적으로 불가능해진다.
5. **레이트리밋은 내부 보수 정책이다.** 아래 §4는 우리가 스스로 정한 상한이며, 상한이 낮은 이유는 계정 신뢰도 보호(§0 ADR-004 사고 이력)다.

## 2. 시나리오별 규칙

### 2.1 인바운드 문의 (Inbound Inquiry)

- **트리거**: 상대가 먼저 DM을 보냈을 때만.
- **처리**: 초안 자동 생성 가능(아래 템플릿 D-01/D-02) → **사람이 검토 후 직접 발송**. 크론이 초안을 만들어 승인 큐에 올리는 것까지는 허용, 발송 버튼은 사람.
- **응답 시한**: 영업일 기준 당일 이내 응답 목표(내부 SLA).

### 2.2 댓글→DM 전환 (명시적 요청 후에만)

- **트리거**: 게시물 댓글에서 상대가 "DM 주세요", "우리 가게도 되나요 DM으로", "궁금해서 DM 남길게요" 등 **명시적으로 DM을 요청**했을 때만.
- **금지**: 댓글을 남겼다고 해서 요청 없이 먼저 DM을 보내는 것 — 이건 콜드 DM이다(§1-2 위반).
- **처리**: hook-bank CTA `C-07`("우리 가게도 되나 싶으면 DM. 업종만 알려주시면 됨")로 유도된 댓글만 이 경로 대상. 템플릿 D-03.

### 2.3 웜 컨택 (기존 지인)

- **트리거**: 회장 또는 운영자가 이미 아는 사람(기존 고객·지인·업계 관계자)에게 개별적으로 소개하고 싶을 때.
- **처리**: **완전 수동.** 이 경로는 초안조차 자동 생성하지 않는다 — 지인 관계의 뉘앙스는 템플릿화 대상이 아니다. 참고 톤(§3 D-04)만 제공, 발송 문구는 사람이 직접 작성.

### 2.4 후속(Follow-up)

- **트리거**: 인바운드 문의(§2.1)에 응답했으나 상대가 3영업일 이상 무응답일 때만 1회.
- **횟수 상한**: 후속은 **최대 1회**. 그 이후 무응답이면 재연락하지 않는다(콜드 압박 방지, 신뢰 자산 보호 — brand.md 톤 "낮은 흥분").
- **템플릿**: D-05.

### 2.5 수신거부/차단 요청 (Unsubscribe / Stop)

- **트리거**: 상대가 "그만", "연락하지 마세요", "관심 없어요" 류 의사를 표시.
- **처리**: **즉시 그 대화 스레드 발송 중단.** 예외 없음 — 재요청·설득 시도 금지. 내부 기록(§5 로그)에 `opt_out: true` 표시하고 이후 어떤 초안 생성 대상에서도 제외.
- **템플릿**: D-06(확인 응답만, 설득 문구 없음).

## 3. 템플릿 (전부 초안 — 발송 전 사람 검토·개인화 의무)

톤 규칙은 [brand.md](../../1-team-brand/brand.md) §4·[creative-briefs/_base.md](./creative-briefs/_base.md) §2 그대로: 담백한 리포트체(단 DM은 1:1 응대라 "오스무입니다" 자기소개 허용), 굽신 콜센터 톤 금지, 이모지 0~1개, "고객님~" 금지.

### D-01 — 인바운드 문의 첫 응답 (서비스 문의 일반)

```
안녕하세요, 오스무입니다. 사장님 가게 SNS 관련 문의 남겨주셨네요.

지금은 공개 베타로 운영 중입니다. 업종이랑 지금 SNS 운영 상황(직접 하시는지/안 하시는지)
알려주시면 맞는 안내 드릴게요. 가입/문의는 프로필 링크로도 가능합니다.
```
사용 조건: 인바운드 DM에만. "공개 베타 운영 중"은 발송 시점 실제 서비스 상태(대기열·정원 제한 여부)와 일치해야 함 — 만약 실제로 대기·정원 제한이 생기면 그 사실 그대로만 쓰고, 없는 상태에서 대기·마감을 암시하는 표현은 금지(§1 윤리 — marketing.md §4 "존재하지 않는 희소성 조작 금지").

### D-02 — 인바운드 문의 첫 응답 (가격/일정 문의)

```
문의 감사합니다. 가격·일정은 아직 확정 전이라 정확한 안내를 못 드리는 점 양해 부탁드립니다.
가입해주시면 확정되는 대로 안내드려요. 가입/문의는 프로필 링크로 가능합니다.
```
사용 조건: 가격 확정 전 상태에서만. 가격 확정 후엔 이 템플릿 폐기하고 실제 가격 안내로 교체(지어낸 가격 발송 금지). **"순서대로" 표현은 제거함(2026-07-16 재작업)** — 실제로 접수 순번을 관리하는 큐 시스템이 없는데 순서를 암시하면 존재하지 않는 시스템을 암시하는 것과 같다(marketing.md §4). "가입 후 확정되는 대로 안내"로 정직화.

### D-03 — 댓글→DM 전환 (업종 데모 요청)

```
댓글 보고 왔습니다. 업종이랑 지금 어떤 걸 SNS에 제일 자주 올리시는지(신메뉴/이벤트/후기 등) 알려주시면,
어떤 식으로 도와드릴 수 있는지 예시 보여드릴게요.
```
사용 조건: 상대가 댓글에서 DM을 명시적으로 요청했을 때만(§2.2).

### D-04 — 웜 컨택 참고 톤 (발송 문구는 사람이 직접 작성 — 이 블록은 템플릿이 아니라 톤 가이드)

실제 참고 copy(JSON copy와 정확히 동일, 한 줄 — 그대로 복붙 발송 금지, §2.3 규칙대로 발송 문구는 사람이 직접 작성):
```
아는 사이의 자연스러운 어투로: "저 요즘 이런 거 하고 있는데 OO님 가게에도 맞을 것 같아서 — 관심 있으면 얘기해볼까요?" 급하게 팔려는 티 내지 말 것. 거절해도 자연스럽게 넘어갈 것.
```

### D-05 — 후속 (3영업일 무응답, 최대 1회)

```
지난번 문의 관련 후속입니다 — 바쁘시면 답 안 주셔도 괜찮습니다.
필요하실 때 프로필 링크로 언제든 가입/문의 가능합니다.
```
사용 조건: 최초 응답 후 3영업일 경과 + 이 시나리오에서 이미 1회 발송한 이력이 없을 때만.

### D-06 — 수신거부 확인 (설득 문구 절대 금지)

```
알겠습니다. 앞으로 연락드리지 않겠습니다.
```
사용 조건: 상대가 그만/차단 의사를 밝힌 즉시. 이 응답 이후 그 스레드에 추가 발송 금지.

## 4. 레이트리밋 (내부 정책 — v1 안전핀)

| 항목 | 값 | 비고 |
|---|---|---|
| 1일 최대 발송 | 5건 | 계정 전체 기준 |
| 시간당 최대 발송 | 1건 | 계정 전체 기준 |
| 후속(follow-up) 상한 | 최대 1회 | §2.4 |

이 상한은 외부 플랫폼의 발송 한도를 옮겨 적은 게 아니라, v1이 콜드 발송을 아예 하지 않는 구조(§1-2, §1-4)에서 실수로 대량 발송 로직이 붙는 것을 막기 위해 우리가 스스로 정한 안전핀이다. 플랫폼 자체의 발송 속도·메시징 정책은 이번 v1(수동 승인·소량 인바운드 응대) 범위에서 참조할 필요가 없다 — 자동 발송 기능을 실제로 붙이는 시점에 개발 문서로 별도 확인한다(⛔ 회수 대상, 지금 범위 아님).

**v1 정책 확정(회장 지시)**: v1은 **수동 승인·수동 발송**이 원칙이다. 크론이 초안을 만들 수는 있어도(§5), 발송 버튼은 예외 없이 사람이 직접 누른다. 위 내부 상한(1일 5건/시간당 1건)은 이 수동 운영 체제 안에서의 안전핀이지, 자동 발송을 허용하는 근거가 아니다.

## 5. 승인·기록 게이트

1. 모든 DM 발송은 초안 생성(자동 가능) → **사람 승인** → 사람이 직접 발송(또는 승인된 발송 액션 실행)의 3단계를 거친다. `auto_send=false`는 예외 없음.
2. 발송 로그는 growth-log.md 규칙을 따라 최소한의 사실만 기록(상대 식별정보는 최소화 — 업종·시나리오 유형·발송일만, 대화 전문 wiki 기록 금지).
3. opt-out(§2.5) 표시된 상대는 이후 어떤 초안 생성 대상 리스트에도 포함하지 않는다.

## 6. 레드팀 셀프체크

- **공격**: "인바운드/웜/댓글요청이라는 구분이 실제로는 콜드 DM을 우회하는 핑계가 될 수 있지 않나?"
- **방어**: §2.2에 "명시적 요청"을 댓글 문구 예시로 구체화했고(모호하면 §2.3 웜 경로로도 못 감 — 아예 발송 안 함), §1-4로 콜드 리스트 자체를 만들지 못하게 구조적으로 막았다(스크레이핑 금지) — "타겟팅할 명단"이 존재하지 않으면 우회할 도구 자체가 없다.
