운영 중에 무엇이 고장났는지 알 수 있게 만든다.

지금은 고장이 나도 사용자가 말해 줘야 안다.

기반 산출물에 dashboard/src/lib/observability/ 와 dashboard/scripts/health-alert.sh 를 추가로 읽어라.

할 일:
1. 발행 실패, 토큰 만료, 생성 실패, 외부 서비스 오류를 한곳에서 볼 수 있게 한다.
2. 사람이 개입해야 하는 것과 저절로 낫는 것을 가른다. 저절로 낫는 것으로 알림을 울리지 마라.
3. 설정이 안 된 상태를 고장으로 세지 마라. 오늘 /api/auth/google 이 그 사례였다.
4. 어느 작업 공간에서 났는지가 붙어야 한다.

실제로 고장을 만들어(토큰을 망가뜨리는 등) 알림이 뜨는 것을 관찰해 증거로 붙여라.

공통 규율(어기면 반려된다):
- 기반 산출물을 반드시 Read 하고 시작한다. 임의 재해석 금지.
  확정 프로토타입 docs/prototype/openclaw-auto-4room-v63.html
  회장 확정 요구 대장 docs/requests/회장-확정-요구사항-대장.md (해당 화면·기능을 grep 해서 관련 항목 전부 읽어라)
  사업 좌표 wiki/product/사업좌표-OSMU와-ZERO-ONE.md (여섯 사업체가 같이 쓴다. 한 벤처 전용으로 굳히지 마라)
  갭 재확인 docs/audit/osmu-gap-recheck-2026-08-28.md (이미 되는 것을 다시 만들지 마라)
- 완료 = 증거. 도는 앱(localhost:3456)에 실제 요청을 보내 상태코드와 응답을 관찰하고 붙여라. mock 통과는 증거가 아니다.
- npm run test 와 npx tsc --noEmit 통과가 필수다.
- 사족 문구 금지. 긴 대시 금지. 이모지 금지. 영문 단추 라벨 금지.
- 새 테이블이 필요하면 만들되, 기존 dashboard/db/schema.sql 의 테넌트 격리(RLS)와 명명 규칙을 그대로 따르고 마이그레이션을 남겨라.
- 자격증명은 dashboard/.env.local 에 있다. 작업 공간은 cd1d0a40-540d-4524-9b49-bf2445d82182.
